## 3. 关键发现：删边仍 37/40 ⇒ 评测对关系结构不敏感

复评在**内存中**做的消融（原图/原题均未改；本项目**未复核**，因其结论方向明确且与铁律 #54 同源）：

| 实验                                    |        判对 | 失败题                                                            |
| ------------------------------------- | --------: | -------------------------------------------------------------- |
| 正常规则基线                                |     40/40 | —                                                              |
| **删除全部边**（保留节点与参考表）                   | **37/40** | MS-03 / MS-04 / MS-06                                          |
| 再删除全部节点（保留程序与参考表）                     |     25/40 | 15 题（DV-01/02/03/05/06/07/08、MS-03/04/06、NM-01/02/08、US-04/05） |
| **把全部问题文本替换为无意义句子**（保留 method/inputs） | **40/40** | —                                                              |

⇒ 三条推论（本项目须接受）：

1. 现有 40 题**主要覆盖规则工具**：`eval_runner.solve` 直接读 `task["method"]` 与已结构化 `inputs`，  
   **没有「问题文本 → 识别任务 → 抽取条件 → 选方法」环节**，故题面文本不参与求解。
2. 现有 40 题**应保留为回归集**，但**不能再当作端到端能力证据**（与铁律 #54「自建集自洽 ≠ 泛化」一致）。
3. **必须**新增：**独立盲测**（复评建议 80 题：20 dev / 60 盲测，隐藏 method/expected/拒答标签）
   - **图谱消融对照**（同源同信息预算下，比 `规则+表格/检索` vs `规则+图谱`）。

复评三条主张与本项目既有铁律**同源**，可直接纳入：

- 「故障注入要打到**最外层用户命令**，不能只证明底层函数会报错」→ 铁律 **#14**（自检必须非真空）+ **#43**（独立审计器必须允许报错）。
- 「**构建与验收分离**，验收不得重建清单把错误数据登记成正确」→ 铁律 **#22**（改正派生须留痕）+ 新增：**验证模式只读**。
- 「**重写哈希不能恢复 valid**」→ 铁律 **#61** 的孪生：**哈希是「当时字节」的证明，不是「正确性」的证明**。

**建议新增铁律（编号续 #62 起）**：

- **#62 发布链必须 fail-closed 且逐项传退出码**：多步发布命令任一步非零即整体非零；`WARN` **不得替代** `FAIL`（缺规范图 / 坏哈希 / 子进程失败 / 关键 SKIP 必须阻断）。
- **#63 判分器的「拒绝」分支必须是显式的**：依赖 `NaN`/`Inf` 比较来判错会被 NaN 语义穿透；**非有限值必须在入口显式拒绝**。
- **#64 「政策」必须由程序执行**：写在文档里的许可/口径边界，若无程序判据，则等于没有（A03 现场）。
- **#65 评测必须做「消融对照」**：全对只说明在**该题集**上一致；**删边仍高分**说明该题集测不到结构增量。
- **#66 ★规模本身是设计约束**：当全量对象大到**默认交互不可用**时，**默认入口不得是「加载全量」**；
  必须提供「**查询取部分 → 再看**」的路径，且**部分的数量必须是预算受控**的（`max_nodes / max_edges / deadline`）。
  ★ 逆命题同样成立：**前端能渲染一部分，不等于后端能给出一部分** —— 后端必须先有**有限的、可解释的**子图抽取。
- **#67 ★查询的「空」与「失败」必须分列**（#55 的查询版）：`no_result`（真的没有）/ `truncated`（有但被预算截断）/
  `timeout`（超时）/ `error`（异常）/ `ok`（有且完整）**五态必须显式**；把异常吞成「空列表」
  等于让「查不到」与「查崩了」不可区分（A06 现场：`queries.py` 异常统一转空列表）。
  ★ 且**截断必须报明「被什么截断」与「截前规模」**，否则用户会把不完整结果当作完整结果。
- **#68 ★「可替代的独立性」必须分级披露**：当外部独立资源（学科专家）不可得时，**不得假装有**，
  也**不得悄悄降标准**；应把独立性**分级**（L0 无 / L1 自出题+预注册+外部权威锚点+AI 红队 / L2 跨机构 / L3 学科专家），
  **在结论上强制标注等级**，并把「由外部权威值唯一确定答案」的题目**单列为更高级别的证据**（见 §6.2）。

   附索引 `07_交付物/外部评审/README.md`。

### 6.2 学科审题资源：**本项目无此资源** ⇒ 处理方案（**分级披露 + 可替代锚点**）

**先承认问题**：复评（及本项目铁律 #54/#57）要求「**独立学科人员出题/审核**」。本项目**确无**该资源。
**两种错误做法必须避免**：① 假装有（伪造独立性）；② 悄悄降低标准却不声明。

**关键拆解**：「审题独立」其实是**两个可分离的东西**：

- **(a) 题目内容独立** —— 谁出的题、题干是否有偏 ⇒ 需要**人**（本项目缺）；
- **(b) 判定独立** —— 答案对不对由谁裁定 ⇒ **可以不需要人**：若答案由**外部权威数据唯一确定**
  （NIST WebBook / IUPAC / CODATA / SI 基表 / Crossref 元数据），则**判定独立于本项目语料**。

> 本项目**已有先例**：Phase 40（R09）就是用**独立 SI/ISO 80000 基表**去对照「由被校验语料反解出的真值表」
> —— 这正是 (b) 的落地。本方案把它**推广到整个评测集**。

#### 6.2.1 处置四件套（全部可执行、可复现）

| # | 措施 | 说明 | 替代了什么 |
|---|---|---|---|
| 1 | **题集分层标注** `answer_anchor` | 每题标 `answer_anchor ∈ {external_authority, internal_recompute, expert_judgment}` + `anchor_ref`（外部表 id / 版本 / 内容哈希） | 把「独立性」从**整集布尔值**变成**逐题可核** |
| 2 | **预注册 + 冻结** | 题集在**看到系统输出之前**冻结并公开哈希（`tasks.json` sha256 + 提交时间）；事后改题/改规则必须**留痕并降级为「回归」** | 保证**过程独立**（无法 post-hoc 调题）—— 替代不了人，但可证「未事后调参」 |
| 3 | **对抗性红队（角色隔离）** | 出题者 / 解题者 / 审核者**三方角色分离且留痕**；审核者**必须尝试证伪**（构造反例使题失败）且**必须允许报错**（铁律 #43）。可用**其他模型**做红队，但**必须标注「AI 红队，非学科专家」** | 部分替代「外部审核」的**证伪功能** |
| 4 | **强制披露** | 在**北极星**与**评测报告**上强制标注 `review_independence = L1`、`无独立学科审题`；**除由 `external_authority` 类题支撑的结论外，任何跨域能力结论都带此限定** | 把「无独立审题」写成**已知置信上限**，而不是隐藏 |

#### 6.2.2 独立性等级（写入报告与指南）

| 等级 | 含义 | 证据强度 |
|---|---|---|
| **L0** | 无审题（自出题、自判定、无留痕） | ❌ 不得对外 |
| **L1** | 自出题 + **预注册冻结** + **外部权威锚点题** + **AI 红队**（= 本项目**当前可达**） | ⚠ 内部一致 + 部分外部锚定 |
| **L2** | L1 + **跨机构/跨团队**独立出题或审核 | ✅ 可对外（受限） |
| **L3** | L1 + **学科专家**逐题审核 | ✅ 可对外 |

★ **升级路径**：一旦获得外部专家（**哪怕 1 位**），把专家审过的题目升级为 L2/L3 并**重算对应指标**；
在此之前，凡引用**未锚定外部权威**的结论，必须带上 `review_independence = L1`。

#### 6.2.3 本轮即可落地的增量（并入 P1-C / B02-）

1. `12_评测/build_tasks.py` 为每道题增设 `answer_anchor` / `anchor_ref` 字段（**不删已有字段，保持回归兼容**）。
2. **优先扩充 P-A 类（`external_authority`）题目**：可由 `11_真实数据/si_base_table.py`（独立 SI 基表，63 量）、
   `11_真实数据/webbook_*.json`（NIST WebBook 热化学）、`element_reference.py`（IUPAC 元素）唯一确定答案的题
   ⇒ **这类题判对即「独立于本项目」**，是最强的可得证据。
3. **P-B 类（`internal_recompute`）**：保留现有 40 题作**回归集**，**不得**再作端到端能力证据（铁律 #54）。
4. **P-C 类（`expert_judgment`）**：**不得进入对外结论**，仅在报告「待外部审题」清单中列出。
5. 评测报告头部固定打印：`review_independence`、各类题计数、冻结哈希、红队结论。

> ★ 这套方案与铁律 **#57**（独立基表外对照）、**#54**（评测必须能失败）、**#43**（审计器必须允许报错）
> 同源，且新增铁律 **#68**（可替代的独立性必须分级披露）。**不假装有外部审题。**
