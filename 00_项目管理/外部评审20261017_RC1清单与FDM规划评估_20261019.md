### 3.2 架构建议：成立，且比规划者以为的更近

它建议的分层是「图谱检索 → 确定性过滤 → 小模型排序 → 校准 → SymPy 验证 → 证据化结果」。
其中**前两层和后两层 STTP 已经有了**，不是待建：

| 规划中的层 | STTP 现有能力 | 差距 |
|---|---|---|
| 混合候选检索（关键词+向量+图谱路径） | 关键词检索 + `subgraph` 路径 + `seeds` 候选 | **缺向量** |
| 确定性过滤（量纲、单位、类型、硬约束） | `dimension` 60 一致 / 1 约定 / **0 冲突**；`dimension_table.py` + `element_reference.py` | 基本无差 |
| 小模型排序 / 适用性 / 拒答 | — | **全缺**（这是真要训练的） |
| 概率校准 | — | 全缺（依赖模型存在） |
| SymPy 等价验证 | `verification_model.py` 已在 | 无差 |
| 证据化结果 + 快照 ID | `source_registry` + `snapshot sha256` + A04 五态 | **无差，且更强** |

**推论：** 这个系统里「确定性的一半」已经是 STTP 的存量资产。真正要新建的只有**排序/适用性/拒答模型 + 校准**。
规划把整条链当绿地来估工期，**高估了工作量**。

### 3.3 方法论问题：顺序反了

规划 §7 阶段 1 自己写了「用现有检索、规则、外部模型建立**零训练基线**」——这是对的。
但接着阶段 2 就进入「生成 20,000—50,000 条训练候选」，而**全文没有一条退出条件写「零训练基线达标就不训练」**。

它的 §10 决策建议是「批准一个有退出条件的 12 周 PoC」，但四条退出条件全是
「Top-5 / Top-1 / 高置信错误率 / 拒答指标达标后进入 Alpha」——**只有向上通道，没有「不值得做」的判据**。
在一个 96.7% 数据不可复算、40 题同源的底座上，这不是小问题：**训练会把数据缺陷固化成权重**。

**建议改成（成本 2—3 周，先于任何预算审批）：**

1. 把 40 题扩成 **300—500 题独立集**（含图外拒答、量纲陷阱、同名公式困难负例）；
2. 用**现有**图谱+量纲+SymPy 跑零训练基线，出 Top-1 / Top-5 / 拒答召回；
3. 用基线数字决定是否进入 12 周 PoC——这正好是它自己阶段 1 的内容，但**必须前置为门槛而非前置为起点**。

这样做的额外好处：300—500 题独立集本身就是 RC1「科学有效性证据」维度（评审自评 5.8 分）的缺口。

### 3.4 一个可以**现在就用、不用训练**的东西

规划 §2 那个 JSON 契约，值得立刻吸收：

```json
{
  "formula_choice": {"value": "...", "probability": 0.91},
  "applicability": {"value": "conditionally_applicable", "confidence": 0.87},
  "dimension_valid": {"value": true, "verified_by": "symbolic_engine"},
  "missing_conditions": ["temperature", "pressure", "standard_state"],
  "action": "ask_user_for_conditions"
}
```

其中 `dimension_valid` + `verified_by` 是**现成的**（量纲引擎就有）；`missing_conditions` + `action`
不需要任何模型——它正是 **D69（单节点/0 边无解释）缺的那一层**：

> 现在的界面说「已隐藏 12 条」；改成「当前可信档没有可显示关系，缺条件：X / 建议动作：切到全档」，
> 就是同一个契约的零训练版本。

**所以 FDM 规划里最先落地的一条，不是模型，是错误反馈的结构化契约。**

### 3.5 与项目定位的关系

`PROJECT_DEVELOPMENT_GUIDE.md` §0.2 把 STTP 定为**研究演示系统**，明列「不新增 GNN/LLM 产品功能」。
FDM 是**新产品线**，不是 Phase 序列里的一个功能。规划 §7 阶段 0 也写了「先完成 RC1」，**顺序上不冲突**。

但**人**会冲突：规划建议 4—6 人专职，而当前 RC1 收口 + D65–D71 还在同一个人手上。
建议：FDM 只批准「§3.3 的 2—3 周前置实验」，**不批准 12 周 PoC 立项**，等 RC1 全绿 + 独立题集出来再议。

  但其**结构判断**（成本大头是专家数据与评测，不是 GPU）与我们一致，可作为决策参考。

### 4.2 可复用的：三项失败的技术诊断

评审对 `V16c / V18d / V18h` 的失败给了解释，其中 **`V18h` 的解释在本仓库也成立，而且是隐患**：

> 「断言使用包含 A04 状态的 `edge_is_stale()`，却与纯字节层 `changed + unverifiable_no_source` 比较」

**本仓库复核（`phase43_subgraph_selfcheck.py:890-925`）：**

```python
ind_stale = sum(1 for e in b_all if Q.edge_is_stale(e, reg))     # 含 A04 层
rep.add(ind_stale == gcounts.get("changed", 0) + gcounts.get("unverifiable_no_source", 0), ...)   # 纯字节层
```

同一函数上方，Phase 45 已经把口径**正确拆成两条**：

```python
rep.add(ind_fid_stale == base_stale, "V18f 字节层 stale == changed + no_source")          # 精确等式
rep.add(base_stale <= ind_stale <= base_stale + ind_a04_stale, "V18f2 全图 stale = 两层并集")  # 区间
```

而 **`V18h` 没有跟着改**，仍用 `ind_stale` 去等纯字节层。

**后果：** 本仓库现在 `V18h` 是 PASS，但读数说明了一切——

```
V18f2：stale=121 ∈ [121, 121]（A04 层贡献 0）
V18h ：not_in_repo=47055（占 96.6%）｜stale=121
```

`ind_a04_stale == 0` ⇒ `ind_stale == base_stale` ⇒ **V18h 当前恒真**。
一旦 A04 判出**任何** stale/rejected 边，`ind_stale > base_stale`，`V18h` 立刻假红——
这正是 Phase 45 注释里写的「旧断言在 A04 判出 stale 时会假红」，**V18f2 修了，V18h 漏了**。

同时它想守的性质（`not_in_repo` 不计入 stale）**已由 V18f 守住**（`not_in_repo` 是第五类，不进 `changed + no_source`）。
所以 `V18h` 现在既不守任何东西，又是一个定时炸弹。

**建议（新登记 D72，成本 0.5 天）：**

1. `V18h` 改为**构造性**判据：取一条 `unverifiable_not_in_repo` 边，验证
   `edge_fidelity(e) == "unverifiable_not_in_repo"` 且 `edge_is_stale(e) is False` —— 判据非真空；
2. 用 `V18f2` 的精确等式替代残留的宽松比较：`ind_stale == base_stale + ind_a04_stale`；
3. 配 `red_probe` 一条：人为让 `edge_is_stale()` 对 `not_in_repo` 返回 True ⇒ 新 `V18h` 必红。

> 这是本次评估里**唯一一个评审自己都没意识到严重性**的发现：他们在副本上把它当「基线问题」，
> 实际上在本仓库它是「还没爆的口径缺陷」。

## 五、结论与建议的下一步

### 5.1 需要你裁定的（1 项，管 3 条工单）

**STTP 要不要一个浏览器开发依赖组？**

| 选项 | 后果 |
|---|---|
| **A. 维持 D14（不声明 Playwright）** | RC1-08 / 09 / 13 三项**全部不做**，在「已知边界」里如实登记：「浏览器回归靠人工，非门禁」。与现有定位一致，成本 0 |
| **B. 加 `[browser-test]` 可选组 + CI** | RC1-08 落地；09 可做；13 才有基础。但引入 Playwright 版本漂移、Chromium 下载体积、CI 时长，且与「零浏览器测试依赖」的对外承诺要重新表述 |
| **C. 折中：只加可选组，不进 CI** | 开发者可本地跑 E2E，门禁不变。RC1-08 达成，09/13 降级为「可选手工」。成本低 |

我倾向 **C**：它让「第三方能否复现浏览器验收」有一个明确答案（能，但需装一个 extra），
又不把 Playwright 变成发布门禁。**但这与你之前「维持不声明」的裁定不同，需你确认。**
