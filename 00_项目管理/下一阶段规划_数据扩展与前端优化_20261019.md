## 〇、先给三个判断

盘点之后，有两件事和你的设想一致，有一件事需要修正。

**① 方向对：数据 + 前端确实是当前最该做的两条线。**
评审的 RC1 清单在本仓库已过 6 成，剩下的不是「版本收敛」而是「数据可用性 + 用户能不能理解」。
小模型暂缓是合理的——FDM 规划自己的阶段 0 也写「先形成可复现快照」。

**② 但「增加数据」的第一动作不是「抓更多」，是「补结构」。**（详见 §2）

当前 5,090 个公式里：

| 字段 | 覆盖率 | 意味着什么 |
|---|---:|---|
| `latex` | **99.98%** | 图能**显示**公式 |
| `description` / `usage` / `meta_source` | **1.59%**（81 条） | 图不能**解释**公式 |
| `applicability`（适用条件） | **0.00%** | 图不能**判断**公式 |
| `assumptions`（假设前提） | **0.00%** | 同上 |
| `symbols` | **0.16%**（8 条） | 符号在边上（`has_symbol` 24,341 条），不在节点上 |

**结论：这个库现在「能查」，但「不能用」。**
而你要做的两件事——训练模型、开数据接口——恰恰都要求「能用」：
模型要学的是「什么问题 → 哪个公式 + 什么条件下成立」，接口调用方要的第一条也是适用条件。
**在 applicability=0 的库上训练，等于让模型学「哪个公式长得像」，学不到「什么时候该用」。**

所以数据阶段的顺序应该是：**先补结构 → 再补规模 → 最后才谈训练**。

**③ 前端不是「美化」，是「补决策路径」。**（详见 §4）
评审报的三件事（单节点无解释 / warming 无进度 / 切档无效）本质是同一件：
**系统知道原因，但没告诉用户。** 原型要先把这套「原因 + 动作」的信息结构立起来，视觉是第二步。

## 二、数据扩展：三层，按「能不能用」排序

### 2.1 第一层：让公式「可判断」（最高优先，也是模型/接口的前提）

| 字段 | 现状 | 目标 | 方法 |
|---|---:|---:|---|
| `applicability`（适用条件） | 0 / 5,090 | ≥ 1,500 | 见下 |
| `assumptions`（假设前提） | 0 / 5,090 | ≥ 1,500 | 同上 |
| `symbols`（变量表） | 8 | 从边上回填 | **零抓取**，`has_symbol` 已有 24,341 条边 → 反向聚合到节点 |
| `description` | 81 | ≥ 2,000 | 规则 + 抽取 + 人工 |
| `domain` 二级学科 | 90 | 5,090 | **纯规则**（关键词 + 公式形态） |

**`symbols` 回填是纯赚的**：24,341 条 `has_symbol` 边已经在库里，只是没聚合回节点。
这一步不需要任何抓取，预计能把覆盖率从 0.16% 提到 90%+。**建议第一个做，用来验证整条「补字段 → 存图 → 前端可读」的链路。**

**`applicability` 的三条来源路径（需先探测可行性，不许先承诺数字）：**

1. **PhysicsBabel 原文**：本地已有 `physicsbabel_raw.json`（14 MB）。先写探针统计其中有多少条记录含「assumption / condition / valid when / applies to」类字段——**这是 Go/No-Go 判据**，探测前不许写「能补 5,000 条」。
2. **规则抽取**：量纲表 + 元素表 + 公式形态 → 能推出一部分硬条件（如「仅适用于理想气体」「要求 T 为常量」需要语义，规则只能覆盖符号层面）。**预期覆盖低，但准确率 100%，可作高置信底座。**
3. **LLM 离线抽取**：用本地已有 `04_验证闭环/llm_hypothesis.py` 的通道，逐条产出「适用条件候选 + 置信度 + 出处」，**必须人工抽检 + 标注 `verification_level=model_inferred`**，不得与 `source_asserted` 混列。
   ⚠️ 这一条**不训练模型**，只做抽取，符合「训练暂缓」。

> **铁律提醒（#14/#43/#65）：** 任何「补了多少条」的说法必须有构造性反例。
> 补字段的验收不是「条数达标」，是「随机抽 30 条，专家认可 ≥ 27 条」。

#### 2.1.1 探针实测（2026-10-20，Phase 63）—— 目标 1,500 **不可达**

`06_PoC/_recon_applicability.py` 把四条路径全部量清（只读，不写任何字段）：

| 路径 | 实测 | 判否理由 |
|---|---:|---|
| **P1** PhysicsBabel 原文 | **0** | parquet 15 列 + raw 12 字段，**零命中**（这就是规划指定的 Go/No-Go 判据） |
| **P2** 词典法（策展文本） | **30** | 54 条命中逐条核对：真 43 / 假 11 = **79.6%，不达 90%** |
| **P2b** 量纲推硬条件 | **0** | 量纲齐次是**恒真性质**，冒充前提违反铁律 #14 |
| **P3** 论文摘要 | **0** | 抓取时未保留 abstract（181 节点 + 188 条原始记录均无） |
| **P4** LLM | 需**新建** | 规划说「复用 `llm_hypothesis.py`」，实测它是**假设生成器**（图→候选假设），不是抽取器（文本→前提） |

**覆盖率 30 / 5,090 = 0.59%，缺口 1,470 条。**

三条被探针推翻的想当然：

1. 条件**不是** `Given/assuming` 引导句，而是**名词短语/状语**（恒温下 / 理想气体 /
   凸多面体 / 与模数互素）。第一版词表按引导句写，只命中 4 条；换形态后 54 条。
2. **命中 ≠ 适用条件**。误命中四种模式：① 量名·常数名（静止质量 / 真空光速）
   ② 被定义对象（介质中的光速 / 与 n 互素者）③ `usage` 写的是**用途**（判定互素）
   ④ 类比提及（与薄透镜方程同形）。
3. **5,000 条 PB 合成式没有指称对象** —— `m = k₀·ℓ⁻¹·t²·F` 谁也不是，
   不描述任何真实过程，**无从谈适用条件**。这才是缺口的真因，不是「抓取还没做」。

**处置（2026-10-20 定）**：接受 **30 条高置信底座**，**不追 1,500**。
`applicability_status` 三态落盘：`extracted` 30 / `no_referent` 5,001 / `not_extracted` 59。
把「没抽到」与「不可能有」分开记 —— 后者不是欠债，是事实。
**判据逼你造假时，先检查判据的前提**：「≥1,500」默认了「每个公式都有适用条件」，
而 98% 的公式是机器拼的量纲式，根本没有。

### 2.3 第三层：规模与接口化（为「数据接口」准备）

| 项 | 现在 | 目标 | 说明 |
|---|---|---|---|
| 原始数据入库 | 12 个 `*_raw.json` 被 gitignore（96.6% 边不可复算） | **外部分包** | Release asset / Zenodo + sha256 + 恢复命令。**这是「开放数据接口」的前置** |

```
dataset/
  manifest.json          # schema_version / snapshot_id / 文件清单 / sha256 / 许可

```
一个目录 + 一个 manifest，别人 `wget` 下来就能用——**比 REST API 更符合当前阶段**，
也不需要服务器、账号、限流。等有人真的接入了，再谈 API。

### 2.4 第四层：证据分级（1—5 分）—— 不新增评分表，只给已有字段加折扣

> 完整规则见 **`证据分级规范与抓取优先级_20261019.md`**，此处只写结论与准入条件。

**需求来源**：「公式使用案例、科研论文的使用数据，要不要 1—5 分——网上抓来无法证明的打 1 分、
可确认的打 5 分，依次标记作为下一步抓取的依据。」

**结论：要，但必须是派生的。** 图里已有两套正交字段：`verification_level`（断言怎么验的）
与 `fidelity`（证据能否从仓库复算）。1—5 分只能是二者的**合成折扣**（取最小值、多源独立 +1），
不允许另建一份人工打分表——那会造出第二套真相（铁律 #87）。

实测分布（48,712 条边）：

| 5 分 | 4 分 | 3 分 | 2 分 | 1 分 |
|---:|---:|---:|---:|---:|
| 702（1.4%） | 351（0.7%） | 482（1.0%） | **47,032（96.6%）** | 145（0.3%） |

**必须一起说的三句话**（否则评分会被误读）：

1. 96.6% 卡在 2 分**不是「不可信」**，是「来源文件未随仓库分发、不可复算」——
   其中 31,138 条是**规则机检通过**的。
2. 最反直觉的一处：`cross_source`（最强证据）有 **79% 掉到 2 分**，因为交叉验证需要两个来源文件同时在库。
3. 1 分只有 145 条（0.28%）⇒ 图**不是** LLM 生成的，模型推断占比极低，这可以对外讲。

**双口径（因「暂不对外」而定）**：`grade_internal`（本机全量）与 `grade_public`（仅仓库内证据）
**永不合并**；对外材料不得单独引用「1.4% 达到 5 分」而不附封顶说明。

**论文侧的真问题不是分数，是空白**：181 篇里 90.1% 有 DOI，但 **63.5% 是 closed**（只能到 3 分）；
更严重的是 `discusses` 178 条**全部指向数学概念**，**5,050 个物理公式被论文讨论的数量 = 0**。
论文线要从物理主题**重建**，不是给现有论文补分。

**使用案例是 0 条边**（24 种边里没有 `used_in`/`applied_to`），只有 81 条人工 `usage` 文本可作基准样例。
这条线必须**出生即打分**（抓取时带 `grade` + `locator`），事后补分的代价就是现在这 96.6%。
