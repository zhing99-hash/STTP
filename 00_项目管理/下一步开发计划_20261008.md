## 三·补·b · A5 轮新增发现（2026-10-08）

A5（元素命名空间去重）施工中又跑出三个真问题，已在同轮修复：

1. **A2 的 GNN 在不同元素之间猜出了 `same_as`**（最严重）
   `gate_check()` 的 Element×Element 分支只判同周期/同族，两者都不满足时返回 `None`，Part A 便**直接采信 GNN 的类型预测**。
   于是产出 `Cl→O`、`N→H`、`H→C` 等 **13 条跨元素符号的 `same_as`**（`same_as` 语义是「同一实体」，跨符号绝不成立）。
   触发原因：`EL:c/h/o`、`BC:el:nitrogen` 挂着 375~670 条 `composed_of` 入边，呈"超级枢纽"形态，嵌入趋同。
   → 清存量 13 条 + `gnn_infer.py` 门控加硬约束（跨符号且既不同周期也不同族 → `REJECTED`）。

2. **`graph_export.py` 在 import 时替换 `sys.stdout`，会让长驻服务全局失联**
   原写法 `sys.stdout = io.TextIOWrapper(sys.stdout.buffer, ...)` 有 **GC 关闭底层 fd** 陷阱：旧 wrapper 被回收时连带关掉同一个 buffer，
   此后进程内所有 `print` 抛 `ValueError: I/O operation on closed file`。
   `viz_server.py` 的 `/api/stats` 一旦触发该 import，服务就**对所有请求返回空响应、连访问日志都打不出**。
   → 改用 `stream.reconfigure(...)` 原地改编码。

3. **`/api/stats` 的类型分布与快照对不上**
   统计直接用 `labels[0]`，但 1658 个节点的 labels 是 `["Entity", "Reaction"]`，首标签恒为 `Entity`，
   导致 Reaction/Molecule/Symbol 全被吞成 `Entity`。→ 改用权威 `graph_export.pick_type()`。

## 三·补·e · Phase 8 轮新增发现（2026-10-09）

开 Phase 8（真实 ETL）时先做数据源可行性验证，两个技术假设被推翻：

1. **出口白名单是「按域 **且按路径**」放行的 —— 域名可达 ≠ 端点可达**（重要环境认知）
   arXiv 分层探测（TLS 握手 → 原始 HTTP）：`export.arxiv.org/` 根路径 ✅200，
   但 **`export.arxiv.org/api/query`（官方 API）TLS 可握手、响应 0 字节超时**；

## 三·补·k · Phase 30 跨域桥「去伪存真」（2026-10-10 · **第 20 轮 · 已完成**）

> 完整报告：`07_交付物/Phase30_去伪存真报告_20261010.md`

### 起点：侦察得出的三条「负结果」（直接改变了本轮方案）

原计划承接上轮建议「攻数学桥」，按铁律**先做低成本可行性侦察**，结果三条均为负：

1. **「数学↔物理 29 条」里 28 条是 GNN 噪声**：13 条 `defines | <任意数学公式> --> 气体常数`
   （Euler 恒等式、圆面积、链式法则… **15 个不同源都声称"定义"气体常数**）；
   14 条 `has_symbol`（数学对象里的字母与物理符号**同名碰撞**）。唯一的 `rule_checked` 那条还是 `volume→volume`（同名同概念）。**真桥 = 0**。
2. **数学桥天花板极低**：全图 5090 个 Formula 节点中，含数学算子的仅 `exp` 4 / `log` 9 / `sin·cos` 3 / `π` 9 / `deriv` 11 / `∑` 4 / `∫` 2（合计 ≈ **40 个公式**）→ 无论 DLMF / OEIS / AST 哪条路线，产出上限 ≈ 40–60 条。
3. **但暴露出更值钱的东西**：`defines`/`has_symbol`/`has_unit` 这类语义边**可被确定性反驳**（目标符号根本不在源表达式里）
   → 属「**正确性**」问题，比「加桥」更贴北极星。

→ 经与用户确认，本轮主题改为 **「跨域桥去伪存真（De-noise + Rebuild）」**，而非「数学桥专项」。

### 去伪：三条确定性反驳规则 + 一条冲突规则（全部可复算，**不可判定者一律不撤**）

| 规则 | 判据 | 命中 |
|---|---|---:|
| **R1** `defines`（仅模型产物边） | 目标量的**符号**必须出现在**源公式的表达式**（`latex`/`formula`）中 | **23** |
| **R2** `has_symbol`（仅模型产物边） | 目标**符号**必须出现在**源对象的表达式 / `symbols` 声明**中 | **28** |
| **R3** `has_unit`（**全量**） | `dim(物理量) == dim(单位)`（`dimension_table` 真值表 × 单位符号解析） | **29** |
| **R5** `has_unit`（冲突） | 同一量的多条单位边**量纲互斥** → 撤**模型侧**（模型猜测不得与策划断言冲突） | **1** |
| | **合计撤回** | **81** |

**R3 的最重要发现 —— 5 条策划数据本身的错误**（此前**从未被任何门禁检查过**）：

| 边 | 记录量纲 | 应然 |
|---|---|---|
| `力 --has_unit--> kg` | M | 力 = **MLT⁻²** |
| `动量 --has_unit--> N` | MLT⁻² | 动量 = **MLT⁻¹** |
| `角动量 --has_unit--> J` | MLT⁻² | 角动量 = **ML²T⁻¹**（J·s） |
| `冲量 --has_unit--> N` | MLT⁻² | 冲量 = **MLT⁻¹**（N·s） |
| `作用量 --has_unit--> eV` | MLT⁻² | 作用量 = **ML²T⁻¹**（J·s） |

> **R5 是门禁自证抓出来的**：新加的 `unit_unique_per_quantity` 首次运行即 FAIL，暴露 `磁通量` 同时挂 `Wb`(策划,正确) 与 `J/K`(GNN) ——
> 因「磁通量」真量纲不在真值表里（不可判定），R3 撤不掉它。**「不可判定」不等于「可以放过」**。

### 两处判据校准（都用「正反例」冻结）

1. **判据只读表达式，不读散文**：首版把 `informal`/`statement` 等散文也算进「符号是否出现」→ **9 条真·错误边逃逸**
   （如 `Rate of doing work.` 里的 "R"、`Links e, i, and pi.` 里的 "k"）→ 判据收紧为只读 `latex`/`formula`，**并配正对照防误撤**。
2. **数学算子规则宁缺勿滥**：主动删除两条不严规则 —— `\sum`→Taylor（**泛指求和 ≠ 级数展开**，`Z=\sum_i e^{-E_i/kT}` 是配分函数）、`\nabla`→`expand`（微分算子 ≠ 展开）。

### 存真：13 条数学桥 + 1 条单位桥（全部 `rule_checked`）

### 本轮的方法论收获（拟入铁律 #30~#34）

1. **「不可判定」不等于「可以放过」** —— 需要一层与真值无关的**自洽性**断言。
2. **判据字段的选择就是判据强度** —— 只读结构化字段 + 正对照防误撤。
3. **模型猜测不得与策划断言冲突** —— 冲突时撤模型侧；策划自身的错由 R3 单独处理（两条通路互不掩盖）。
4. **每引入一个新维度，都要先问「这里有没有从未被检验过的断言」** —— 「单位」维一加 A8 就冒出 29 条违规。
5. **负结果优先** —— 先侦察证明「数学桥天花板 ≈ 40 条、且 28/29 是噪声」，才避免把整轮投在不可行路线上。
