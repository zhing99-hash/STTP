### 本轮发现的两个具体缺陷

**缺陷 1 · 符号解析用错字段，导致氧元素丢失（正确性 bug）**

- 源数据 `10m_elementkg_release.csv` 中 **E73 = Oxygen**（`NAME_IS=O`）、**E93 = Sulfur**（`NAME_IS=S`），是两个独立实体；
- 两者 `HASATOMIC` 都是 **16**——Oxygen 的这个值实际是**族号**（16 族），不是原子序数；
- `11_真实数据/elementkg10m_ingest.py` 未读取权威的 `NAME_IS`，而是用 `ATOMIC_TO_SYMBOL[HASATOMIC]` 反查 → `16 → "S"`；
- 节点 id 按符号生成 `EK2:el:{sym}` → Oxygen 与 Sulfur **撞 id**，最终只剩一个节点，且字段被污染：
  `EK2:el:S` 的 `symbol=S` 但 `name=Oxygen`、`atomic_number=16`、`weight=15.999`（氧的质量）。
- **后果**：EK2 层 12 个元素中**氧元素整体缺失**，且存在一个自相矛盾的硫节点。

**缺陷 2 · 14 个元素缺原子量**

| `IC:el:*`（无机切片） | sodium(Na) / chlorine(Cl) / iron(Fe) | **NaCl 摩尔质量算不出**（Phase 9 深化已知失败） |

## 三·补·b · A5 轮新增发现（2026-10-08）

A5（元素命名空间去重）施工中又跑出三个真问题，已在同轮修复：

1. **A2 的 GNN 在不同元素之间猜出了 `same_as`**（最严重）
   `gate_check()` 的 Element×Element 分支只判同周期/同族，两者都不满足时返回 `None`，Part A 便**直接采信 GNN 的类型预测**。
   于是产出 `Cl→O`、`N→H`、`H→C` 等 **13 条跨元素符号的 `same_as`**（`same_as` 语义是「同一实体」，跨符号绝不成立）。
   触发原因：`EL:c/h/o`、`BC:el:nitrogen` 挂着 375~670 条 `composed_of` 入边，呈"超级枢纽"形态，嵌入趋同。
   → 清存量 13 条 + `gnn_infer.py` 门控加硬约束（跨符号且既不同周期也不同族 → `REJECTED`）。

2. **`graph_export.py` 在 import 时替换 `sys.stdout`，会让长驻服务全局失联**
   原写法 `sys.stdout = io.TextIOWrapper(sys.stdout.buffer, ...)` 有 **GC 关闭底层 fd** 陷阱：旧 wrapper 被回收时连带关掉同一个 buffer，
   此后进程内所有 `print` 抛 `ValueError: I/O operation on closed file`。
   `viz_server.py` 的 `/api/stats` 一旦触发该 import，服务就**对所有请求返回空响应、连访问日志都打不出**。
   → 改用 `stream.reconfigure(...)` 原地改编码。

3. **`/api/stats` 的类型分布与快照对不上**
   统计直接用 `labels[0]`，但 1658 个节点的 labels 是 `["Entity", "Reaction"]`，首标签恒为 `Entity`，
   导致 Reaction/Molecule/Symbol 全被吞成 `Entity`。→ 改用权威 `graph_export.pick_type()`。

## 三·补·c · A4/A9 轮新增发现（2026-10-09）

网络恢复后推进 A4（离线可视化）与 A9（Kuzu 幂等化），施工中又挖出四个真问题：

1. **fcose 布局从来没有真正生效过（依赖链缺失）**
   `cytoscape-fcose.js` 的 UMD 头是 `root["cytoscapeFcose"] = factory(root["coseBase"])`，
   而 `cose-base.js` 又是 `factory(root["layoutBase"])` —— **三级依赖链**。
   页面原先只引了 fcose 一个文件 → `factory(undefined)` 抛错 → 被 `try { cytoscape.use(...) } catch(e) {}` 吞掉
   → **静默退回内置 cose 布局**，功能表面正常、实际从未启用。
   → 修法：按 `layout-base → cose-base → cytoscape-fcose` 顺序本地化并加载；
   A4 测试增加 `fcose_registered === true` 断言作为永久回归守卫。

2. **MathJax 用 CHTML 构建根本无法真离线**
   `tex-mml-chtml.js` 需另拉 30+ 个 woff 字体文件（散在多个子目录），断网时公式渲染不出。
   → 改用 `tex-svg.js`：SVG 输出把字形路径**内嵌进 DOM**，单文件自包含（2.1 MB）。
   且页面原有配置 `svg: { fontCache: 'global' }` 本就只在 SVG 输出下生效 —— 说明原配置与所加载的构建**从一开始就不匹配**。

3. **`viz_server.py` 自身仍在用被项目废弃的 stdout 替换写法**
   第 45–50 行 `sys.stdout = io.TextIOWrapper(sys.stdout.buffer, ...)`，正是 A5 轮导致服务
   "端口在监听但对所有请求返回空"的那个模式。→ 改为 `stream.reconfigure(...)` 原地改编码，与项目约定对齐。

4. **A3 测试台缺 `document.write` 桩**
   A4 引入的 CDN 兜底写法在 `vm` 沙箱里抛 `TypeError: document.write is not a function`（真实浏览器无此问题）。
   → 给 `a3_path_harness.cjs` 补 `write` 桩，并把写入内容收集起来，便于将来断言兜底 URL。

## 三·补·d · Phase 7b 轮新增发现（2026-10-09）

补齐 Phase 7 缺失切片前先做了一轮「证据否决」，三个直觉被数据推翻：

1. **沙箱出口白名单**（环境认知，影响路线图排序）
   逐主机三轮复测，结果稳定二分：GitHub 全域 / jsdelivr / cdnjs / unpkg / esm.sh / PyPI / **arXiv** / zenodo / doi **可达**；
   **wikidata / wikipedia / wikimedia / huggingface / ncbi / pubchem / neo4j.io 全域 TIMEOUT**。
   → 直接判定 **Phase 9（Wikidata 真实对齐）不可做**，而不是把它当成「网络已通所以能做」。

2. **`score` 字段是「复杂度取反」，不是质量分**（一次差点做错的数据治理）
   与 `complexity` 的相关系数 **−0.995**（score 9.0 ↔ complexity 1.0）。若按「score 降序取优」扩充 PhysicsBabel，
   会把 `m = k₀·v⁻¹·p` 这类**平凡移项**全部选入。→ 与 ElementKG `HASATOMIC` 同一类教训，已记入记忆。

3. **PhysicsBabel 扩容 = 加剧学科失衡，故否掉**
   该数据集 `plausible=True` 共 46,720 条，现行 5000 条对各域覆盖率均 **≈10%**（是**无偏均匀抽样**，不是"选错"）；
   且 **100% 方程都含 mechanics 域**，而图谱物理已占 73%。扩容只会让「跨学科」更失衡 → 不做。

4. **一个遗留缺陷（本轮有意未动）**：`graph_export._NS_SUBJECT` 把 `CM/QM/TH/EM/OP/SM/RT` 等物理切片命名空间
   映射为「数学」。影响面仅限这些切片的**符号节点**（量/单位/常量因带 `phys.*` domain 已正确）。
   系 A8 轮「未知前缀保持旧行为以压缩改动面」时有意保留；修正需同步核对 A3 测试台断言，属独立一轮。

## 三·补·e · Phase 8 轮新增发现（2026-10-09）

开 Phase 8（真实 ETL）时先做数据源可行性验证，两个技术假设被推翻：

1. **出口白名单是「按域 **且按路径**」放行的 —— 域名可达 ≠ 端点可达**（重要环境认知）
   arXiv 分层探测（TLS 握手 → 原始 HTTP）：`export.arxiv.org/` 根路径 ✅200，
   但 **`export.arxiv.org/api/query`（官方 API）TLS 可握手、响应 0 字节超时**；
   `arxiv.org/abs|list` ✅200。→ **arXiv 官方 API 不可用**，路线图「MathXiv 增量拉取」需换通道。
   方法教训：判断端点可用性必须**发真实请求读到响应体**，仅测 TLS 握手会把「路径级拦截」误判为「可达」。

2. **开放学术 API 是 Phase 8 的更好入口**（新发现的可达资源）
   `api.openalex.org` ✅（CC0 学术图谱，含 works/引用/主题）、`api.crossref.org` ✅、
   `api.datacite.org` ✅、`api.semanticscholar.org` ✅（需限速）。
   → Phase 8 数学侧改用 **OpenAlex**，比被拦的 arXiv API 更结构化、更适合批量。

3. **OpenAlex 的 `concepts` 字段有消歧错误，不能直接做概念匹配**（外部字段语义陷阱）
   实测高频 concept 含 `Prime (order theory)` 21、"Ring (chemistry)"、"Calculus (dental)"、"Dentistry"。
   若用 `prime` 匹配 `NT:mc:prime`，会把 21 篇**序理论**论文错挂到**数论素数**上。
   → 改用质量更高的 `primary_topic` 做粗粒度对齐；**宁可桥接稀疏，也不臆造**。
   （与 ElementKG `HASATOMIC`、PhysicsBabel `score` 同属「外部字段语义必须先验证再使用」。）

4. **通用合并器增补 `--reason` / `--label`**：使 `merge_seed_delta.py` 的 delta meta 可随场景定制
   （原先写死「Phase 7 广度切片补齐」），Phase 7 与 Phase 8 共用同一工具。
