# STTP · 前端「局部图谱查询浏览」方案

日期：2026-10-13（Asia/Shanghai）｜性质：**方案（规划）**，未改生产代码
需求来源：老板指令（2026-10-13）——「图库规模非常大，全图浏览不好使用，建议前端页面用户通过
对话框或表单，获取其一部分图库然后展示查看，前端放入任务中提高优先度，规划出一个好的方案。」
关联：`00_项目管理/codex复评响应与下一阶段规划_20261013.md` §4.2（P1-A）/ §5（铁律 #66–#68）；
复评 A06（有限可解释路径查询）、B03（任务入口的局部图谱界面）

---

## 0. 一句话方案

**把默认交互从「打开全图」改成「先说出要看哪一块，再看那一块」**：
前端不再加载 46 MB 全图，改为**查询面板（表单/对话框）→ 后端有限子图 API → 只渲染返回的局部子图**；
「展开邻居 / 问路径 / 按条件筛」三种增量操作在同一契约上叠加；**全图降级为「概览视图」**（聚合元图），
仅在需要establishing context 时使用。

## 1. 问题陈述（先量化，再设计）

| 事实 | 数值 | 后果 |
|---|---|---|
| 规范图规模 | **9 657 节点 / 48 712 边**（`06_PoC/etl/normalized.json`，54.9 MB） | 内存后端可查询，但**前端渲染不了** |
| 前端投影体积 | `06_PoC/graph_data_phase41.json` = **46.5 MB** | 首屏需下载 46 MB |
| 现状入口 | `graph_view.html` `loadData()`（第 384 行） `fetch("./graph_data.json")` → **一次性拉全图**，再 `initCy()` 全量建元素 | 首屏慢、力导向布局在万级节点上不可用（卡死/白屏）|
| 后端已有能力 | `/api/neighbors`（**仅 1 跳**）、`/api/path`（`queries.paths_between`）、`/api/stats` | **没有「给我一块图」的接口**；路径查询`all_simple_paths` **物化为 list、无界**、异常吞成空列表 |
| 已有纪律 | 「页面与查询必须同版本」（`GRAPH_SOURCE_FILE` / Phase 37 R06） | 子图接口必须**继承**该纪律，并新增**快照绑定** |

★ **根因判断**：问题不是「前端画得不够快」，而是**缺少「取一部分」的后端能力**（铁律 #66 的逆命题）。
因此本方案的**主线是后端子图抽取 API，前端是它的视图**。

## 2. 目标 / 非目标

### 2.1 目标（本方案要达成的）

1. 用户能在 **≤ 3 次交互**内看到「他关心的那一小块图」：搜索 → 选中 → 看邻域。
2. 单次响应 **≤ 2 MB**、单次渲染 **≤ ~1 500 节点**（可流畅），且**超预算时有明确提示**。
3. 任何「空 / 截断 / 超时 / 报错」都**与「正常但小」分开显示**（五态）。
4. 子图中每条边都带**证据与来源身份**（`src / src_ver / src_hash / impl_ver`），证据卡片可直接展开。
5. **全图浏览不再存在**；改为「概览视图」（学科×类型聚合元图，几十个节点）。

### 2.2 非目标（明确不做）

- ❌ 不做「全图虚拟化渲染 / WebGL 万级节点引擎」（收益低、与定位无关）；
- ❌ 不做图数据库前端直连（继续走 `viz_server.py` 本地后端，**不引入 Flask**）；
- ❌ 不做自然语言问答式取图（本轮为**表单/对话框**；NL→查询 属后续可选）；
- ❌ 不改动 `graph_export.py` 的投影口径（子图复用同一投影，避免出现第二套格式）。

## 3. 设计原则（与项目铁律对齐）

| 原则 | 对应铁律 | 落地 |
|---|---|---|
| **规模是设计约束，默认入口不得是「加载全量」** | **#66（新）** | 默认视图 = 空画布 + 查询面板 |
| **查询的「空」与「失败」必须分列** | **#67（新）** / #55 | 五态 `ok/no_result/truncated/timeout/error` |
| **页面与查询同版本** | #53 / Phase 37 | 响应绑 `snapshot_id`（查询源 sha256[:12]）；缓存键含 `snapshot_id` |
| **证据的来源身份随证据落库** | #59 / #60 | 子图边内联 `src/src_ver/src_hash/impl_ver`；前端证据卡片直读 |
| **政策/边界由程序执行** | #64 | 预算上限、五态、stale 过滤都是**代码判据**，不是文档约定 |
| **判据非真空** | #14 / #43 | §9 每条验收都配「注入反例 ⇒ 必须变红」 |
| **结构诊断须同报规模** | #55 | 前端始终显示 `n 节点 / m 边（是否 truncated）` |

## 4. 交互设计（四条入口）

> 形态：**顶部全局搜索框 + 左侧查询面板 + 底部路径栏 + 右侧详情/证据卡片**（沿用现有三栏骨架，
> 把左栏的「筛选器」升级为「查询面板」，并把默认数据流从「全图」改为「子图」）。

### 入口 1 · 找点（Search → Ego）

```
[搜索框] 输入 "甲烷" / "CH4" / "Gibbs" / "MX:def:manifold" / "has_quantity"
   ↓ /api/search?q=...&limit=20   （带自动补全）
[候选列表] 显示 id · 类型 · 学科 · 一句话摘要
   ↓ 点击某项
[画布] 该节点 + 1 跳邻域（/api/subgraph?mode=ego&seeds=<id>&hops=1）
```
★ 命中为空 ⇒ 显示「**没有匹配**（no_result）」，并给出**放宽建议**（去掉类型过滤 / 改学科 / 提高 hops）。

### 入口 2 · 展开（Expand，增量）

```
[画布] 选中任一节点 → [展开邻居] 按钮
   ↓ /api/subgraph?mode=ego&seeds=<id>&hops=1
[画布] 新节点/边**并入**当前子图（去重），并显示"本次 +k 节点 / +m 边"；可反复展开
[子图栈] 每次操作入栈 → [返回上一层] 可撤销
```
★ 目的：让用户**从一个小种子逐步长成他需要的大小**，而不是一次要一个「正确的大数」。

### 入口 3 · 问路径（Path）

```
[底部] 起点 / 终点（可「取选中」）→ [高亮路径]
   ↓ /api/path?src=&dst=&max_paths=20&max_hops=5&deadline_ms=3000
[画布] 高亮前 N 条路径（每条带 edge id + 关系语义 + 证据）
```
★ 五态：`ok`（有路径）/ `no_path`（**真的没有**）/ `truncated`（路径数被预算截断，报**截前条数**）/
`timeout` / `error`。**不得**再出现「异常 → 空列表 → 显示『无路径』」。

### 入口 4 · 筛一块（Filter）

```
[左侧面板]
  学科:  [数学][物理][化学]        节点类型: [Formula][Molecule][Element][Reaction][Unit][PhysicalQuantity]...
  边 kind: [composed_of][has_quantity][has_unit][uses_operator]...
  置信度 ≥ [0.00 ──────]    ☑ 仅已验证    ☐ 排除 stale(待 Phase 44)    ☐ 含推断边
  预算: 节点上限 [500]  边上限 [2000]  跳数上限 [3]  超时 [3000] ms
   ↓ [生成子图]
[画布] /api/subgraph?mode=filter&types=...&kinds=...&min_confidence=...&max_nodes=500&...
```
★ 过滤结果若超预算 ⇒ `status=truncated`，画布显示「**已截断：显示 500 / 实有 12 340 节点**」，
并提供「**提高预算** / **缩小过滤**」两个动作。**绝不静默截断。**

### 入口 5（降级）· 概览视图

```
[按钮] 概览 → /api/overview
[画布] 学科×类型的**聚合元图**（约 15 类型 × 3 学科 = 几十个节点；边权 = 边数）
       或「度优先抽样骨架」（top-K 度节点，K≈300），角标明确写 **"概览（非全图）"**
   ↓ 点击任一聚合节点 → 变成入口 4 的一次 filter 查询（按该类型/学科）
```
★ **「全图浏览」这个功能从此不存在**，只存在「概览 → 下钻」。

## 5. 后端契约（`06_PoC/viz_server.py` 新增端点）

> 全部走标准库 `http.server`（不引入 Flask）；全部带 CORS；全部只读。

### 5.1 `GET /api/search`（新增）

| 参数 | 说明 |
|---|---|
| `q` | 文本（id 前缀 / 名称 / 公式 / LaTeX 片段） |
| `types` | 可选，节点类型白名单 |
| `subject` | 可选，学科 |
| `limit` | 默认 20，上限 100 |

返回：`{status, query, count, hits:[{id,type,subject,label,formula,score}]}`

### 5.2 `GET /api/subgraph`（新增 · **核心**）

| 参数 | 默认 | 说明 |
|---|---|---|
| `seeds` | — | 逗号分隔节点 id（与 `query` 二选一） |
| `query` | — | 等价于先 `/api/search` 取首个命中作 seed（一步到位） |
| `mode` | `ego` | `ego` / `path` / `filter` |
| `hops` | 1 | `ego` 模式跳数，上限 `max_hops`（默认 3） |
| `types` | 全部 | 节点类型白名单 |
| `kinds` | 全部 | 边 kind 白名单 |
| `min_confidence` | 0.0 | 边置信度下限 |
| `verified_only` | false | 仅显示独立复核边（≥ rule_checked） |
| `include_inferred` | true | 是否含 `explicit_or_inferred=inferred` |
| `exclude_stale` | **false** | ★ 排除 `status=stale` 的证据环（**Phase 44 后启用**） |
| `max_nodes` | 500 | 硬上限 |
| `max_edges` | 2000 | 硬上限 |
| `max_hops` | 3 | 硬上限 |
| `deadline_ms` | 3000 | 硬上限（超时即返回 `timeout`） |

返回（**统一信封**）：

```json
{
  "status": "ok | no_result | truncated | timeout | error",
  "reason": "",                        
  "snapshot_id": "a1b2c3d4e5f6",       
  "query": { "...参数回显，规范化后..." },
  "query_hash": "sha256(规范化参数)[:16]",
  "seed": {"id": "...", "type": "...", "subject": "..."},
  "nodes": [ /* 与 graph_data.json 同投影：id/label/type/labels/subject/domain/formula/confidence/attrs */ ],
  "edges": [ /* id/source/target/type/kind/confidence/explicit_or_inferred/verified/evidence/rationale
                + src/src_ver/src_hash/impl_ver */ ],
  "stats": {
    "n_nodes": 428, "n_edges": 1103,
    "truncated_by": null,              
    "pre_truncation": {"n_nodes": 428, "n_edges": 1103},
    "expansions": 1, "elapsed_ms": 37
  }
}
```

**语义约定（必须实现）**：

| status | 含义 | 前端必须区分显示 |
|---|---|---|
| `ok` | 有结果且**未被截断** | 「428 节点 / 1 103 边」 |
| `no_result` | **确实没有**（seed 不存在 / 过滤后为空） | 「没有找到」+ 放宽建议（**不是**「0 节点」） |
| `truncated` | 有结果但**被预算截断** | 「已截断：显示 500 / 实有 12 340」+ 截断原因 `nodes/edges/hops/paths` |
| `timeout` | 超 `deadline_ms` | 「超时（3 000 ms）」+ 建议缩小范围 |
| `error` | 异常 | 显示异常类型与信息（**不得吞成空**） |

### 5.3 `GET /api/path`（**改造**现有）

- 新增 `max_paths`（默认 20）/ `max_hops`（默认 5）/ `deadline_ms`（默认 3000）；
- **`queries.paths_between` 去掉 `list(all_simple_paths(...))` 的无界物化**：改为**带预算的 DFS/BFS**，
  `yield` 到 `max_paths` 即停，返回 `(paths, truncated: bool, pre_truncation_count)`；
- **不再吞异常**：`nx.NodeNotFound` ⇒ `no_path`；超时 ⇒ `timeout`；其他异常 ⇒ `error`。

### 5.4 `GET /api/overview`（新增 · 概览视图）

返回**聚合元图**：`nodes = 学科×类型组合`（约几十个），`edges = 组合间的边数（权重）`。
★ 可选参数 `mode=sample&k=300` 返回度优先抽样骨架。响应含 `"note": "概览，非全图"`。

### 5.5 端点统一纪律

1. **`snapshot_id`** = 查询源文件（`GRAPH_SOURCE_FILE` / `with_inferred.json` / `normalized.json`）的
   `sha256[:12]`，**每次请求现算**（图变了 id 就变 ⇒ 前端缓存自动失效）。
2. **`query_hash`** = 规范化参数（键排序、默认值补全）的 `sha256[:16]`，用于前端缓存与**复现**。
3. 所有响应 `Cache-Control: no-store`（与现状一致）；如需缓存，键必须 = `snapshot_id + query_hash`。
4. **顶层错误**一律包成 `{"status":"error","reason":"..."}` 且 HTTP 200（便于前端统一处理），
   但 4xx（参数非法）保留 HTTP 400 并附 `reason`。

## 6. 前端改造（`06_PoC/graph_view.html`）

### 6.1 结构变化

| 区域 | 现状 | 改造后 |
|---|---|---|
| 顶部 | 数据状态 + 适配/重置/布局 | ＋**全局搜索框**（自动补全）＋**当前子图规模**徽章 ＋**概览**按钮 |
| 左侧 | 搜索 + 类型/边类型/置信度筛选 + 图例 | **查询面板**（入口 4 全参数）＋ 图例；**缩小为可折叠** |
| 中间 | Cytoscape 画布（全图） | 画布（**子图**）＋ **子图栈**工具条（返回上一层 / 重置 / 当前规模） |
| 底部 | 路径高亮栏 | 保留 ＋ **五态状态行**（ok/no_result/truncated/timeout/error 逐色区分） |
| 右侧 | 节点详情 | 节点详情 ＋ **边证据卡片**（kind/verifier/来源 id+version+哈希/复算结果）＋ 截断提示 |

### 6.2 关键实现要点

1. **初始化不再 `fetch("./graph_data.json")`**；改为渲染空画布 + 查询面板。
   （`loadData()` 保留但**仅**用于「概览」与**离线样例单文件**模式：见 §6.4）
2. **元素合并去重**：每次响应按 `node.id` / `edge.id` 并入 `cy`（`cy.add()` + 已存在则跳过），
   展开操作天然幂等；**布局**：新元素做局部 `fcose` 局部布局，避免整图重排。
3. **子图栈**：栈元素 = `{snapshot_id, query_hash, 参数}`；「返回上一层」= 重新请求上一参数（而非缓存整图）。
4. **五态视觉**：`truncated` 用**黄色横幅**并强制显示「显示 X / 实有 Y」；`timeout/error` 用**红色**；
   `no_result` 用**中性灰**并给建议 —— **四者可一眼区分**。
5. **证据卡片**：边点击 → 读 `edge.evidence[]`，每条显示 `kind / impl(=verifier) / src / src_ver / src_hash[:12] / impl_ver`，
   并**明确标注**「`impl` = 谁验的，`src` = 读的是哪个源/哪一版」（铁律 #59）。
6. **保留既有能力**：MathJax 公式渲染、ghost 外部节点、explicit/inferred 区别着色、置信度阈值 —— 全部沿用，
   只是作用域从「全图」变成「当前子图」。

### 6.3 「概览 → 下钻」路径（替代全图）

`概览视图` 的每个聚合节点携带 `{type, subject}` ⇒ 点击即触发 `mode=filter&types=<type>&subject=<subject>`
⇒ 进入局部子图。**这就是「全图」的替代品**：先看骨架，再下钻到块。

### 6.4 离线样例模式（与发布包兼容，必须保住）

发布包（`bash sttp.sh sample`）用**单文件样例**（`sample_graph.json` / `sample_normalized.json`）离线跑通。
该场景下 `graph_data.json` 很小（样例 < 1 MB），**可以**继续整图加载。
⇒ 设计上提供**两种模式**，由响应/配置决定：

- `mode=live`（默认）：查询面板 + 子图 API；
- `mode=bundle`：单文件整图（仅样例/小图，页面角标**标注「样例全量」**）。

★ 这保证 **Phase 43 改造不破坏已验证的发布样例链路**（`verify_release.py` 的 25 条断言、样例子集 78 条）。

## 7. 数据流（端到端）

```
用户输入（搜索/展开/路径/筛选）
   → 前端规范化参数 → /api/subgraph|/api/path|/api/search
   → viz_server 路由 → queries.NXBackend（或 Neo4j）
        ├─ 预算控制（max_nodes/max_edges/max_hops/deadline）
        ├─ 过滤（types / kinds / min_confidence / verified_only / exclude_stale）
        └─ 五态判定（ok/no_result/truncated/timeout/error）
   → 投影为 graph_data 同格式（复用 graph_export 的字段口径）
   → JSON 响应（+ snapshot_id / query_hash / stats）
   → 前端合并入 cy → 局部布局 → 渲染
   → 状态行显示规模与五态；证据卡片按需展开
```

## 8. 预算与性能目标

| 指标 | 目标 |
|---|---|
| 单次响应体积 | ≤ **2 MB**（`max_edges=2000` 时约 1–1.5 MB） |
| 单次渲染节点数 | ≤ **1 500**（超出即 `truncated`） |
| `/api/subgraph` P50/P95 | ≤ **150 ms / 800 ms**（NetworkX 内存后端） |
| `/api/search` P95 | ≤ **200 ms** |
| 首屏（无查询） | **0 图数据下载**（只下 HTML + vendor） |

## 9. 验收标准（**每条都可注入反例变红**）

| # | 断言 | 反例（注入后必须变红） |
|---|---|---|
| V1 | 首屏**不请求全图** | 在页面初始化 fetch 列表中断言无 `graph_data.json` 全量项 |
| V2 | 超预算 ⇒ `status=truncated` 且 `reason` 非空、`n_nodes ≤ max_nodes` | 构造必然超预算的 filter（`types=Formula,Molecule&max_nodes=50`） |
| V3 | 不存在 seed ⇒ `status=no_result`（**≠ `ok`**） | `seeds=DOES:NOT:EXIST` |
| V4 | 环/大图 ⇒ `status=timeout` 且 `elapsed_ms ≥ deadline_ms` | `mode=path&src=...&dst=...&deadline_ms=1` |
| V5 | `snapshot_id` == 查询源 sha256[:12]；换图 ⇒ 变 | `rm` + `checkout -f --` 换一份快照（★ 参照铁律 #61 的负对照手法） |
| V6 | 子图每条边都有 `src/src_ver/src_hash/impl_ver` | 抹掉一条证据的 `src` ⇒ 断言失败（复用 Phase 41 门禁判据） |
| V7 | `exclude_stale=true` 时 stale 边不出现 | 注入一条 `status=stale` 证据（Phase 44 后启用） |
| V8 | 五态在 UI 上**颜色可区分**（截断=黄、超时/错误=红、无结果=灰） | 快照比对（人工/截图断言）+ DOM class 断言 |
| V9 | `mode=bundle` 下发布样例链路**仍通过** | 跑 `bash sttp.sh release`（25 条）+ `release-full`（门禁 108） |
| V10 | 同参数两次请求 `query_hash` 相同、`nodes/edges` 逐元素相同（确定性） | 连发两次比对 |

★ **验收纪律**：V2–V5 必须**同时**有「正例通过」与「反例变红」两条证据（铁律 #14/#43）。

## 11. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 局部布局反复重排导致闪烁 | 体验差 | 新元素只做`局部 fcose`；已有元素位置锁定（`cy.nodes().lock()` 局部） |
| 预算太小 ⇒ 频繁截断，用户反复调参 | 体验差 | 截断横幅直接给**一键「提高预算」**（×2 / ×5）；记住上次预算 |
| `hops=2` 在 hub 节点（如某 Formula）上爆炸 | 响应过大 | `max_nodes` 硬截断 + `truncated` 明示；hub 节点建议提示「该节点邻居 1 203 个」 |
| Neo4j 后端与 NX 后端语义漂移 | 双实现不一致 | **同一份契约测试**跑两个后端（至少 NX 全跑；Neo4j 可选跳过并标记 SKIP=失败） |
| 改前端破坏发布样例链路 | 回归 | `mode=bundle` 双模式 + V9 断言（Phase 37 的 25 条 + 样例子集 78 必须保持绿） |
| `exclude_stale` 依赖 A04（Phase 44） | 前端先行时该开关不可用 | 先以 `exclude_stale` **默认关闭 + UI 置灰并标注「待 Phase 44」**，A04 完成后启用 |
