> **v1 → v2 改了什么**（评审书 §3/§6）
> ① **修正 UI 标注错误**：`composed_of / has_quantity / has_unit / uses_operator …` 是 **`type`（语义关系，24 种）**，
> 不是 `kind`（来源/管线标签，**115 种**）⇒ 过滤改为**双维度两组 UI**（评审 §2-M1）。
> ② **吸收 4 条更强设计**：会话级累计预算 / 服务端签发 `expandable token` / `why_shown` / 优先分与可信度分列。

> 桌面宽度分配与断点、页面加载与服务耗时分开统计等。
> ④ **修正可信度档位**：单档 → **两档** `verified` / `verified_strict`（默认 `verified`），必显「已隐藏 N 条」。
> ⑤ **修正过期语义**：不新造 `status: valid|stale`（该字段不存在），改为 `evidence[].src_hash` vs

> ⑥ **明确排除**：React/Vite 构建链、FastAPI 新服务、任务账号、用户试用、Remotion 视频（均为 Option，见评审书 §4/§5）；
> 前端改用**浏览器原生 ES Module 拆分**（零构建、离线照开）替代构建链。

> **v2 → v3 改了什么**（**实现与方案的实际偏差**，逐条对应报告 §6）
> ① ★★ **新增最重前提（D1）**：`stale` 判据依赖「worktree 字节 == 仓库 blob」，实测**不成立**
> （7/21 已入库 `locator` 行尾不一致、13 个未入库）⇒ **干净检出下会假阳**。已加探针并随响应暴露，
> **根因未修**，因此 **`exclude_stale` 默认仍为 `false`（有意）**；修法须与 Phase 44 对齐。
> ② **契约文件收窄为 4 份**：只做 `subgraph / search / overview / error`。**`task_draft` / `task_result` 未做**
> ——它们属「任务型」接口（B01–B03 / C01，**已裁决不做**），本方案 §5 也从未定义其字段；硬造 schema = 无实现可校验（铁律 #38）。
> ③ **`session_budget` 参数取消**，改为**服务端按 `session_id` 记账**：新增 `session_id`（缺省 ⇒ **不记账、不判硬门**，
> `stats.session.tracked=false`）与 `reset=1`（前端「重置」）；记账模式 = `ego` 增量 / `filter`·`path` 视为新视图先重置；
> 会话表上限 **256**（超限按最久未写淘汰）。★ 自检 **V17a–V17e**。
> ④ **`filter` 模式必须至少一个过滤条件**：`mode=filter&trust=all` 单独使用 ⇒ **HTTP 400**（**刻意**防全图倾倒；
> 全图走 `/api/overview`）。前端须把它渲染成「请至少选一个筛选项」而非系统故障。
> ⑤ **`pending_frontier` 明确是下界**（中断时队列长度），字段旁附 `pending_frontier_note`；前端**不得**渲染成"还有 N 个"。
> ⑥ **`path` 模式在 hub 端点必超时**（实测 `PQ:mass → MX:def:manifold` hops≥3 ⇒ 3.1–3.3 s `timeout`）——
> 是**正确行为**（非空、非失败）；双向 BFS/剪枝列为**待办**。
> ⑦ **`/api/path` 保留 legacy 扁平信封**（旧页面兼容）⇒ 新前端代码一律用 `/api/subgraph?mode=path`。
> ⑧ **`error_code` 两个是接口预留**：`ENTITY_AMBIGUOUS` / `MISSING_CONDITION` 本轮**无产生路径**（属科学任务层）。
> ⑨ **契约校验器是 JSON-Schema 子集**（12 个关键字）；新增自检 **C5b** 断言 schema 不得使用未实现关键字
> （防"写了但不检查"的静默失效）。
> ⑩ **§8 性能目标已用实测替换**（见下）——其中 **默认预算下最坏 2.4 MB**、**硬上限下 10.3 MB**，**§8 原定的 ≤2 MB 未达标**。

## 0. 一句话方案

**把默认交互从「打开全图」改成「先说出要看哪一块，再看那一块」**：
前端不再加载 46 MB 全图，改为**查询面板（表单/对话框）→ 后端有限子图 API → 只渲染返回的局部子图**；
「展开邻居 / 问路径 / 按条件筛」三种增量操作在同一契约上叠加；**全图降级为「概览视图」**（聚合元图），
仅在需要establishing context 时使用。

## 1. 问题陈述（先量化，再设计）

| 事实 | 数值 | 后果 |
|---|---|---|
| 规范图规模 | **9 657 节点 / 48 712 边**（`06_PoC/etl/normalized.json`，54.9 MB） | 内存后端可查询，但**前端渲染不了** |
| 前端投影体积 | `06_PoC/graph_data_phase41.json` = **46.5 MB** | 首屏需下载 46 MB |
| 现状入口 | `graph_view.html` `loadData()`（第 384 行） `fetch("./graph_data.json")` → **一次性拉全图**，再 `initCy()` 全量建元素 | 首屏慢、力导向布局在万级节点上不可用（卡死/白屏）|
| 后端已有能力 | `/api/neighbors`（**仅 1 跳**）、`/api/path`（`queries.paths_between`）、`/api/stats` | **没有「给我一块图」的接口**；路径查询`all_simple_paths` **物化为 list、无界**、异常吞成空列表 |
| 已有纪律 | 「页面与查询必须同版本」（`GRAPH_SOURCE_FILE` / Phase 37 R06） | 子图接口必须**继承**该纪律，并新增**快照绑定** |

★ **根因判断**：问题不是「前端画得不够快」，而是**缺少「取一部分」的后端能力**（铁律 #66 的逆命题）。
因此本方案的**主线是后端子图抽取 API，前端是它的视图**。

## 2. 目标 / 非目标

### 2.1 目标（本方案要达成的）

1. 用户能在 **≤ 3 次交互**内看到「他关心的那一小块图」：搜索 → 选中 → 看邻域。
2. 单次响应 **≤ 2 MB**、单次渲染 **≤ ~1 500 节点**（可流畅），且**超预算时有明确提示**。
3. 任何「空 / 截断 / 超时 / 报错」都**与「正常但小」分开显示**（五态）。
4. 子图中每条边都带**证据与来源身份**（`src / src_ver / src_hash / impl_ver`），证据卡片可直接展开。
5. **全图浏览不再存在**；改为「概览视图」（学科×类型聚合元图，几十个节点）。

### 2.2 非目标（明确不做）

- ❌ 不做「全图虚拟化渲染 / WebGL 万级节点引擎」（收益低、与定位无关）；
- ❌ 不做图数据库前端直连（继续走 `viz_server.py` 本地后端，**不引入 Flask**）；
- ❌ 不做自然语言问答式取图（本轮为**表单/对话框**；NL→查询 属后续可选，且**不得**引入 LLM 任务解释器
  —— 属产品化，评审书 §4-O2）；
- ❌ 不改动 `graph_export.py` 的投影口径（子图复用同一投影，避免出现第二套格式）；
- ★ ❌ **不引入前端构建链**（React / TS / Vite / TanStack Query / Zod）—— 仓库现**无 `package.json`**，
  现前端为**单文件 + 本地 vendor**（cytoscape 3.30.2 / fcose 2.2.0 / mathjax 3.2.2，各带 LICENSE），
  **离线可开、无构建**，且 `verify_release.py` 通过读 `graph_view.html` 内的查询契约做
  「页面↔查询同版本」断言。换构建链会同时破坏**离线可复现**与**既有校验**（评审书 §4-O1）。
  ⇒ 可维护性收益改由**浏览器原生 ES Module 拆分**取得（零构建、零新依赖、离线照开，见 §6.1）；
- ★ ❌ **不做 Remotion 视频链路**（评审书 §5：许可非 OSI、与「无构建链 / 推送预算 / 离线可复现」三约束冲突、
  价值定位为"演示"而指南 §0.1 明列不作为评价标准）。「可带走」需求由 §6.5 的导出能力满足。

## 3. 设计原则（与项目铁律对齐）

| 原则 | 对应铁律 | 落地 |
|---|---|---|
| **规模是设计约束，默认入口不得是「加载全量」** | **#66（新）** | 默认视图 = 空画布 + 查询面板 |
| **查询的「空」与「失败」必须分列** | **#67（新）** / #55 | 五态 `ok/no_result/truncated/timeout/error` |
| **页面与查询同版本** | #53 / Phase 37 | 响应绑 `snapshot_id`（查询源 sha256[:12]）；缓存键含 `snapshot_id` |
| **证据的来源身份随证据落库** | #59 / #60 | 子图边内联 `src/src_ver/src_hash/impl_ver`；前端证据卡片直读 |
| **政策/边界由程序执行** | #64 | 预算上限、五态、stale 过滤都是**代码判据**，不是文档约定 |
| **判据非真空** | #14 / #43 | §9 每条验收都配「注入反例 ⇒ 必须变红」 |
| **结构诊断须同报规模** | #55 | 前端始终显示 `n 节点 / m 边（是否 truncated）` |

## 4. 交互设计（四条入口）

> 形态：**顶部全局搜索框 + 左侧查询面板 + 底部路径栏 + 右侧详情/证据卡片**（沿用现有三栏骨架，
> 把左栏的「筛选器」升级为「查询面板」，并把默认数据流从「全图」改为「子图」）。

### 入口 1 · 找点（Search → Ego）

```
[搜索框] 输入 "甲烷" / "CH4" / "Gibbs" / "MX:def:manifold" / "has_quantity"
   ↓ /api/search?q=...&limit=20   （带自动补全）
[候选列表] 显示 id · 类型 · 学科 · 一句话摘要
   ↓ 点击某项
[画布] 该节点 + 1 跳邻域（/api/subgraph?mode=ego&seeds=<id>&hops=1）
```
★ 命中为空 ⇒ 显示「**没有匹配**（no_result）」，并给出**放宽建议**（去掉类型过滤 / 改学科 / 提高 hops）。

### 入口 2 · 展开（Expand，增量）

```
[画布] 选中任一节点 → [展开邻居] 按钮
   ↓ /api/subgraph?mode=ego&seeds=<id>&hops=1
[画布] 新节点/边**并入**当前子图（去重），并显示"本次 +k 节点 / +m 边"；可反复展开
[子图栈] 每次操作入栈 → [返回上一层] 可撤销
```
★ 目的：让用户**从一个小种子逐步长成他需要的大小**，而不是一次要一个「正确的大数」。

### 入口 3 · 问路径（Path）

```
[底部] 起点 / 终点（可「取选中」）→ [高亮路径]
   ↓ /api/path?src=&dst=&max_paths=20&max_hops=5&deadline_ms=3000
[画布] 高亮前 N 条路径（每条带 edge id + 关系语义 + 证据）
```
★ 五态：`ok`（有路径）/ `no_path`（**真的没有**）/ `truncated`（路径数被预算截断，报**截前条数**）/
`timeout` / `error`。**不得**再出现「异常 → 空列表 → 显示『无路径』」。

### 入口 4 · 筛一块（Filter）

```
[左侧面板]
  ★ 维度一 · 语义关系 (type，白名单来自实测 24 种)
    [has_symbol][composed_of][has_quantity][reactant_of][product_of][defines][has_unit]
    [uses_operator][derived_from][has_element][same_as][dimensionally_consistent]...
  ★ 维度二 · 来源/管线 (kind，115 种；默认全部)
    [real][rhea_product][chebi_composition][gnn_typed_verified][webbook_thermochemistry]...
  学科:  [数学][物理][化学]        节点类型: [Formula][Molecule][Element][Reaction][Unit][PhysicalQuantity]...
  可信范围 (radio):  ( ) verified（≥by_construction，默认）  ( ) verified_strict（≥rule_checked）
  置信度 ≥ [0.00 ──────]    ☐ 排除 model_inferred    ☐ 排除 stale(待 A04)    ☐ 含推断边
  预算: 单次节点上限 [500]  单次边上限 [2000]  跳数上限 [3]  超时 [3000] ms
        会话累计上限 120 节点 / 200 边（达到即禁止继续展开，非静默截断）
   ↓ [生成子图]
[画布] /api/subgraph?mode=filter&types=...&kinds=...&trust=verified&min_confidence=...&max_nodes=500&...
       ★ 过滤生效后**必须**显示「已隐藏 N 条（N 因可信范围被排除）」——禁止无提示剔除。
```
★ **`type` 与 `kind` 是两个不同维度，UI 必须分两组**（评审书 §2-M1）：
`type` = 语义关系（`has_symbol` 24 341 / `composed_of` 7 756 / `has_quantity` 4 478 …，共 **24** 种）；
`kind` = **来源与管线标签**（`real` 26 563 / `chebi_composition` 5 092 / `gnn_typed_verified` 3 324 …，共 **115** 种）。
把关系名当 `kind` 传参会**返回 0 条**（`filter_edges_by_kind("has_quantity")` 实测为空）。
★ **可信范围两档**（评审书 §2-M3）：实测 `verification_level` 为
`rule_checked` 31 520 / `source_asserted` 13 797 / `cross_source` 3 249 / `model_inferred` 135 / `by_construction` 11——
只给「rule_checked 及以上」会**隐藏 56.9% 的边**（含 13 797 条 `source_asserted`）而不告知；
故默认 `verified`（≥`by_construction`，铁律 #19），`verified_strict` 为可选项，**两者都显示剩余量**。
```
★ 过滤结果若超预算 ⇒ `status=truncated`，画布显示「**已截断：显示 500 / 实有 12 340 节点**」，
并提供「**提高预算** / **缩小过滤**」两个动作。**绝不静默截断。**

### 入口 5（降级）· 概览视图

```
[按钮] 概览 → /api/overview
[画布] 学科×类型的**聚合元图**（约 15 类型 × 3 学科 = 几十个节点；边权 = 边数）
       或「度优先抽样骨架」（top-K 度节点，K≈300），角标明确写 **"概览（非全图）"**
   ↓ 点击任一聚合节点 → 变成入口 4 的一次 filter 查询（按该类型/学科）
```
★ **「全图浏览」这个功能从此不存在**，只存在「概览 → 下钻」。

## 5. 后端契约（`06_PoC/viz_server.py` 新增端点）

> 全部走标准库 `http.server`（不引入 Flask）；全部带 CORS；全部只读。

### 5.1 `GET /api/search`（新增）

| 参数 | 说明 |
|---|---|
| `q` | 文本（id 前缀 / 名称 / 公式 / LaTeX 片段） |
| `types` | 可选，节点类型白名单 |
| `subject` | 可选，学科 |
| `limit` | 默认 20，上限 100 |

返回：`{status, query, count, hits:[{id,type,subject,label,formula,score}]}`

### 5.2 `GET /api/subgraph`（新增 · **核心**）

| 参数 | 默认 | 说明 |
|---|---|---|
| `seeds` | — | 逗号分隔节点 id（与 `query` 二选一） |
| `query` | — | 等价于先 `/api/search` 取首个命中作 seed（一步到位） |
| `mode` | `ego` | `ego` / `path` / `filter` |
| `hops` | 1 | `ego` 模式跳数，上限 `max_hops`（默认 3） |
| `node_types` | 全部 | **节点类型**白名单（`Formula`/`Molecule`/`Element`/`Reaction`/`Unit`/`PhysicalQuantity`…） |
| `types` | 全部 | ★ **语义关系（edge `type`）白名单**，实测 24 种；常用见 §4 入口 4（**不是** `kind**） |
| `kinds` | 全部 | ★ **来源/管线标签（edge `kind`）白名单**，实测 115 种（`real`/`rhea_product`/`gnn_typed_verified`…） |
| `trust` | `verified` | ★ `verified`（≥`by_construction`）/ `verified_strict`（≥`rule_checked`）；**决定可见边集，须回显已隐藏条数** |
| `min_confidence` | 0.0 | 边置信度下限 |
| `exclude_model_inferred` | false | 排除 `verification_level=model_inferred`（实测 135 条） |
| `exclude_stale` | **false** | ★ 排除 **stale 边**（定义见下；血缘缺口 fail-closed 视为 stale） |
| `max_nodes` | 500 | 单次硬上限 |
| `max_edges` | 2000 | 单次硬上限 |
| `max_hops` | 3 | 硬上限 |
| `deadline_ms` | 3000 | 硬上限（超时即返回 `timeout`） |
| `session_id` | — | ★ **v3 修正**：**无此参数 ⇒ 不记账、不判硬门**（`stats.session.tracked=false`，匿名调用彼此独立）。会话级累计上限 `120/200`（节点/边）由服务端**按 `session_id` 记账**，**达到即拒绝继续展开**（不静默截断）；`ego` 增量，`filter`/`path` 视为新视图先重置 |
| `reset` | — | ★ **v3 新增**：`reset=1` ⇒ 先清空该会话计数（前端「重置」按钮） |
| `expand_token` | — | ★ 展开凭证（§5.2.1）；`mode=expand` 时**必须**带，服务端据此校验**快照一致 + 种子 + 预算口径（`filt=query_hash`）**；篡改/伪造 ⇒ **400** |

返回（**统一信封**）：

```json
{
  "status": "ok | no_result | truncated | timeout | error",
  "reason": "",                        
  "error_code": null,                  
  "snapshot_id": "sha256:a1b2c3d4e5f6", 
  "query": { "...参数回显，规范化后..." },
  "query_hash": "sha256(规范化参数)[:16]",

**`why_shown`（新增 · 吸收 codex §5.5「为什么显示」）** —— 枚举，**每个节点/边必带**：

| 值 | 含义 |
|---|---|
| `used_in_step` | 本次计算/判定**直接使用** |
| `evidence_path` | 位于结论的**证据路径**上 |
| `user_specified` | 用户**明确指定**（种子 / 搜索命中 / 点击展开） |
| `task_anchor` | 系统识别的**任务锚点**（目标量、缺失条件关联的量/单位/定义） |
| `verified_context` | 经过验证的**一跳上下文** |
| `expansion` | 由某次**展开**并入（携带 `from_node`） |

★ **`why_shown` 与「展示优先分」是裁剪排序依据，`verification_level` 是证据强度 —— 三者不得混为一个"可信度"视觉编码**
（评审书 §3.1-S4；节点大小/边粗细只能表达其中**一个**，其余用徽标/文字/线型）。

**stale 的定义（修正：不新造 `status` 字段，评审书 §2-M2）**：

> 一条边 **stale** ⇔ 其 `evidence[]` 中存在 `e.src_hash ≠ source_registry[e.src]` 的**当前内容哈希**，
> 或 `e.src ∈ lineage_gap_sources`（血缘缺口 ⇒ 无法判定 ⇒ **fail-closed 视为 stale**）。
> 数据来源：`11_真实数据/source_registry.py`（31 源，version/locator/内容哈希/`imports_from`）+
> `11_真实数据/lineage_invalidation.py`（`sttp-lineage-invalidation/v1`，当前 `n_affected_edges=0`）。
> ★ 实测：边 props 里的 `status` **只出现在 3 423 条（7.0%）** 且取值为 `VERIFIED`/`NEEDS_REVIEW`（GNN 产物），
> **与"过期"无关** ⇒ 规划原文的 `"status": "valid"` 字段在本仓库**不存在**。

#### 5.2.1 `expandable[].token`（新增 · 吸收 codex §8.5）

由**服务端签发**，绑定 `task_id + snapshot_id + 过滤条件 + 剩余预算`；契约：

- `mode=expand` 请求**必须**携带 `expand_token`，服务端**重算**并拒绝不匹配/超预算的展开；
- 前端**不得**自行拼接任意参数构造无限查询（这条把预算控制权从浏览器收回服务端）；
- token 用 **HMAC(服务端密钥, 规范化参数 + 剩余预算)** 生成，**不透明、不可伪造**；
- 同一 token 重复使用 ⇒ 幂等（返回同一批增量），避免前端重试放大预算。

**语义约定（必须实现）**：

| status | 含义 | 前端必须区分显示 |
|---|---|---|
| `ok` | 有结果且**未被截断** | 「428 节点 / 1 103 边」 |
| `no_result` | **确实没有**（seed 不存在 / 过滤后为空） | 「没有找到」+ 放宽建议（**不是**「0 节点」） |
| `truncated` | 有结果但**被预算截断** | 「已截断：显示 500 / 实有 12 340」+ `truncated_by ∈ nodes/edges/hops/paths/deadline` |
| `timeout` | 超 `deadline_ms` | 「超时（3 000 ms）」+ 建议缩小范围 |
| `error` | 异常 | 显示 `error_code` + 异常信息（**不得吞成空**） |

**`error_code`（新增 · 吸收 codex §8.6；与上面五态**共存不并存**：五态管"结果类别"，`error_code` 管"原因"）**：

| code | 触发 |
|---|---|
| `ENTITY_AMBIGUOUS` | 实体消歧失败（同分子式异构体 / 不同质子化态） |
| `MISSING_CONDITION` | 缺必要条件（温度、物相、标准态、单位、定义域） |
| `SNAPSHOT_MISMATCH` | 请求的 `snapshot_id` 与当前查询源不符 |
| `EVIDENCE_STALE` | 引用了 stale 证据（§5.2 stale 定义） |
| `SUBGRAPH_LIMIT_REACHED` | 命中预算（单次或会话级） |
| `GRAPH_QUERY_TIMEOUT` | 超 `deadline_ms` |
| `TOOL_EXECUTION_ERROR` | 受控工具执行异常 |
| `BAD_REQUEST` | 参数非法（HTTP 400） |

### 5.3 `GET /api/path`（**改造**现有）

- 新增 `max_paths`（默认 20）/ `max_hops`（默认 5）/ `deadline_ms`（默认 3000）；
- **`queries.paths_between` 去掉 `list(all_simple_paths(...))` 的无界物化**：改为**带预算的 DFS/BFS**，
  `yield` 到 `max_paths` 即停，返回 `(paths, truncated: bool, pre_truncation_count)`；
- **不再吞异常**：`nx.NodeNotFound` ⇒ `no_path`；超时 ⇒ `timeout`；其他异常 ⇒ `error`。

### 5.4 `GET /api/overview`（新增 · 概览视图）

返回**聚合元图**：`nodes = 学科×类型组合`（约几十个），`edges = 组合间的边数（权重）`。
★ 可选参数 `mode=sample&k=300` 返回度优先抽样骨架。响应含 `"note": "概览，非全图"`。

### 5.5 端点统一纪律

1. **`snapshot_id`** = 查询源文件（`GRAPH_SOURCE_FILE` / `with_inferred.json` / `normalized.json`）的
   `sha256[:12]`，**每次请求现算**（图变了 id 就变 ⇒ 前端缓存自动失效）。
2. **`query_hash`** = 规范化参数（键排序、默认值补全）的 `sha256[:16]`，用于前端缓存与**复现**。
3. 所有响应 `Cache-Control: no-store`（与现状一致）；如需缓存，键必须 = `snapshot_id + query_hash`。
4. **顶层错误**一律包成 `{"status":"error","reason":"..."}` 且 HTTP 200（便于前端统一处理），
   但 4xx（参数非法）保留 HTTP 400 并附 `reason`。

### 6.2 关键实现要点

1. **初始化不再 `fetch("./graph_data.json")`**；改为渲染空画布 + 查询面板。
   （`loadData()` 保留但**仅**用于「概览」与**离线样例单文件**模式：见 §6.4）
2. **元素合并去重**：每次响应按 `node.id` / `edge.id` 并入 `cy`（`cy.add()` + 已存在则跳过），
   展开操作天然幂等；**布局**：新元素做局部 `fcose` 局部布局，避免整图重排。
3. **子图栈**：栈元素 = `{snapshot_id, query_hash, 参数, session 记账}`；「返回上一层」= 重新请求上一参数
   （而非缓存整图）；★ **同时回滚会话累计计数**。
4. **五态视觉**：`truncated` 用**黄色横幅**并强制显示「显示 X / 实有 Y」+ `truncated_by`；`timeout/error` 用**红色**
   并显示 `error_code`；`no_result` 用**中性灰**并给建议 —— **四者可一眼区分**，且**颜色 + 图标 + 文字三重编码**
   （不得只靠颜色，评审书 §3.2-I10）。
5. **证据卡片**：边点击 → 读 `edge.evidence[]`，每条显示 `kind / impl(=verifier) / src / src_ver / src_hash[:12] / impl_ver`，
   并**明确标注**「`impl` = 谁验的，`src` = 读的是哪个源/哪一版」（铁律 #59）；
   ★ 若该证据判 **stale**（§5.2 定义）则在卡片上以**琥珀色徽标**标出，并在边工具栏提示。
6. **`why_shown` 必显**：节点抽屉与边抽屉顶部固定一行「为什么显示」；取值见 §5.2 表。
7. ★ **可信度不得混成一个视觉编码**：节点**填充色 = 学科**、**形状 = 类型**；边**颜色 = 语义关系 `type`**、
   **线型 = explicit/inferred**；**`verification_level` 用徽标**、**展示优先分用排序/淡入**。
   二者（可信度 vs 优先分）**必须可分别读出**（评审书 §3.1-S4）。
8. **过滤生效提示**：任何过滤（可信范围 / 学科 / 类型 / 来源 / 置信度）**必须显示「已隐藏 N 条」**。
9. **保留既有能力**：MathJax 公式渲染、ghost 外部节点、explicit/inferred 区别着色、置信度阈值 —— 全部沿用，
   只是作用域从「全图」变成「当前子图」。
10. **会话累计硬门**：达到 `120 节点 / 200 边` ⇒ **禁用**所有展开按钮并提示「本次会话预算已用尽，请返回上一层或重置」，
    **不得静默截断**、不得自动放宽。

### 6.3 「概览 → 下钻」路径（替代全图）

`概览视图` 的每个聚合节点携带 `{type, subject}` ⇒ 点击即触发 `mode=filter&types=<type>&subject=<subject>`
⇒ 进入局部子图。**这就是「全图」的替代品**：先看骨架，再下钻到块。

### 6.4 离线样例模式（与发布包兼容，必须保住）

发布包（`bash sttp.sh sample`）用**单文件样例**（`sample_graph.json` / `sample_normalized.json`）离线跑通。
该场景下 `graph_data.json` 很小（样例 < 1 MB），**可以**继续整图加载。
⇒ 设计上提供**两种模式**，由响应/配置决定：

- `mode=live`（默认）：查询面板 + 子图 API；
- `mode=bundle`：单文件整图（仅样例/小图，页面角标**标注「样例全量」**）。

★ 这保证 **Phase 43 改造不破坏已验证的发布样例链路**（`verify_release.py` 的 **28 条**断言、
`--full` 31 条、样例子集 78 条，均须保持绿）。

### 6.5 「可带走」需求（替代 Remotion，零新依赖）★ 新增

用户「把这一小块图带走」的真实诉求由**三件零依赖能力**满足（评审书 §5.3）：

1. **导出 PNG / SVG**（Cytoscape 原生 `cy.png()` / `cy.svg()`）—— 当前子图 + 图例 + `snapshot_id` 水印；
2. **复制 LaTeX**（MathJax 已具备）—— 公式可粘贴到文档；
3. **导出 JSON 快照** —— 子图 + 边证据 + `snapshot_id` + `query_hash`，可**离线复现同一次查询**。

★ **不做** Remotion 视频链路（许可 + 构建链 + 定位三重冲突，评审书 §5）；将来若要，须先满足
评审书 §5.2 的四条前提并**另起裁决**。
