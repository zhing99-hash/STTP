## 8. 本轮学费

**D130 · 迁移不能只看「体积对得上」。**
本项目存在一个**被 `.gitignore` 排除的大件层**（`公共数据集/` 2.9 G、`.runlog/`、`dataset/slices/`）。若用 `git clone` 迁移，这条通道会静默丢掉它们 —— 而 `du` 对比体积时才发现对不上，届时数据已经在另一台机器上找不回来了。
教训：**凡 git 之外还有被忽略的大件，迁移只能用文件系统搬运，并逐项列 checksum。**

**D131 · Windows 树根 rename 失败 ≠ 有东西被锁。**
`mv` 报 Permission denied 时，先别急着怪权限。这次 ACL 正常、无进程占用、非 cwd —— 但 55 个顶层条目**每一个都能单独移动**。绕过办法是「逐个移出 → 删空壳 → 再改名」。
教训：**整树 rename 对句柄的约束比单条目严**，报错含义与实际原因常常不是一回事，要靠二分移动来验证而不是靠猜。

**D132 · 「重跑 ETL」是个误导性说法。**
本轮差点照这个词去执行。`03_知识层/etl_pipeline.py` 的 `--source` 只有四个适配器（mathxiv / mathgraph / physicsbabel / elementkg），它重建的是**基础图**；而当前权威图里 35 个 source 中大部分是后续 `apply_delta` 逐层 enrich 上去的（Phase13 元素修复 / 60 分级 / 61 符号 / 62 domain / 63 适用性 / 68 文献提及 / 69 化学 / 71 元素）。
**盲跑 `etl_pipeline.py` 会把 9,750 节点 48,813 边的图炸成一个远小的子集。**
正确说法是「最小 diff 回灌」—— `sync_seed_delta.py` 的注释早就写明了：*「改完源头若不做差量回灌，权威图仍是旧的 —— 两边静默漂移」*。而 phase79 的 S95/S96 报红，正是这条漂移的检测器在工作。
推论：**凡本项目说「重跑某个管线」，先问清楚它写的是全量还是差量。**

**D133 · 回灌前先分辨「缺失」与「被清理」。**
`sync_seed_delta.py` 首次扫出 339 变更 + **95 新节点 + 401 新边**。后两者看着像「当年漏了」，差点一并回灌。逐条查证后发现它们恰恰相反 —— 是**历史上被主动移除的**：
- `EK2:el:S`：`apply_element_fix.py` 记载 Oxygen 的 HASATOMIC=16 实为族号，反查得 S 与 Sulfur 撞 id ⇒ 该节点属**错误解析产物**
- 42 个 `EK2:rxn`：`push_pending.py` 第 56 行记载的**孤儿反应节点**

若图省事直接 apply，等于把当年的清理结果撤销 —— 一次「看着像补全」的倒退。最终只取 339 条 props 变更，规模 **(+0/+0)**。
教训：**diff 里每一类变化都要能说清它为什么存在；说不清的不许进图。**
