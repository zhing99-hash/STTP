## 0 结论先行

**要打分。但不能新造一套人工评分，也不能把 1—5 分当成一个能对外公布的「数据质量分」。**

三条实测结论：

1. **评分几乎无法靠人工打**：48,712 条边 + 5,090 条公式 + 181 篇论文，人工打分不可能覆盖，且
   一旦人工介入就不可复算、不可回归、会随时间漂移 —— 与铁律 #87 直接冲突。
2. **评分必须派生自已有的三套字段**（`verification_level` / `evidence.kind` / `fidelity`），
   只新增一个**规则版本号**，不新增一份「打分表」。
3. **瓶颈不在断言质量，在来源可复算性**：96.6% 的边得 2 分，其中 31,138 条是「规则机检通过」
   —— 它们**可信**，只是**不可复算**。所以评分的第一用途是**排抓取队列**，
   第二用途才是对外披露，且对外必须换口径。

> ⚠️ **「暂不对外」的直接后果**：外部分发时那 12 个 `*_raw.json` 不在包里 ⇒ 96.6% 的边
> 对外**永久封顶 2 分**。这不是数据变差，是分发范围决定的。见 §5 双口径。

## 1 为什么不能新造一套（已有字段盘点）

| 字段 | 语义 | 取值 | 覆盖 |
|---|---|---|---:|
| `verification_level` | **这条断言是怎么被验证的** | `rule_checked` 31,520 / `source_asserted` 13,797 / `cross_source` 3,249 / `model_inferred` 135 / `by_construction` 11 | 100% |
| `evidence[].kind` | 单条证据的**取证方式** | `recompute` 31,970 / `source_assertion` 11,143 / `cross_source` 3,285 / `equation_species_consistency` 3,002 / `model_prediction` 136 / `carryover` 20 / `construction` 16 | 100% |
| `fidelity`（派生） | 证据字节能否**从仓库复算** | `verified` 1,536 / `unverifiable_not_in_repo` 47,055 / `unverifiable_no_source` 121 / `changed` 0 | 100% |
| `confidence` | 历史遗留数值（0.7—1.0） | 36,859 条是 0.95 | 99.6% |

**判据**：前两者回答「断言可信度」，第三者回答「证据可复算性」，**正交且都已存在**。

`confidence` 不作为评分输入 —— 它 76% 挤在 0.95，区分度不足，且与 `verification_level`
语义重叠；保留但不参与打分（在披露中标注「不参与」）。

## 2 E 级：关系/断言（1—5 分）

### 2.1 规则

三个维度，**取最小值**（fail-closed），独立性达标可 +1：

| 维度 | 输入 | 映射 |
|---|---|---|
| **V** 断言强度 | `verification_level` | `cross_source`→5 ｜ `rule_checked`→4 ｜ `by_construction`→4 ｜ `source_asserted`→3 ｜ `model_inferred`→1 ｜ 缺失→1 |
| **F** 可复算性 | `fidelity` | `verified`→5 ｜ `unverifiable_not_in_repo`→2 ｜ `unverifiable_no_source`→1 ｜ `changed`→1 |
| **I** 独立性 | `evidence` 中不同 `src` 数 ≥2 或 `indep` 数 ≥2 | 满足且 `min(V,F)≥3` ⇒ +1（封顶 5） |

```
grade = min(V, F)
if grade >= 3 and (distinct_srcs >= 2 or independent_evidences >= 2):
    grade = min(5, grade + 1)
```

**两处策略选择需公开（不是唯一解）：**
- `rule_checked` 记 4 而 `cross_source` 记 5：多源独立 > 单源机检。若认为「机检比同行断言硬」，
  两者可互换，但**必须同时改规则版本号**（`grade_rule_version`），不得静默调整。
- `changed` 记 1 而非 2：来源字节已变、断言未重验 ⇒ 按 fail-closed 处理，宁可低估。

### 2.2 实测分布（48,712 条边）

| 分数 | 条数 | 占比 | 含义 |
|---:|---:|---:|---|
| **5** | 702 | 1.4% | 多源独立 + 可复算 |
| **4** | 351 | 0.7% | 单源但可复算（机检/构造） |
| **3** | 482 | 1.0% | 来源断言可定位、可复算 |
| **2** | **47,032** | **96.6%** | 断言有档，但来源文件不在库 |
| **1** | 145 | 0.3% | 模型推断 / 无源 / 字节已变 |

### 2.3 交叉表（这张表是全部结论的来源）

| `verification_level` | → 5 分 | → 4 分 | → 3 分 | → 2 分 | → 1 分 |
|---|---:|---:|---:|---:|---:|
| `rule_checked` | 26 | 351 | 0 | **31,138** | 5 |
| `source_asserted` | 0 | 0 | 482 | **13,315** | 0 |
| `cross_source` | 676 | 0 | 0 | **2,573** | 0 |
| `model_inferred` | 0 | 0 | 0 | 0 | 135 |
| `by_construction` | 0 | 0 | 0 | 6 | 5 |

**三条解读：**

1. **`cross_source` 有 79%（2,573/3,249）掉到 2 分** —— 最强的证据类型反而大多不可复算，
   因为交叉验证要求两个来源文件同时在库。**这是评分体系最反直觉的一处，必须对外说明。**
2. 31,138 条 `rule_checked` 拿 2 分，**不代表规则机检不可信**，只代表机检所用的输入文件没入库。
3. 1 分只有 145 条 —— **模型推断在图上极少（0.28%）**，图不是 LLM 生成的，这点应作为对外卖点。

## 3 P 级：科研论文（1—5 分）

论文的「可确认」标准与关系不同：**能不能核到正文里怎么用这个公式**，而不是「有没有 DOI」。

### 3.1 实测底座（181 篇）

| 字段 | 覆盖 |
|---|---:|
| `openalex_id` / `title` / `year` / `cited_by` | 181（100%） |
| `doi` | **163（90.1%）** |
| `venue` / `authors` | 176 / 179 |
| `cited_by` 中位 | **600**（零引用 0 篇） |
| `oa_status` | closed **115（63.5%）** ｜ bronze 48 ｜ green 12 ｜ hybrid 3 ｜ diamond 2 ｜ gold 1 |

### 3.2 规则

| 分 | 判据（同时成立才给） |
|---:|---|
| **5** | OA 可读全文 **且** 与公式的 `discusses` 边带段落级定位（页码/节号/公式号） |
| **4** | OA 可读（全文或摘要），但无段落级定位 |
| **3** | DOI 可解析、但 closed（只能核到书目层）—— **63.5% 的天花板** |
| **2** | 仅 OpenAlex 元数据（无 DOI） |
| **1** | 仅标题、无任何外部标识符 |

### 3.3 两条硬结论

1. **论文侧「书目层合格、正文层薄弱」**：90.1% 有 DOI，但 63.5% closed ⇒ 最多 66 篇能到 4—5 分。
   想提高，唯一办法是**补 OA 版本**（预印本/机构库），不是补 DOI。
2. **物理侧完全空白（这是最严重的缺口）**：`discusses` 178 条**全部**指向 `MathConcept`
   （`NT:mc:*` 74 + `MA:mc:*` 104），**5,050 个物理公式被论文 discuss 的数量 = 0**。
   现有 181 篇来自 `openalex_math_raw`（数学主题），物理公式一条论文支撑都没有。
   ⇒ 「科研论文的使用数据」不是「补分数」，是**从零建一条线**。

## 4 U 级：公式使用案例（新数据线）

现状：**0 条**。图里 24 种边没有 `used_in` / `applied_to` / `example_of`；只有 81 条节点属性
`usage`（1.59%，来自 `curated_seed` 人工撰写），质量可用作**基准样例**：

> `FO:emc2` → 「核反应与湮灭过程的能量核算；质量与能量的互换换算。」
> `FO:fma` → 「由受力求加速度（动力学计算）；建立运动微分方程。」

### 4.1 规则（按你给的口径落地）

| 分 | 判据 | 典型来源 |
|---:|---|---|
| **5** | 原文可定位 + 可复核（教材页码、标准号条款、手册表号） | 教材、国标/ISO、CRC 手册 |
| **4** | 论文正文中的应用 + DOI 可解析 | 期刊论文、会议论文 |
| **3** | 专业数据库条目（有条目 ID，可回溯） | NIST、ChEBI、PubChem 的用途字段 |
| **2** | 网页有出处但不可长期核验（URL 可能失效） | 百科、大学课程页、技术博客 |
| **1** | 无出处 / 抓下来无法证明（含 LLM 生成未核） | 搜索结果、问答站、无引用页面 |

**这正是「直接从网上获取无法证明的打 1 分，可以确认的打 5 分」的机器可判版本** ——
区别在于每一档都绑定了**可检查的字段**（页码？DOI？条目 ID？），不是靠人感觉。

### 4.2 关键约束：出生即打分（born-graded）

U 级**不允许事后补**。抓取脚本在写入每条 `used_in` 边时就必须带上：
`grade`、`locator`（页码/条款号）、`src`、`fetched_at`。
缺 `locator` 的**一律 1 分**，不进入图（或进入但显式标 `unverifiable`）。

理由：事后补要重新访问来源，而来源会失效——这正是现在 96.6% 不可复算的成因。

## 5 双口径：内部 与 对外（「暂不对外」的直接后果）

同一个公式，在本机和在别人机器上**分数必然不同**，因为 `fidelity` 取决于来源文件在不在。

| | **内部口径** `grade_internal` | **对外口径** `grade_public` |
|---|---|---|
| 输入 F 维 | 本机全量（含 `*_raw.json`） | 仅仓库内可见证据 |
| 5 分 | 702 | 0 |
| 2 分 | 47,032 | 47,053 |
| 用途 | **抓取优先级 / 内部质量看板** | 对外披露（若将来对外） |

**硬规则：**
1. 两个数字**永不合并、永不平均**，字段名必须带后缀（铁律 #90）。
2. 前端默认显示 `grade_internal` 并标注「本机可复算」；对外导出只带 `grade_public`。
3. 任何对外材料**不得**只说「1.4% 达到 5 分」——必须同时给出
   「其中 96.6% 因来源未随仓库分发而封顶 2 分」这一句，否则等同于宣称数据质量差。
