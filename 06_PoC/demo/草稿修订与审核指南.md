## 操作

在项目根目录的 PowerShell 中：

```powershell
$sttpPython = '.\review_20261028_full\python311\python.exe'
# 从候选创建全空的内容草稿；已有同名文件不会覆盖
& $sttpPython '.\06_PoC\demo\drafts.py' new --candidate 'pilot-with-relations-20261029.json' --name 'new-draft.json'
# 可选：以当前 Demo 的对应内容预填，依然需要真实审核
& $sttpPython '.\06_PoC\demo\drafts.py' new --candidate 'pilot-with-relations-20261029.json' --name 'draft-with-demo-text.json' --seed-demo
# 复制为新修订；新文件保留父版本哈希，全部审核记录清空
& $sttpPython '.\06_PoC\demo\drafts.py' revise 'pilot-editable-20261029.json' --output 'pilot-revision-2.json'
# 查看缺项及当前每项内容指纹；待审时返回非零状态
& $sttpPython '.\06_PoC\demo\drafts.py' check 'pilot-editable-20261029.json'
```

使用文本编辑器修改新版本中对应记录的 `proposal`：节点填写名称、学科、解释、公式（如适用）、条件和来源；关系填写学科、关系名称、说明、条件和参考来源。来源地址须为 HTTPS。不要修改 `snapshot` 原始摘录、原始哈希或关系端点。如果希望改变关系方向或新增关系，需要另外设计来源和审核流程，本工具不支持直接改写原图关系。

保留旧文件，再通过 `revise` 创建新文件，可形成可比较的版本链。链条依赖使用者保留文件；本地文件不是不可篡改日志或身份认证系统。直接编辑已有文件不会自动留下历史记录，故建议先复制修订再修改。

## 如何记录真实审核

`check` 输出的 `content_sha256` 对每个节点或关系单独计算。它绑定原图哈希、原始记录及摘录、当前 `proposal`；关系指纹还绑定两个端点的当前草稿内容。独立专家或许可审核人员完成真实审核后，使用本次输出的对应指纹填写该记录的 `review.scientific` 或 `review.license`：

```json
{
  "decision": "approved",
  "reviewer": "实际审核者及可核实身份",
  "date": "实际审核日期，格式 YYYY-MM-DD",
  "evidence": "具体来源或授权材料，以及章节、页码或记录位置",
  "scope": "审核的具体内容和可使用范围",
  "content_sha256": "check 输出中对应记录的内容指纹"
}
```

以上只是字段模板，不代表已获得审核。修改节点草稿之后，该节点及连接它的关系所绑定的旧审核指纹会失效；修改关系草稿后，该关系的旧审核指纹会失效。应重新取得真实审核，不能只替换哈希来伪造审核。

程序可以检查必填字段、日期格式、原图和内容哈希，但不能验证审核人身份、独立性、参考证据的真实性或内容许可是否有效。真实来源应回到国际单位定义、原始论文、实验与上游权利声明；专家应检查量纲、变量含义、适用条件、方向和反例。学习效果则需要独立用户完成任务并记录结果。
