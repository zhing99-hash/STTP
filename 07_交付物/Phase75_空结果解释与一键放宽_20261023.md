## 一、问题：空图没有任何解释，而"放宽"是个空按钮

外部评审 RC1-10 的原话：**「单节点/0 边说明原因 + 一键『含全部可信档重试』｜仍只报
`hidden_by_trust` 数字；无入口」**。落到代码上是三处：

| # | 现状 | 后果 |
|---|---|---|
| 1 | `ego` 查询返回 1 节点 0 边时，五态是 **`ok`**，而 `renderBanner` 对 `ok` **直接 `return`** | 用户看到一张空画布，**一个字都没有**说明发生了什么 |
| 2 | `no_result` 横幅只有一句「放宽建议：去掉部分语义关系 / 换学科 / 提高跳数 / 降低置信度门槛 / 检查拼写」 | 五条并列建议 = 没有建议。**没有一条告诉用户"刚才是哪一条把它挡住的"** |
| 3 | 「放宽条件并重试」的实现是 `state.panel.clear()` | 把用户所有条件一并丢掉；下一轮还是不知道谁挡的；而且清空**不保证**有结果 |

第 3 条是 D64 的同族：**指引指向一个代码能执行、但没有信息含量的动作**。按钮在、点得动、
结果照旧空 —— 用户只会得出"这个系统搜不到东西"的结论。

## 二、判断：空结果需要的不是更多文案，是**可复算的原因 + 单一的下一步 + 明确的边界**

三件事必须同时成立，缺一件就退化成假动作：

1. **原因可复算**：不能靠猜"大概是学科太窄"。做法是**单条件反事实计数** ——
   `counts[k]` ＝ **只**取消第 k 个条件（其余一律不动）后能通过的候选边数。
   它是对同一份索引**重算**出来的数，不是估计。
2. **下一步唯一**：从 `counts` 里取**计数最大且为正**的那一项，只放宽它。
3. **边界可证**：`degree` ＝ **不加任何条件**时的候选数。`degree == 0` ⇒ 放宽**必然无效**
   ⇒ 此时**不给动作**。没有这一条，"一键放宽"就变成"永远能搜到东西"的自欺（铁律 #30）。

## 三、处置（后端 · `03_知识层/queries.py`）

新增 `Backend._empty_diagnosis(...)`，只在**结果为空且没被预算截断**时调用（`truncated_by` /
`scan_timed_out` 时「0 条」的含义是"还没找到"，给放宽建议就是把"没算完"说成"没有"）。

| 分支 | 触发条件 | 输出的动作 | 为什么必须单列 |
|---|---|---|---|
| `isolated` | `degree == 0` | **无**（`action: null`） | 该条目在整图没有边，任何放宽都无效 |
| `hops_zero` | `hops == 0` | `hops → 1` | 跳数 0 时邻边一条都不会展开；此时说"放宽可信档能多看到 12 条"是**照做也无效**的建议 |
| `filtered` | 某一项单放宽后 > 0 | 该项 | 正常情形：原因唯一、动作唯一 |
| `combined` | 单放宽任一项都 0，累积才行 | 累积路径的**第一步** | 两个以上条件同时挡着，必须一步步来（每步重新诊断） |
| `undecided` | 诊断自身超预算（`budget_ms`） | **无** | 宁可不说，也不把"没算完"写成"没有"（D110b） |
| `unreachable` | 候选非空、条件全放开仍 0 | **无** | 说明诊断口径与候选集合不同源 —— 这是缺陷，登记，不给无效建议 |
| `missing_seed` | 种子/端点不存在 | **无** | 放宽救不了一个不存在的名字 |
| `no_path`（path） | 没有路径 | `trust` 或 `hops` | **不做**反事实计数（见下） |

**路径模式为什么不做反事实**：连通性不是单条件可分的 —— 去掉一个条件**不一定**让 a、b 连上。
给一个假的精确数字比不给更糟，故 path 分支显式发 `counterfactual: false`，只给两个
**真实可执行**的步骤（放开可信档 / 加 1 跳），并说明"不承诺放宽后一定有结果"。

**中文只允许有一份**：`counts` 输出为 `[{key, what, n}]`，`what`（「可信档」「关系类型」…）
与 `action.label`（「含全部可信档重试」）**都由后端给**，前端只排版。
另设 `EMPTY_RELAX_WHAT`（谁挡的）与 `EMPTY_RELAX_LABEL`（怎么改）两张表 —— 句子里要写
"被『可信档』挡住"，不是"被『含全部可信档重试』挡住"：**动作名 ≠ 条件名，混用就是把动作当原因**。

实测（`normalized.json`，9,750 节点 / 48,813 边，现算）：

| 场景 | `scanned` / `degree` | `counts` | 结论 |
|---|---|---|---|
| `WD:Q3552958`（邻边全在 verified 以下）, trust=verified | 1 / 1 | `trust: 1` | `filtered` → 「含全部可信档重试」，承诺 1 条 |
| `mode=filter`, `kinds=不存在的类型` | 48,813 / 48,813 | `kinds: 34,883`、`trust: 0` | `filtered` → 「清空关系类型」，承诺 34,883 条 |

第二行值得看一眼：**`trust: 0`** —— 放开可信档一条都救不回来（真正的堵点是 kinds）。
旧的并列式建议里恰好就有"降低置信度门槛"，用户照做会**一无所获**。

## 四、处置（前端）

### 4.1 新模块 `06_PoC/js/empty.js`（纯逻辑，可被 node 直接断言）

| 函数 | 职责 | 纪律 |
|---|---|---|
| `emptyDiagOf(env)` | 取 `stats.empty_diagnosis` 并校验形状 | 缺 `why`/`scope` ⇒ `null`；**宁可不说，也不编原因** |
| `emptyDiagHTML(diag)` | 渲染标题 / 正文 / 判定依据 / 计数表 / 边界 / 按钮 | 不出现 `**`（横幅是 HTML）；`n=0` 的行标 `dead` 并写「无效」 |
| `boundaryText(diag)` | 没有按钮时**必须**说明为什么没有 | 渲染在界面上，不是只写在报告里 |
| `scopeText(diag)` | 「判定依据：扫描 N 条候选边」 | **0 条 ≠ 没扫过**，扫描范围必须露出来 |

### 4.2 `panels.renderBanner`：`ok` + 0 边**也要渲染**

```js
const diag = emptyDiagOf(env);
if (!env || (env.status === "ok" && !diag)) { el.innerHTML = ""; el.hidden = true; return; }
```
`ok` + 诊断时用中性类 `st-empty`（既不能染成绿色"正常"，也不能冒充 `no_result` ——
五态是**状态行**在管，横幅管的是解释）。同时 `data-state="empty"` 供 DOM 断言。

### 4.3 `panels.applyPatch(patch)`：改**控件**，不改请求

面板是参数的单一真相源（`collect()` 既是执行入口也是唯一构造点）。绕过面板改请求，
界面显示的条件与实际生效的条件就会分叉 —— 用户下次手点「执行」时又回到旧条件（"点了没反应"）。
`applyPatch` 返回**实际发生变化的键**；空数组 ⇒ 调用方**不得**重发请求。

### 4.4 `main.relaxByDiagnosis(btn)`：四条纪律

1. 只改诊断点名的**那一个**键（整块清空 = 把用户的其他选择一起丢掉）；
2. 改面板控件（4.3）；
3. 面板若什么都没变 ⇒ **不重发**（重发一次注定同样空的查询 = 假动作）；
4. 按钮必须与**当前**诊断对得上（`data-relax-key` vs `diag.action.key`）——
   横幅可能已刷新，拿旧按钮去改新维度就是"点了却改错东西"。

### 5.1 门禁红旗：判据把自己举报成违规（本轮发现并修掉）

`gatecheck` 第一遍是 **RC=1**，红在 `[4/8]` 仓库卫生自检，4 项：

| 红旗 | 判据报的原文 |
|---|---|
| `H1:06_PoC/_gate_selfcheck_phase31.py` | 被活引用 |
| `H1:06_PoC/_recon_domain.py` | 被活引用 |
| `H3:06_PoC/_gate_selfcheck_phase31.py` | 引用了不存在的文件 |
| `H3:11_真实数据/wikidata_adapter.py` | 引用了不存在的文件 |

四处**全部出自判据文件自己**（`06_PoC/tests/repo_hygiene_selfcheck.py`）。根因不是引用，是**输入**：
这个文件必须逐字写下「哪些名字不该被引用」（`MENTION_ONLY`）、「哪个名字是故意不存在的」
（`PLACEHOLDER`）、以及负对照夹具（`{"06_PoC/_recon_domain.py": ["__injected__"]}`）——
按 AST 取字符串常量时，这些和真引用长得**一模一样**，于是判据把自己判成了违规。

为什么 Phase 74 当时是绿的：那时 `PLACEHOLDER` / `MENTION_ONLY` 的豁免都挂在 `.md` 载体上，
而本轮 H1/H3 的载体（`code_files()` / `live_files()`）把判据文件本身也纳进来了。
一句话：**判据长大了，先把自己咬了。**

修法：`scan_refs()` 跳过 `SELF`。但**不能只跳过** —— 静默排除就是又一个看不见的豁免
（下次谁改了豁免表都无从核对，正是 D110b 的家族）。故补自检 **S6a/S6b/S6c**：

- **S6a 排除非空转**：判据文件里确实有 5 条路径字面量（没有 ⇒ 这条排除无从验证，等于空白通行证）
- **S6b 扫描器不瞎**：把同一字面量写进**另一个**临时文件，`_refs_in_py()` 必须抓到
  （取不到 ⇒ 排除会顺带把真引用一起放过）
- **S6c 排除只对 `SELF` 生效**：单扫 `SELF` 得 **0** 条，带上夹具得 **1** 条
  （带夹具仍取不到 ⇒ 排除范围写大了，把别人的引用一起吞了）

修后实测：H1/H2/H3 **RC=0**，**95** 条路径引用全部存在；自检 **S0–S6 全过**（负对照 3 → 5）；
`gatecheck` 八步 **RC=0**。

## 六、判据与探针

**V21（后端，合成图 4 节点 3 边）**——用合成图而不是真图，是因为真图当前**没有**度为 0 的节点
（现算 0 个），最关键的那条分支在真图上**根本走不到**；判据看不见的分支等于没判据。

- V21a 孤立 ⇒ `why=isolated` 且 **`action` 必须为 None**
- V21a′ 反例：有边的种子 ⇒ 不产生诊断（证明 `isolated` 不是恒真）
- V21b / V21b′ 两个条件同时生效时只选**有效**的那一项，且动作必须是**计数为正**的那一项
- V21c 换可信档后计数跟着变（1 → 2）⇒ 是**真复算**，不是常量
- **V21d 承诺 == 交付**：按建议放宽后重跑，实得边数 == 承诺的 `gain`
- V21e `hops=0` 单列；V21f 种子不存在 ⇒ 无动作；V21g filter 模式指向 true 根因（学科）
- V21h 自报扫描范围；V21i path 模式 `counterfactual=false`；V21j 非空结果**不带**诊断

**F45a–F45o（前端 node）**：半份诊断 ⇒ `null`；`to: null` 必须保留（"清空某条件"是合法目标值，
用 `hasOwnProperty` 判存在）；`counts` 非法项剔除；`isolated` 不渲染按钮；`missing_seed`
必须写明"没有按钮"的理由；`counterfactual=false` 不渲染"扫描 N 条"；`ok`+诊断必须显示；
`st-empty` 类名；无诊断时不含 `data-act="relax"`；HTML 不含 `**`；`empty.esc` 与 `panels.esc`
逐字一致（两份实现由测试钉住，而不是靠 import 耦合）。

**R45（探针）**：把 `isolated` 分支改成"也给一个含全部可信档重试" ⇒ **V21a 必须变红**。
实测 `RC=1；目标断言均已变红：V21a`。这条探针存在的理由：那种改动**没有任何报错**——
按钮在、点击有反应、结果照旧空，只有判据能看见它。

**F26c 规格变更（如实登记）**：旧断言要求无诊断时出现「放宽」二字；本轮规格改了
（不再给泛泛的建议），新断言更强 —— 必须**明说「不猜原因」**且**不得**再出现 `data-act="relax"`。
改断言的理由是**产品契约变了**，不是"为了变绿"：旧文案正是评审要拿掉的那句。

## 七、学费

- **D113　"放宽/重试"类动作必须能停下，否则它就是装饰品。**
  能一直放宽到"总有结果"的按钮，等于把"图里没有"这个结论永久掩盖。判据形式：
  **终点处必须没有动作**（`degree == 0` ⇒ `action: null`），且这条要被探针咬住。
- **D114　同一句话里出现两份中文名，就是两处真相。**
  条件名（可信档）与动作名（含全部可信档重试）在句子里**不能互换**；前端若再抄一份映射表，
  迟早一边改了一边没改。做法：中文只在后端一份，前端只排版。
- **D115　诊断必须自报扫描范围，否则「0 条」与「没扫过」同形。**
  `scanned` / `scan_complete` / `degree` 三个字段不是可选装饰：缺了它们，
  一个超时截断的空结果看起来和"确实没有"一模一样（D110b 的同族）。
- **D116　判据文件里的路径字面量是「输入」，不是「引用」；但排除必须被证明，否则就是新的黑箱。**
  一个文件若必须写下「哪些名字违规」才能判违规，它就必然被朴素的引用扫描判成违规 —— 排除它是对的。
  但**只加一句 `if f == SELF: continue` 是错的**：那条排除本身没有任何判据，于是「判据文件被排除」
  成了整份自检里唯一没人核对的一行。要求的形态是 **排除 + 三条自检**（非空转 / 扫描器不瞎 /
  排除范围不越界）—— 与 D110b「0 条与没扫过同形」是同一条病：**你看不见的豁免，等于没有豁免**。
- **流程**：本轮三次被**中文字符串里的直引号**咬（`"没有目标"` 直接截断 JS 字符串）。
  凡在代码里写中文引号，一律用「」——这条已经在 Phase 74 咬过一次，这次又咬了三次。

## 八、剩余边界（如实登记，不在本轮）

1. 反事实只在**种子 1 跳邻边**上算（`ego`）/ 全图边集（`filter`）。多跳情形下"放宽后能否连通"
   仍然只由"放宽后实际重跑"回答，诊断不承诺。
2. `filter` 模式的诊断是全图单遍扫描（8 个条件同时累计），预算 2 s；超预算 ⇒ `undecided`
   **不给建议**。当前实测 48,813 条边 × 8 条件 ≈ 0.15 s，余量充足，但边数再涨一个量级时要重新量。
3. **路径模式不提供反事实数字**（只有两个可执行步骤），理由见 §三。
4. 连续放宽的**轨迹没有留存**（"放宽了 3 次仍空"只有最后一条诊断可见）。要留存得引入
   前端会话级 trail，属于体验优化，不在本轮。
5. `js/empty.js` 的 `esc` 与 `panels.js` 的 `esc` 是**两份实现**（避免循环 import），
   由 F45m 逐字比对守住；若将来其中一份被改成"更严格"的转义（如加 `/`），F45m 会红。
6. 仓库卫生判据**整份跳过** `SELF`。若将来有人把**真的运行仓库内脚本**的代码（`subprocess` +
   一次性脚本路径）写进 `repo_hygiene_selfcheck.py`，H1 看不见它。当前该文件只读文件、不执行脚本，
   这条盲区由「判据文件不执行仓库内脚本」的约定兜住；要咬住它得把排除从「整份跳过」改成
   「只扣除表内的 path」—— 那需要一份「哪些字面量属于判据输入」的显式清单，与 `S6a` 的计数对账。
