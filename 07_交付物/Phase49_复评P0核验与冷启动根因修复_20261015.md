## §2 根因链

### 2.1 P0-2 的完整链条

```
前端用 /api/stats 做探活（判据：HTTP 200 + status=ok），预算 2 s
        │
        ▼
/api/stats 首次调用需要：fidelity_counts_global() 4.27 s + estatus 0.57 s + 逐边迭代 0.31 s
        │        （**与图是否已加载无关** —— 图冷加载是另外 2.3 s，发生在 listen 之前）
        ▼
4.9 s > 2 s ⇒ 浏览器 abort ⇒ normalizeStatus 判 error ⇒ detectMode 判「后端不可用」
        │
        ▼
退 bundle ⇒ GET /graph_data.json（48.7 MB 全图）⇒ 解析 + 渲染 9657/48712 ⇒ 页面卡死
```

**三处修复缺一不可**：
1. **探活换端点**：`/api/healthz` 不碰图谱数据（实测 16 ms）；
2. **预热含 stats 冷算**：否则 `ready` 只代表"图装好了"，第一次看统计仍要 4.8 s；
3. **`ready` 语义收紧**（F4）：`ready` ⇔ 预热整体完成，由计数量化（`cache_builds`）。

### 2.2 F1 的链条

```
main() 顺序：print 横幅 → get_backend()（同步 2.5 s）→ ThreadingHTTPServer(...) → serve_forever()
                                    ↑ 副作用：① 端口要 2.8 s 才 listen；② _WARM 永不启动
                                                                        ⇒ warm_state() 永远 warming
                                                                        ⇒ 三态成为死代码
改为：... → ThreadingHTTPServer(...) → kick_warmup() → serve_forever()
```

### 2.3 P0-4 的链条

```
/api/subgraph 的 path 模式实现只认 seeds（契约：`mode=path` 需 2 个 seed）
前端 runPath() 沿用 legacy /api/path 的 `src`/`dst` 命名
        ⇒ 后端收不到种子 ⇒ no_result
        ⇒ 前端把 no_result 渲染成「没有路径」
⇒ 用户看到的是"这两个东西之间没有关系"，而不是"参数没传对"（**错误的方向被彻底带偏**）
```

★ 这正是 §1.3 那一族的**共同危险**：静默丢失参数不仅丢数据，还会**产出看起来合理的错误结论**。

## §3 覆盖缺口：为什么既有断言全绿

| 缺陷 | 既有断言为何没抓到 |
|---|---|
| P0-2（探活误判） | `H6a2` 只断言 `/api/stats` **带 `status`**（形状）；`F11` 断言"同输入两次序列化相同"（形状）。**没有任何断言测"探活判据在冷态下是否成立"** —— 冷态从未被构造（#82 仪器自指：测量环境不含被测条件） |
| P0-4（路径参数错位） | 后端自检用 `seeds=` 直连后端（**绕过了前端**）；前端自检用假 `fetchImpl`（**没连后端**）。两侧各自绿，**中间那条缝没人测** ⇒ 本轮新增 **H8m**（用 `src/dst` 打真后端必须 `no_result`）+ **X16d**（契约层） |
| `hops`/`subject`/`exclude_inferred` | 契约只描述**响应**；`buildParams` 的键集合**没有**与任何"权威清单"求差。前端"少发一个键"在类型上完全合法 |
| F3（重复冷算） | 既有断言全部是**单请求、串行**；并发从未被构造 |
| F4（就绪语义） | `H8` 第一版只断言"最后会 ready"；**没有**断言"ready 意味着什么" |

★ 一句话：**既有断言都在查"形状对不对"，没有一条在查"这个判据在这个条件下是否成立"**（#83 家族）。

## §4 修复

### 4.1 D31：端点契约 + **双向求差**（本轮的结构性修复）

新增 `contracts/endpoints.schema.json` —— 「前端参数序列化」与「后端参数读取」之间的**唯一对照表**：

```jsonc
"/api/subgraph": {
  "handler": "_api_subgraph",
  "params": { "mode": …, "seeds": …, "hops": …, "subjects": …, "exclude_model_inferred": … },
  "frontend_uses": [ … ],
  "frontend_must_not_send": ["q", "src", "dst", "subject"],   // ★ P0-4 的契约化
  "note": "★ `mode=path` 只认 `seeds`（需 2 个）。把 `src`/`dst` 发到本端点＝端点读不到（P0-4）"
},
"/api/path": { "legacy": true, "legacy_defaults": {"max_paths":20,"max_hops":5,"deadline_ms":3000} }
```
外加 `backend_params_not_emitted`：后端**读得到但前端有意不发**的每个参数都**必须写明理由**
（`query`＝避免自然语言歧义直接决定查询对象；`snapshot_id`＝待补；`node`/`k`＝legacy）。

**双向求差**（两侧都查，缺一不可）：

| 方向 | 断言 | 查什么 |
|---|---|---|
| 契约 ↔ **前端** | `F37a–F37g`（node） | 后端读的每个参数，前端要么能发、要么显式声明不发+理由；前端每个 `put()` 键都有端点读它（无死参数） |
| 契约 ↔ **后端源码** | `X16a–X16f`（python） | 契约 `params` ⊇ 后端**实读**集合；契约不得登记后端不读的"幽灵参数"；`must_not_send` 与后端行为一致 |

★ 为什么必须双向：**只查前端**会把"契约本身写错（登记了后端不读的参数）"放过去；
**只查后端**会把"前端改名"放过去。两侧都是本轮实测踩到过的坑。

### 4.2 P0-2：`/api/healthz` + 预热 + 先 bind

```python
# 1) 轻量探活：绝不触碰图谱数据
def _healthz(self):
    kick_warmup()                 # ★ 幂等、无条件（否则"图先被普通请求装好"时预热永不启动）

            "warm_ms": _WARM.get("ms"),

# 2) 预热覆盖"整条读路径"
def _warm_worker():
    b = get_backend(); _ = b.node_count

# 3) 先 bind 再预热（F1）
```

**`paths` 恒存在**（非 path 模式为 `[]`）：前端可无条件读 `env.paths`，少一处静默错位。

### 4.3 F3：单飞（single-flight）构建锁

```python
_STALE_BUILD_LOCK / _FIDELITY_BUILD_LOCK / _ESTATUS_BUILD_LOCK = threading.Lock(), …

with _FIDELITY_BUILD_LOCK:                     # 单飞
    with _STALE_LOCK:                          # 双检（等锁期间可能已被建好）
        if cache_valid(key): return cache
    _BUILD_STATS["fidelity"] += 1              # ★ 可观测：算了几次
    out = q.fidelity_counts(b.all_edges(), reg)
    with _STALE_LOCK: cache[key] = out
    return out
```
锁序恒为 `BUILD → CACHE`（无反向嵌套）⇒ 不成环（#79）。`_STALE_LOCK` 保持 **RLock**
（E11 的历史原因：`evidence_status_registry()` 自己要取同一把锁）。

## §9 结论

1. **复评的 5 个 P0 中，3 个在本环境成立**（P0-2 / P0-3 / P0-4），2 个不适用（P0-1 / P0-5）。
   P0-3 已在 P48 修好，本轮为它和它的三个"同族兄弟"建了**结构性防线**（D31 双向求差）。
2. **P0-2 的真实根因与初版表述不同**：不是"图没加载完"，而是 `/api/stats` 首次的 **4.27 s 冷算**。
   这一纠正直接改变了处方（必须预热 stats 冷算，只预热图无效）。
3. **另修三条自测发现的问题**（F1/F3/F4），它们的共性比单个 bug 更重要：
   **不报错、能跑通、断言全绿，只是"看起来对了"**。
4. **既有断言全绿的原因是同一个**：它们在查**形状**，没有一条在查**"这个判据在这个条件下是否成立"**。
   本轮把"冷态 / 并发 / 就绪语义 / 契约一致性"四类条件**构造**出来，并配**负对照**。
5. **未动的**：图谱数据、科学结论口径、北极星分母、可信性模型 —— 本轮改的是
   **可用性、契约与断言**。这一类"静默降级"是否还有别的入口，正是希望外部评审核对的问题。
