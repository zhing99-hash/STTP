## 3. 契约要点（实现与方案 v2 的关系）

- **五态**：`ok / no_result / truncated / timeout / error`；**业务态一律 HTTP 200**，只有**参数非法**才 `400 + BAD_REQUEST`。
- **`error_code` 与五态共存不并存**：五态管"结果类别"，`error_code` 管"原因"。实际用到的 8 个：`SNAPSHOT_MISMATCH / EVIDENCE_STALE / SUBGRAPH_LIMIT_REACHED / GRAPH_QUERY_TIMEOUT / TOOL_EXECUTION_ERROR / BAD_REQUEST`（`ENTITY_AMBIGUOUS`、`MISSING_CONDITION` 已在 schema 枚举中**预留**，本轮**无产生路径** ⇒ 见 §6-D11）。
- **预算**：单次默认 `max_nodes=500 / max_edges=2000 / max_hops=3 / deadline_ms=3000 / max_paths=20`；**硬上限** `{5000, 20000, 5, 30000, 200}`；**会话级累计 120 节点 / 200 边**（达到即 `SUBGRAPH_LIMIT_REACHED`，**不静默截断**）。
- **`expand_token`**：服务端 HMAC 签发（`base64url(payload).hexdigest(HMAC-SHA256)[:16]`），绑定 `snap + seed + hops + filt(query_hash)`；`mode=expand` **必须**携带；篡改/伪造 ⇒ **400**（V13b/V13c）。
- **`snapshot_id`** = 查询源文件 `sha256[:12]`（按 `(path, mtime_ns, size)` 缓存，避免每请求对 54.9 MB 现算）；请求带了不符的 `snapshot_id` ⇒ `SNAPSHOT_MISMATCH`。
- **`why_shown`**（枚举 `used_in_step / evidence_path / user_specified / task_anchor / verified_context / expansion`）**每个节点/边必带**，V15b 断言取值分布**非单一**。
- **可信两档**（铁律 #19）：`verified`(≥`by_construction`) / `verified_strict`(≥`rule_checked`) / `all`；`hidden_by_trust` **必须回显**，V14 断言三式恒等：`visible(v)+hidden(v) == visible(s)+hidden(s) == 48712`。
- **★ 三个易错事实（已实测，写进契约说明）**：
  1. 边 **`type`＝语义关系（24 种）** ≠ 边 **`kind`＝来源/管线标签（115 种）** —— 拿关系名当 `kind` 传参**必返回 0 条**（V11 双向证明：`types=has_quantity` 有 24 341 条边，`kinds=has_quantity` ⇒ 0）；
  2. 边上**没有** `status: valid|stale` 字段（`status` 只出现在 3 423 条、取值 `VERIFIED`/`NEEDS_REVIEW`，是 GNN 产物）⇒ stale 只能**现算**；
  3. `filter` 模式**必须**至少一个过滤条件；只给 `trust=all` ⇒ **400**（**刻意**：防止用 filter 把全图倒出来，全图请走 `/api/overview`）。

## 6. ★ 本轮发现的问题（**必须计入文档，供下次 codex/GPT6 评审考虑**）

### D1（最重 · 根因级 · **已加探针、未修根因**）证据哈希所依赖的字节在干净检出下不可复现

- **现象**：`stale` 判据（`evidence[].src_hash` vs `source_registry` 当前内容哈希）依赖"worktree 里的文件字节 == 仓库里的 blob 字节"。实测**不成立**：
  - **7 / 21** 个"已入库且有 `locator`"的来源文件，**worktree 字节 ≠ 仓库 blob**（CRLF vs LF）：
    `06_PoC/sample_mathxiv.json`、`10_种子数据/seed_{biochem,inorganic,math_calculus,math_numbertheory,organic_chem}.json`、`11_真实数据/seed_papers_openalex.json`；
  - 另有 **13 / 34** 个 `locator` **根本未入库**（被 `.gitignore` 的 `*_raw.json` / `*_cache.json` 挡掉）：`chebi_cache / chebi_synonym_cache / elementkg10m_raw / elementkg_raw / webbook_raw / webbook_cache / physicsbabel_raw / pubchem_mol_raw / pubchem_validate_raw / rhea_raw / chembl_raw / codata2022_raw / openalex_math_raw`。
- **影响**：证据里的 `src_hash` 在**干净检出**（clone）下**不可能复现** ⇒ `stale` 判据在干净检出里会**假阳**；而"可复现"是本项目对外最强的主张之一（铁律 #53/#61）。
- **本轮已做**：加 `viz_server.locator_byte_fidelity()` **探针**（`git -c core.quotepath=false ls-files -s -z` + `git hash-object --no-filters`），**随每次响应暴露**在 `stats.stale_registry`；自检 **V16f** 独立重算并断言与响应一致（`响应 7 / 独立 7`）。★ `-z` 与 `core.quotepath=false` **是必须的**：否则非 ASCII 路径被转义 ⇒ 整个中文目录被判"未入库"（本轮的踩坑）。
- **本轮未做（如实声明）**：**根因未修**。修法候选（择一，须单独一轮 + 负对照）：
  (a) **以仓库字节为唯一口径源**：`source_registry` 的内容哈希改由 `git show HEAD:<path>` 的字节计算，stale 判据也按仓库字节算 ⇒ worktree 行尾差异不再影响；
  (b) **从 HEAD blob 物化**后再跑 ETL/哈希（`rm` + `git checkout -f --` 或 `git cat-file blob`），并把 `.gitattributes` 行尾规则补全；
  (c) 把 13 个未入库 `locator` 显式标为 `unverifiable_from_repo`，并在 `stale` 语义里与"已变更"**分列**（现在是 fail-closed 一律视为 stale）。
- **当前的保护性默认**：`exclude_stale` **默认仍为 `false`** —— 因为此时打开它**会因假阳而误伤**；这是**有意的**，不是遗漏。

### D2 默认信任档 `verified` 会隐藏 28.6% 的边，对 hub 查询不友好

- `trust=verified` 全图口径下 **隐藏 13 932 / 48 712 = 28.6%** 的边（V14 实测；两档差 11 条 = `by_construction`）。
- 具体例子：`MX:def:manifold hops=1` ⇒ `trust=all` 有 9 条边，`trust=verified` **只剩 3 条**（隐藏 6）；`PQ:mass hops=1` 隐藏 18。
- **原因**：`has_symbol`（24 341 条，最大类）这类"来源管线未定级"的边在 `verified` 档被整体排除。
- **已做**：`hidden_by_trust` 必须回显且可加总回全量（V14a/b/c）。**未做**：前端默认档的取舍与提示文案（**属步骤 B**）。
- **建议**：前端默认给 `verified`，但**必须**在状态行显式显示「已隐藏 N 条（<原因>）」并提供一键切 `all`；若隐藏比例 > 50% 则弹出提示。

### D3 `pending_frontier` 只是**下界**，不是"实有未展开节点数"

- `stats.pending_frontier` = 中断时 BFS 队列长度；`ego`/`filter` 模式**无法**给出"这块图实有多少节点"（那需要全图扫描）。
- **已做**：字段旁附 `pending_frontier_note` 明确写"下界"。**要求前端**（步骤 B）**不得**把它渲染成"还有 N 个"。`truncated` 时对外只能说「已截断：显示 500 / 实有 ≥ 5 000（下界）」。

### D4 会话记账语义（已实现，须写进方案与前端）

- **无 `session_id` ⇒ 不记账、不判硬门**（`stats.session.tracked=false`）—— 匿名调用彼此独立。★ 这正是本轮基准脚本踩到的坑（所有匿名请求共享同一计数 ⇒ 第二次展开即被拒）。
- **有 `session_id`**：`mode=ego` **增量**累加；`mode=filter` / `mode=path` 视为**新视图** ⇒ 先**重置**再计数；`reset=1` 显式清空该会话（前端「重置」按钮）。
- **会话表有上限**（`STTP_SESSION_MAX`，默认 **256**，超出按**最久未写**淘汰）—— 无上限即内存无界增长。
- 自检 **V17a–V17e** 逐条断言（匿名不记账 / 计数递增 / `reset` 清零 / 表上限淘汰）。

### D5 `mode=filter&trust=all`（无其他条件）⇒ 400 —— **刻意**，但必须在文档里说清

- 该组合等于"把全图倒出来"，与铁律 #66 冲突 ⇒ 显式拒绝并给出可操作原因。**全图请走 `/api/overview`**（聚合元图 26 节点 / 62 边 / 11 KB）。
- 前端（步骤 B）**必须**把这条错误渲染成"请至少选一个筛选项"，而不是渲染成系统故障。

### D6 响应体积仍可达 ~2.4 MB（filter 500/2000），概览 `sample` 也可达 527 KB

- 默认预算下最坏 2 361 KB（`filter types=composed_of`）；硬上限下 10.3 MB。
- **未决**：是否把默认 `max_nodes` 下调（如 200）、是否给 `edges` 加分页/裁剪策略、前端是否需要虚拟化渲染。**建议**：前端默认只展示裁剪后的"骨架 + 展开"，**不**一次性把所有边推给渲染器。

### D7 `path` 模式在 hub 端点必超时（3 s 内取不出路径）

- `PQ:mass → MX:def:manifold`：hops≥3 ⇒ **`timeout`**（3.1–3.3 s）。当前 BFS 是**单向、无启发**的，分支因子大时前沿爆炸。
- **建议（另开一轮，须配负对照）**：双向 BFS / 按 `verification_level` 与度数剪枝 / 先给"最短路径 1 条"再要更多。
- **当前的正确行为**：返回 `timeout`（**不是**空、**不是**失败），前端须显示"超时（3 000 ms），建议缩小范围"。

### D8 字节忠实性探针本身的开销与口径

- `locator_byte_fidelity()` 每次响应都调 `git ls-files` + `git hash-object`（21 个文件），有缓存（键 = 依赖的 `(path, mtime_ns, size)`）。在高频请求下仍是额外开销；`stats.stale_registry` 让它**每次响应都可见**（可观测性优先于几个 ms）。**未决**：是否需要按需开关。

### D9 `/api/path` 保留 **legacy 扁平信封**（不合统一信封）

- 为不破坏旧页面，`/api/path` 返回 `{src,dst,count,paths,...}` 扁平结构（**无** `nodes/edges/hidden_by_trust/why_shown`），只增了 `snapshot_id/query_hash` 与五态字段。
- ⇒ **新前端代码一律走 `/api/subgraph?mode=path`**，不要用 `/api/path`。这一条已写入契约说明，但**旧端点未废弃**（有意向后兼容）。

### D10 Neo4j 双后端契约一致 **本环境不可达** ⇒ 记 SKIP（**不计通过**）

- 自检 N1 连不上 `127.0.0.1:7687` ⇒ `SKIP`。设计上 NX / Neo4j **共用 `Backend` 基类的全部查询逻辑**（子类只给 3 个原语）⇒ 语义漂移**不可能**发生；但这只是**架构论证**，**不是实测**。如实声明。

### D11 `error_code` 枚举里 `ENTITY_AMBIGUOUS` / `MISSING_CONDITION` **尚无产生路径**
