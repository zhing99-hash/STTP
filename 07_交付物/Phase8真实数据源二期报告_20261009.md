## 二、B1 · NIST CODATA 2022 常量层真实化

### 实现
`11_真实数据/codata_ingest.py`（`--fetch` / `--check` / `--build`）：
拉取 `physics.nist.gov/cuu/Constants/Table/allascii.txt`（CODATA 2022 完整清单，固定宽度
ASCII 表，含 Quantity / Value / Uncertainty / Unit 四列），解析出 **355 条常量**。

### 检出并修正的 3 项真实缺陷

| 图谱节点 | 原值 | CODATA 2022 | 问题 |
|---|---|---|---|
| `TH:pq:gas_const` | `8.314` | `8.314462618` | **精度严重不足**（相对误差 5.56e-05，对化学计算有实际影响）|
| `EM:pq:permittivity` | `8.854187817e-12` | `8.8541878128e-12` | **CODATA 2014 旧值** |
| `EM:pq:permeability` | `1.25663706212e-06` | `1.25663706127e-06` | **CODATA 2018 旧值** |

另修 2 个 **PhysicsBabel 空壳常量**（`PB:pq:grav_const` / `PB:pq:planck`，`value=None`）——
它们与其权威对齐目标同指一物理量，故建 `same_as` 跨源对齐边（**不合并**，因其挂着
大量 `has_symbol` 入边，合并会牵动 3000+ 条边的重组，属独立一轮）。

### 产出
- **13 → 23 个常量节点**：有 `unit` **1 → 18**、有 `uncertainty` **0 → 9**、CODATA 溯源 19
- **新增 10 个跨学科桥常量**（图谱此前完全缺失）：
  Avogadro `N_A`、elementary charge `e`、electron/proton mass、vacuum impedance、
  Stefan-Boltzmann、Rydberg、atomic mass constant、fine-structure `α`、standard gravity `g_n`
  —— 这些是「数学 ↔ 物理 ↔ 化学」共用的桥（如 `N_A` 连接物质的量与微观粒子数）
- 2 条 `same_as` 跨源对齐边（`alignment_source=codata`，`method=quantity_match`）

### 解析过程踩到的两个坑（已修）
1. **列边界**：表头 `Value@65 / Uncertainty@87 / Unit@109`，实测数据列边界为 **60 / 85 / 108**
   （相对表头 −5 / −2 / −1），初版用 57/83/105 切错致 `proton mass` 的单位变成 `7 kg`。
2. **`...` 截断标记**：NIST 用 `8.314 462 618...` 表示精确值在此截断，且省略号**可能出现在
   指数之前**（`1.054 571 817... e-34`）。初版只剥尾部省略号 → `float()` 抛错 → **整行被丢弃**，
   表现为 reduced Planck / Stefan-Boltzmann / molar gas constant / Faraday「未命中」。
   改为剥任意位置的 `...` 后 355 条全解析。

## 三、B2 · PubChem 权威分子校验 + 元素组成缺陷修正

### 实现
`11_真实数据/pubchem_ingest.py`（`--fetch` / `--check` / `--build`）：
用图谱自带的 **`inchikey`**（化学界唯一分子指纹，27 字符）向 PubChem PUG REST 精确反查。
**713 个 inchikey 8 批 26 秒全部命中**。

### 关键技术点
- **PubChem 批量返回的 CID 顺序与请求顺序不一致**（实测请求 8 个返回 9 条且乱序）
  → 不可按顺序对齐；改为在请求中索要 `InChIKey` 属性，用返回值中的 InChIKey **精确匹配**。
- 同一 inchikey 可能对应**多个 CID**（实测 42 例）→ 取**最小 CID** 作为确定性规则。
- 只查有 inchikey 的分子 —— 名称查询有歧义风险（上轮 OpenAlex `concepts` 曾见
  `Prime (order theory)` / `Ring (chemistry)` 类消歧错误），宁缺毋滥。

### 校验结果（三方交叉验证）

| 校验项 | 结果 |
|---|---|
| 图谱 `molecular_weight` vs PubChem | **713 / 713 一致** |
| 图谱 `formula` vs PubChem | **713 / 713 一致** |
| 用权威原子量**独立复算**分子式 vs PubChem | **712 / 713 一致**（相对误差中位 **2.25e-05**）|

唯一"超阈"案例为 `Li+`（PubChem 取 Li≈7.0 整数质量数，IUPAC 标准原子量 6.94）——
属**原子量惯例差异，非数据错误**。

### 🎯 检出并修正：19 条 `composed_of` 的 `count` 错误

对**图谱已有** 2664 条 `composed_of` 边（Phase13 GNN 门控产物）逐条核校原子数：

```
一致 2554 / 不一致 19 / 图谱缺该边 0 / 图谱边缺 count 0
```

**19 条全部是「图谱 count=1，真实 count>1」**，且**根因单一可解释**：

> **Phase13 解析分子式时未剥离电荷后缀，导致紧邻电荷符号的「末尾元素」原子数退化为 1。**

| 分子 | formula | 图谱 | 修正为 |
|---|---|---|---|
| `molecule_283` | `CHO2-` | O=1 | **O=2** |
| `molecule_19660` | `CO3-2` | O=1 | **O=3** |
| `molecule_28123` | `BH4-` | H=1 | **H=4** |
| `molecule_1084` | `O3S2-2` | S=1 | **S=2** |
| `molecule_167232` | `IO4-` | O=1 | **O=4** |
| `molecule_24503` | `Cr2O7-2` | O=1 | **O=7** |
| `molecule_33558` | `N3-` | N=1 | **N=3** |
| `molecule_3280088` | `C6H18NSi2-` | Si=1 | **Si=2** |

**保守修正策略**：因为既有边带 `kind=gnn_typed_verified` / `source=Phase13.Gate.B1` /
`verification_gate` / `rationale` / `status` 等元数据，**绝不整体覆盖** —— 只改 `count`，
并留痕 `count_corrected_from` / `count_corrected_by` / `correction_reason` / `pubchem_formula`。
校验结果确认：**19 条修正边全部保留原有 `kind=gnn_typed_verified` 与 `source=Phase13.Gate.B1`**。

### 产出
- 713 个分子补 `pubchem_cid` + `pubchem_verified` + `pubchem_molecular_weight`（跨源权威背书）
- 754 个分子中 **727 个有 `pubchem_cid`**（另 14 个是原生 `PC:mol:*` 节点）

## 七、源头修复（本轮同步完成）

按本项目铁律「**改数据前先改源头**」，19 条 count 缺陷的**产生脚本已一并修好**，
否则重跑 ETL 会重新长出错误边。

### 根因（贪婪匹配越界）
`09_科研扩展/9_inference/gnn_infer.py` 的 `molecule_formula()` 用一句正则剥离电荷后缀：

```python
s = re.sub(r"[\^]?\d*[+\-\u2212]+\d*$", "", s)   # ← bug
```

**开头的 `\d*` 会贪婪吞掉「末尾元素的下标」**：

| 输入 | 正则匹配 | 剥离结果 | 后果 |
|---|---|---|---|
| `CHO2-` | `2-` | `CHO` | O 退化为 **1** |
| `Cr2O7-2` | `7-2` | `Cr2O` | O 退化为 **1** |
| `BH4-` | `4-` | `BH` | H 退化为 **1** |
| `N3-` | `3-` | `N` | N 退化为 **1** |

该 `\d*` 本意是匹配 `+3` 这类电荷量，但它同样匹配元素下标 —— 二者在无 `^` 分隔时无法由单个正则区分。

### 修复
拆成两条精确剥离，先处理 `^` 上标式、再处理直接以 `[+-]\d*` 结尾的形式：

```python
s = re.sub(r"\^\d*[+\-\u2212]+\d*$", "", s)   # 如 SO4^2-
s = re.sub(r"[+\-\u2212]\d*$", "", s)          # 如 CHO2- / Cr2O7-2 / Al+3
```

**验证**：19 个缺陷 case 全部修正；边界 case（`Al+3` / `H2O4P-` / `CH4` / `C6H6`）**新旧一致无回归**；
`FORMULA_RE` 全匹配。`11_真实数据/pubchem_mol_ingest.py` 的 `parse_formula` 同样缺失电荷剥离，一并补上。
