## 一、验收原文被拆成了三个必须真做的动作

「可被 wget 后离线校验通过」如果只跑一遍校验器，那只是自述。本轮把它拆成四个可执行判据，
全部由 `06_PoC/dataset/wget_offline_e2e.py` 真跑：

| 动作 | 怎么证明 | 实测 |
|---|---|---|
| 真的能取下来 | 起 `127.0.0.1` 静态 `http.server`，按清单**逐文件纯 HTTP GET** | **E1 10/10 文件** |
| 目录就是清单那一份 | 下载目录文件集 == 清单文件集（多一个、少一个都红） | **E5 一致** |
| 下下来还是同一份 | 下载副本与**源目录**逐字节比 sha256（**不跟清单比** —— 清单可能是错的） | **E2 10/10 相同** |
| **断网**也能校验 | 子进程里用 `sitecustomize` **打断 `socket.connect`/`connect_ex`/`sendto`/`create_connection`**，再跑随包校验器 | **E3 RC=0、10 条判据全过、零网络访问** |
| 校验器不是空跑 | 在**下载副本**上改一个字节 ⇒ 必须变红 | **E4 RC=1，V2/V3/V6/V7 变红** |

> **E3 是这一轮的核心**：「我没看到它联网」不等于离线。把 socket 打断之后它还能跑完，
> 才叫「离线可校验」。这条判据同时排除了「校验器偷偷回连仓库/网络取数据」这种最隐蔽的假通过。

**关于 wget（如实记录）**：本机**没有装 `wget`**（`which wget` 空，只有 `curl`）。
E1 因此打印的是「客户端 curl」—— `wget` / `curl` / 标准库 `urllib` 三者都是**纯 HTTP GET**，
语义等价，所以能力被验证了；但**为第三方写的命令仍是 `wget -r -np -nH --cut-dirs=1`**
（见 `dist/README.md`），不因为构建机没装就假装用过了。

## 三、许可分区：为什么只剩 11%（这是本 Phase 最重要的一句话）

`public_demo` 的口径是**血缘闭包**：边自己的来源、两端节点的来源**三者都必须 `redistributable`**
（复用 `make_sample.license_partition`，三态表只有 `source_registry` 一份）。
剔除 **43,396 边 / 6,913 节点**，前五位：

| 来源 | 被剔边数 | 原因 |
|---|---:|---|
| PhysicsBabel | 24,104 | `DATA_LICENSES.md` 里「待核对、不打包」 |
| ElementKG2.0 | 7,797 | 同上 |
| **ChEBI** | **5,092** | ★ 见下 |
| Phase13.Gate.B1 | 2,578 | 上游 PhysicsBabel（派生不得比上游宽松） |
| chembl_api | 2,512 | CC BY-SA 3.0，对外须专项核对 |

★ **ChEBI 是 `redistributable` 却被剔了 5,092 条** —— 逐条查证后确认：
这 5,092 条**全部**是 `composed_of`（分子 → 元素），**另一端是 ElementKG2.0 的 Element 节点**。
元素节点不可再分发 ⇒ 边跟着不可再分发（闭包规则正确）。
**后果必须说清楚：对外包里 `composed_of` = 0 条**，分子有 1,397 个但**没有分子组成关系**。
这不是 bug，是「政策由程序执行」（铁律 #64）后的如实结果；
要补回来只有两条路：① 核对 ElementKG2.0 许可；② 换 `element_reference`（Apache-2.0）重接元素层。
**两条都还没做，因此对外数据集目前「能查反应、不能算分子式」。**

## 四、判据一览（都能红）

| 层 | 判据 | 结果 |
|---|---|---|
| 构建 `export_dataset.py` | S1 源快照 sha256 构建后重新现算一致 ｜ S2 许可后置审计 0 违规（独立重算） ｜ S3 分区计数自洽 ｜ S4 声明集==实际写出集 ｜ S5 **确定性**：二次全量重建逐字节相同 ｜ S6 随包校验器 0 FAIL ｜ S7 边端点闭合 | **7/0** |
| 校验 `verify_dataset.py` | V0 清单可解析 ｜ V1 文件集齐备（双向） ｜ V2 逐文件 sha256+字节 ｜ V3 JSONL 结构与行数 ｜ V4 引用闭合/id 唯一 ｜ V5 许可一致 ｜ V6 计数一致 ｜ V7 `SHA256SUMS` 自洽 ｜ V8 上游登记形态 ｜ V9 署名落地 | **10/0**（在产物上） |
| 端到端 `wget_offline_e2e.py` | E1 可取 ｜ E5 文件集一致 ｜ E2 逐字节相同 ｜ E3 **断网**校验 ｜ E4 改一字节必红 | **5/0** |
| 自检（可红性） | `verify_dataset --selftest` **VS1–VS9**（合成夹具逐项注入缺陷 + 负对照）｜ `export_dataset --selfcheck` **E1–E5**（许可判据可红） | **9/0**、**5/0** |
| 红探针 | **R36** 校验器 V2 改成「拿清单比清单」⇒ VS2 必须变红 ｜ **R37** 构建把 profile 写死成不过滤 ⇒ S2 必须变红 | **均真会红** |

**S5 的确定性是怎么保证的**：记录按 `id` 排序、`json.dumps(sort_keys=True)`、行尾固定 `LF`
（Windows 默认 CRLF 会让同一份数据在两台机器产出不同 sha256）、清单里**没有时间戳/没有随机数**、
`build.python` 与 `generator.sha256` 是仅有的「环境相关」字段（换环境/改代码会变，这是诚实溯源）。

**fail-closed 的产出方式**：先构建到 `dist.tmp` → 跑随包校验器 → **0 FAIL 才** `os.replace` 成 `dist/`。
直接写 `dist/` 的话，一次失败的构建会留下一份「看着像数据集、其实不完整」的目录，
而下游（下载测试、发布资产）只看目录在不在 —— 这正是「静默产出坏东西」。

## 五、本轮交的学费（新增两条）

**D104 · 判据的输入形态也是接口。** S2 第一次运行就红了，报「16,251 处再分发违规，来源 `<none>`」。
逐条查证：我把**投影后的记录**（原始属性收在 `attrs` 里）喂给了 `audit_redistribution`，
而它要的是带 `props.source` 的**规范图** ⇒ 所有来源读成 `<none>`。
判据没错，是接线错。**教训：#111 判据红了先分清「数据错」还是「喂错」** ——
这次红得很有价值（第一次运行就抓出自己的接线），但也提醒：判据报错的原因不必然是它要防的那件事。

**D105 · 忽略规则在大小写不敏感的文件系统上会多吞东西。**
`.gitignore` 写了 `06_PoC/dataset/dist*`（想连 `.tmp` 一起兜住），结果 Windows 上
`core.ignorecase=true` ⇒ **`DIST_README.md` 也被吞掉**，`git status` 里根本不出现它。
表现形态极安静：文件在工作区里、代码引用它、构建能跑通，**只是永远不会被提交** ——
干净检出上才会炸。修：收窄成 `dist/` + `dist.tmp/` 两条，并把随包 README 改名为 `README_dist.md`。
**教训：#112 「我用通配符兜住所有情况」在大小写不敏感的平台上是另一种漏。**

## 六、能力边界（写在 `manifest.boundary`，不藏在文档里）

1. 上游快照 **81,689,190 B 不入包** ⇒ **V8 只能核对登记值，不能重算上游哈希**。
2. 三态**判定规则**在仓库 `source_registry.py`；包里只有**判定结果** + 逐文件哈希。
   它能证明「包内自洽、未被篡改、没有混进非 redistributable 的记录」，
   但**无法独立重算**「某个上游到底该不该可再分发」。
3. sha256 覆盖**字节**不覆盖语义：语义由 `counts`（V6）、引用闭合（V4）、上游溯源（V8）共同约束。
4. 对外包缺 `composed_of`（见 §三），这是许可政策的结果，不是数据丢失。
