## §2 五条 P0 逐条核验（全部属实，附我的独立证据）

### P0-1 PhysicsBabel 把"整式量纲齐次"误写成"两量之间量纲一致" —— ✅ 属实

- **源码**：`11_真实数据/physicsbabel_ingest.py:83-93`。取方程参与量 `qnodes[0], qnodes[1]` 两个值建 `dimensionally_consistent` 边，写 `verified: True`，**未校验两端量纲相同**。
- **我的独立复现**：参与量顺序 `['PQ:mass','PQ:accel',...]` → 建边 `PQ:mass —dimensionally_consistent→ PQ:accel, verified=True`；然而 M 与 L·T⁻² 量纲并不同。
- **附加问题**：第 72 行把 `exp.get(k)`（该量在**无量纲单项式中的指数**）存进名为 `dimension` 的字段 → **字段语义误标**（不是七维 SI 量纲向量）。
- **影响面**：主图 `06_PoC/etl/normalized.json` 中 `dimensionally_consistent` 边 **1200 条**，全部来自 PB → **问题确在主图，非仅候选产物**。
- **附带诚实说明**：代码 `rationale` 写的是"方程 X 中量纲自洽"（意图是整式），但**边类型名**与 `verified=True` 会被下游读成"这两个量量纲一致"→ **命名与语义负载过重**。

### P0-2 LaTeX 字符串清洗被当成数学等价证明 —— ✅ 属实（我已独立复现）

- **源码**：`09_科研扩展/9_inference/gnn_infer.py:503-509`（`norm_latex` 删全部 LaTeX 命令 + 小写）；`:576-578`（两者归一化后非空且相等 → `same_as / R-MATH / VERIFIED`）。
- **我的独立复现**（亲自跑）：

  | 输入一 | 输入二 | 归一化结果 | 判定 |
  |---|---|---|---|
  | `\sin(x)` | `\cos(x)` | 均 `(x)` | **same_as / VERIFIED** ❌ |
  | `\alpha+x` | `\beta+x` | 均 `+x` | **same_as / VERIFIED** ❌ |
  | `E=mc^2` | `e=mc^2` | 均 `e=mc^2` | **same_as / VERIFIED** ❌ |

- **判定**：属实。字面相似只能作检索候选，**它却直接授予 VERIFIED**。

### P0-3 校验器未声明"验证范围" —— ✅ 属实

- **化学**（`04_验证闭环/verification_loop.py:86-93`）：`count_atoms` 只数 `atom.GetSymbol()`（**显式原子**），不计隐式氢、不查电荷 → `CO>>C=O`（甲醇→甲醛，氢 4 vs 2）、`[Na+]>>[Na]`（电荷不守恒）均会 `VERIFIED`。
- **数学**（同文件 `:283`）：`sp.Symbol(s, real=True, positive=True)` 把**所有变量隐式设为正实数** → `sqrt(x**2)=x` 在该假设下恒成立而被判 VERIFIED，未显式附加 `x≥0`。
- **物理**（`gnn_infer.py:566-573`）：分子 + 任意名称含 `mass/weight/energy` 的物理量、只要算得出摩尔质量 → `has_quantity / VERIFIED`。用水的摩尔质量 + 名为 energy 的量也返回 VERIFIED。
- **判定**：属实。根子是**一个布尔 `verified` 包办了多种完全不同的检查强度**。

### P0-4 化学实体不能仅凭分子式 `same_as` —— ✅ 属实

- **源码**：`11_真实数据/elementkg10m_ingest.py:206-214`「骨架桥接」：`if f in SKELETON_FORMULA: 生成 same_as (kind=skeleton_bridge, alignment=formula, confidence=0.9, inferred)`。
- **反例成立**：乙醇 `CCO` 与二甲醚 `COC` 同为 C₂H₆O 但结构不同（PubChem CID 702 = 乙醇）→ 分子式不足以断言身份。
- **影响面**：主图 `same_as` 边 108 条，其中 `skeleton_bridge` **6 条** → 规模小，但**语义错误类别真实**（分立构 / 盐型 / 质子化 / 同位素同源）。
- **判定**：属实。`same_as`（身份）与 `same_formula_as`（分子式相同）未区分。

### P0-5 GNN 训练/测试泄漏 —— ✅ 属实且最严重

- **源码**：`gnn_infer.py:126-138` 把每个关系的**全部边**加入 `train_pairs`（仅 `has_symbol` 下采样）；`:342-347` 评估又从**同一份 `edge_by_type[rel]`** 取前 10% 作测试 → **测试正样本已在训练集中**。
- **附加泄漏**：`:157-163` 的 `out_et/in_et` 结构特征取自**全图**（含测试边）。
- **负采样**：`:321-339` `pool=250` 随机负例，**允许重复**、不约束端点类型 → 是"250 随机负样本口径的排序指标"，**不能当作 filtered MRR**。
- **指标不一致属实**：`phase13_gnn_metrics.json` 的 `avg_MRR = 0.7037`，而某阶段报告写 **0.7391**（无 run ID / 数据哈希可解释差异）。
- **判定**：属实。**当前 GNN 指标不能用于宣称"发现能力"**。

## §4 需要校准的地方（不是错，是"力度"与"假设"）

1. **P0 的"紧急度"取决于项目定位**。文档自己承认 STTP 当前是"研究原型"。对研究原型，这 5 条是"已知局限 + 必须补课"；对**商业产品**才是真正 P0。所以 P0 的标签成立的前提是"要往可信产品走"。→ **这恰好是需要老板拍板的那个岔路口**。
2. **文档默认 3 人 + 0.5 专家、90 天冲刺**。若实际是小团队/单人，其 §8 排期不可直接照搬（文档也补了一句"若为单人项目，应压缩范围"）。
3. **对主图影响面它偏保守**（称无法推断受影响边数）。实际可量化：`verified=True` 覆盖主图 **28680/49881 条边**，`dimensionally_consistent` **1200 条**，`skeleton_bridge` **6 条** → **"verified 语义通胀"是系统性的，不是个别脏边**。这一点我方应比文档更清醒。
4. **商业章节**（TAM/定价/竞品）自认是假设；Wolfram/Reaxys 的对比成立但比较对象是"成熟商业产品"，用它来否定一个**研究原型**的研发价值，逻辑上略越界。→ 其商业警示应"听进去"，但不应据此否定研究路线。

## §5 路线调整建议：**调整，但分两层**

### §5.1 第一层（技术层）——**全盘采纳**，且与现有项目原则完全兼容

文档的 5 条 P0 修法，与本项目既有铁律**高度同构**（"改数据前先改源头""北极星必须有仪器""静默降级最危险""种子不是权威"）。建议把下一轮直接定为 **「可信性修复轮（Trust Fix）」**：

| 项 | 动作（源头修复，非下游打补丁） | 验收 |
|---|---|---|
| P0-1 | PB 参与关系改 `uses_quantity`（或保留 `dimensionally_consistent` 但**仅当两端经 pint 校验量纲一致时**才置 verified）；`dimension` 字段改名 `exponent_in_term` | 反例 `mass–accel` 不再判等 |
| P0-2 | **立即撤销** `norm_latex` 的自动 VERIFIED 权限；LaTeX 规范等价降级为**检索候选**，真等价走 AST + 变量域 | `sin/cos`、`α/β`、`E/e` 三反例归零 |
| P0-3 | `verified` 布尔的**语义拆分**：语法有效 / 量纲齐次 / 计量守恒 / 电荷守恒 / 变量域 / 来源核对 / 专家审核 —— 各为独立字段；补隐式氢与电荷检查；数学变量域显式化；摩尔质量门控限定"质量类"且要求单位/模型 | 文档反例集全部达到正确结果 |
| P0-4 | 分子式匹配降级为 `same_formula_as` / 候选；身份走规范化 InChIKey | 乙醇/二甲醚反例不再 `same_as` |
| P0-5 | **重建 GNN 评测**：先分组去重再切分 train/val/test（same_as/逆向边/同公式变体不跨集）、只用训练图构建邻接、报类型约束 filtered 排名 + 分组 P@K/Recall/置信区间 + 规则基线消融 | **切分交集 = 0**，并用独立标注集验证增量 |
| 新增仪器 | **冻结反例集（counterexample suite）**，作为与 `connectivity_audit.py` 并列的**新门禁**："已知反例误升 VERIFIED = 0" | 纳入 `sttp.sh check` |

**关键：这一层不依赖"是否商业化"，无论走哪条路都该做，而且成本低、收益高。** 建议作为下一轮（第 17 轮）。

### §5.2 第二层（战略层）——**有选择地校准**，把决策权交回老板

文档主张："把目标从『更大的跨学科图』改成『能可靠完成一组跨学科任务的知识产品』，并走 90 天商业化"。

我的判断：**方向对，但需要与项目原始定位对表**——STTP 是 **Science Topology Through Physics**，其北极星（跨学科连通性）本身是一个**研究假设**。因此存在两条路线，请老板裁定：

- **路线 A（研究原型，收敛版）**：保留"跨域连通"作为研究目标，但**接受文档对北极星的定义修正**——从"跨域边计数/占比"改为**"在固定任务集上，跨域结论正确且证据可追溯的比例"**；下一批内容建设 = 文档 §5.4 的 **"热力学—化学平衡—数学方法"专题**（它天然产 **数学↔物理↔化学** 真跨域桥，正好也是我们 Phase 26 说要找的"能产跨域桥的源"，**两条线在此收敛**）。
- **路线 B（产品化，文档版）**：采用文档 §5–§9 的 Claim/Evidence/Verification 三层对象 + Trusted/Supported/Hypothesis 三层发布 + `python -m sttp` CLI + release manifest + 90 天用户/付费试点。**但这需要真实团队与商业投入**，且应先确认老板是否要做产品。

**建议的执行顺序（两条路线的公共部分）**：
1. **第 17 轮：可信性修复轮**（§5.1，两条路线都要）。
2. **第 18 轮：Claim/Evidence/Verification 轻量落地**——注意**不必新建一堆微服务**，本项目已有 `props.confidence / explicit_or_inferred / verification_gate` 范式，可**先以边级元数据 + 一个 `Claim` 视图**渐进引入（复用既有"零 schema 改动优先"经验）。
3. **第 19 轮：热力学—平衡专题**（同时服务"跨域桥"研究目标与文档的"精品专题"目标）。
4. **品牌/复现工程**（低风险高收益，穿插做）：小离线 demo + release manifest + 依赖锁 + `--out` 统一 CLI。**这一条我建议无条件做**，它直接消除文档 §4.7/§4.10 的"不可复现"指控。

### §5.3 明确**不采纳**的部分

- ❌ **不采纳"删除物理节点 / 强行提高跨域边比例"**——文档也明确反对（与项目铁律 #18 一致）。
- ❌ **不采纳"以商业章节否定研究价值"**——竞品对比对象是成熟商业产品，结论只适用于"是否商业化"，不适用于"是否继续研究"。
- ⏸ **暂缓**：百万级扩库、更大模型训练、图库双活、通用药物发现（文档与项目认知一致）。
