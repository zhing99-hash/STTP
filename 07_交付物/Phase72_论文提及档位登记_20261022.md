## 二、为什么不"把落库改小去迁就重算"

当时有三条路（见 Phase 71 报告 §八）：降档 / 补登记 / 白名单。选 A 的理由在侦察后被**修正**过一次，
值得写下来：

| 设想 | 实测后 |
|---|---|
| 把 m1 登记为 `rule_checked` + `recompute`/`indep=True` | **可行**，但必须先证明"重算真的能复现" |
| 随手给 101 条补一条证据对象 | **不行** —— 证据由 `build_evidence` 从**重算结果**构造（铁律 #36 同源），照旧标签另写一份就是编造 |

于是先测量再动手：用 `phase68_paper_fetch` 的 `canon_tokens/name_tokens/find_span`
（**m1 的唯一实现，不复制**）在 101 条上重跑一遍：

```
(where, 命中 snippet, 命中 Paper 节点 title)
   79  ('abstract', True, False)
   22  ('title',    True, True)
snippet 重算不命中: 0
```

- **101 条全部复现**（m1 重算通过，没有一条是假的）；
- 22 条 `where=title` 的边还能用 **Paper 节点的 title** 复核 —— 这条输入**与边的记录无关**，是真独立复核；
- 79 条 `where=abstract` 的边：摘要**没有落库到 Paper 节点**（只有 title 落库了）⇒ 只能用边自带 snippet
  把规则**重跑一遍**。

## 三、处置（三件事）

### ① 把 m1 登记进判级模型（`11_真实数据/verification_model.py`）

新增 **A11 分支** + 纯函数 `name_mention_in_text(name, text)`：

```python
if t == "mentioned_in" and kind == "openalex_name_mention":
    ok, via, why = ctx["mention_ok"].get(eid, (None, None, ""))
    if ok is True:
        return R("rule_checked",
                 "name_mention_title_recompute" if via == "node_title"
                 else "name_mention_snippet_recompute",
                 MENTION_VERIFIER, ...)
    if ok is False:
        return R("unverified", "name_mention_mismatch", MENTION_VERIFIER, ...)
```

★ **两个 scope 刻意分开**：`title` 档的输入是节点 title（真独立），`snippet` 档只是把规则重跑一遍
（只证明"可复现"）。**独立性强弱必须让读者一眼看见**，不能混成一个名字。

★ m1 的 tokenizer/span 匹配 **import 而不复刻**（`phase68_paper_fetch` 只依赖标准库）：
复制一份就会变成「同一条规则两个版本」（#88/#102）。导入失败 ⇒ 一律返回"不可判定" ⇒ **不猜**。

★ 判否即判否：重算复现不出公式名 ⇒ `unverified` + `rebuttal`，不因为"当年建过边"就放行。

## 五、两条学费

### #116 · **自洽 ≠ 登记**：两个一起坏的时候，判据仍然绿

R41 第一版期望 **E3**（落库 == 重算）变红，结果**没红**。原因值得写清楚：

E3 判的是**合并后的最终态**，而本 delta 的作用恰恰是「把落库改成重算」⇒ 注入把重算改坏成
`unverified` 时，delta 会**跟着把落库也降成 `unverified`**，两边**仍然一致** ⇒ E3 恒绿。

也就是说：**E3 只能证明"自洽"，证明不了"m1 还在模型里"。**
修法是加 **E8**：直接查重算结果的 scope 是否以 `name_mention_` 开头 ——
m1 一旦被撤，这些边落到 B8 兜底（`unclassified`），**在 E8 上红**。

> 与 #108（判据要看最终态，不能看本轮产出）是**同一个坑的镜像**：
> #108 说"别看产出"，这条说"只看最终态也不够 —— 当 delta 就是用来对齐两者时，最终态必然自洽"。
> **判据必须直接指名它要保护的那个东西**（这里是"m1 在不在模型里"），不能靠旁证。

### #117 · 探针环境的洞，会在你第一次加依赖时冒出来

新增 `verification_model → phase68_paper_fetch` 这条 import 后，`bash sttp.sh evdeps --check`
的 ⑦ 段立刻假红：`unverifiable_verifier:11_真实数据/phase68_paper_fetch.py`。

根因不在数据：⑦ 段在**临时 git 仓库**里只镜像了参考表，**没镜像验证器及其本地依赖**
⇒ 算 `dependency_versions` 时取不到 blob ⇒ 基线变 `needs_review`。

修在**探针侧**（把 `VERIFIER_MODULES` 及其 `code_imports` 结果一并镜像），
而不是"以后别加依赖" —— 这样修，才对**将来任何一条新依赖**都成立。
