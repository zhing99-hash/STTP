## 2. A4 · CDN 依赖本地 vendored

### 2.1 为什么要本地化

原页面三个 `<script src="https://cdn.jsdelivr.net/...">` 是**无条件外部依赖**。CDN 不可达时页面必然走纯文本降级分支，前端交互代码根本不执行——这不是"轻微降级"，而是可视化能力整体失效。上一轮因此也无法做任何浏览器端验证。

### 2.2 落地内容

**（1）新增 `06_PoC/vendor/fetch_vendor.py`**（下载器 + 校验器）

| 文件 | 体积 | 作用 |
|---|---|---|
| `cytoscape.min.js` | 373,304 B | 图渲染内核 3.30.2 |
| `layout-base.js` | 147,958 B | 依赖链最底层 2.0.1 |
| `cose-base.js` | 118,906 B | 中间层 2.2.0 |
| `cytoscape-fcose.js` | 57,239 B | 力导布局 2.2.0 |
| `tex-svg.js` | 2,108,580 B | MathJax 3.2.2（LaTeX → SVG） |
| **合计** | **2.8 MB** | |

脚本特性：直连优先、失败回退系统代理；三个 CDN 主机互为备用；每项带体积下限与 sha256；`--verify` 只校验不下载；幂等（已存在则跳过）。

**（2）`viz_server.py` 新增 `/vendor/*` 静态路由**

原服务只服务 4 个路由 + 根页，**没有任何静态文件路由**——所以"下载文件"只完成一半，必须补路由。安全设计：

- **目录穿越防护**：解析后的绝对路径必须落在 `VENDOR_DIR` 内，否则 403
- **扩展名白名单**：仅放行 `.js/.mjs/.css/.json/.map/.woff/.woff2/.ttf/.svg/.txt`，其余 403

实测：

| 请求 | 结果 |
|---|---|
| `/vendor/cytoscape.min.js` | 200，373,304 B |
| `/vendor/tex-svg.js` | 200，2,108,580 B |
| `/vendor/../.env` | **403**（穿越被拦） |
| `/vendor/x.exe` | **403**（扩展名不符） |
| `/vendor/nope.js` | 404 |

**（3）`graph_view.html` 改为「本地优先 + CDN 兜底」**

```html
<script src="vendor/cytoscape.min.js" onerror="window.__v_cy=1"></script>
<script>
if (window.__v_cy || !window.cytoscape) {
  document.write('<script src="https://cdn.jsdelivr.net/npm/cytoscape@3.30.2/dist/cytoscape.min.js"><\/script>');
}
</script>
```

用 `onerror` 而非特性探测来判断本地是否可用——因为 MathJax 的 `typesetPromise` 是**启动完成后**才挂上的，用特性探测会误判并触发无谓的 CDN 请求。

### 2.3 顺带发现并修掉的 3 个既有缺陷

**缺陷 1 · fcose 布局从来没有真正生效过（最严重）**

`cytoscape-fcose.js` 的 UMD 头是三级依赖链：

```
root["layoutBase"]      ← layout-base.js
   ↓
root["coseBase"]        ← cose-base.js   factory(root["layoutBase"])
   ↓
root["cytoscapeFcose"]  ← cytoscape-fcose.js  factory(root["coseBase"])
```

页面原先**只引了 fcose 一个文件**（CDN 路径也一样缺前提）→ `factory(undefined)` → 抛错 → 被 `try { cytoscape.use(window.cytoscapeFcose); } catch (e) {}` **静默吞掉** → 一直退回内置 cose 布局。

**表面一切正常，功能从未启用**——这类缺陷只有断言才抓得住。修法：按序本地化并加载三级；A4 测试增加 `cy.layout({name:'fcose'})` 可实例化断言作为永久回归守卫。

**缺陷 2 · MathJax 用 CHTML 构建根本无法真离线**

`tex-mml-chtml.js` 是 CHTML 输出，需另拉 **30+ 个 woff 字体文件**（散在多个子目录），断网时公式渲染不出来。

改用 `tex-svg.js`：SVG 输出把字形路径**内嵌进 DOM**，单文件自包含。

值得一提：页面原有配置写的是 `svg: { fontCache: 'global' }`——这个选项**只在 SVG 输出下生效**。说明当初的配置意图就是 SVG，但加载的却是 CHTML 构建，**配置与构建从一开始就不匹配**。本次改动实际是把二者对齐。

**缺陷 3 · `viz_server.py` 自身仍在用被项目废弃的 stdout 替换写法**

第 45–50 行：

```python
sys.stdout = io.TextIOWrapper(sys.stdout.buffer, encoding="utf-8", errors="replace")
```

这正是 A5 轮导致「端口在监听但对所有请求返回空」的同一模式（GC 关闭底层 fd）。项目已明确约定一律用 `reconfigure()`——但 `viz_server.py` 自己没改。本次一并改掉，并移除随之失效的 `import io`。

## 3. A9 · Kuzu 演示脚本幂等化

### 3.1 问题

`03_知识层/load_kuzu_demo.py` 的 DDL 无 `IF NOT EXISTS`，且数据用 `CREATE` 写入。原实现靠"每次先删库"绕过，但那是**破坏性**做法，且直接对着已有库运行会报 `Node already exists`。

### 3.2 修法

| 维度 | 改动 |
|---|---|
| DDL | `CREATE NODE TABLE IF NOT EXISTS` / `CREATE REL TABLE IF NOT EXISTS` |
| 节点写入 | `MERGE (x:Node {id:$id}) SET ...`（按主键对齐） |
| 边写入 | `MATCH (a),(b) MERGE (a)-[r:TYPE]->(b) SET r....`（按 起点/类型/终点 对齐） |
| 破坏性操作 | 收进 `--fresh`（显式要求才删库），默认**非破坏性增量对齐** |
| 新增开关 | `--db <path>`（换库路径）、`--limit N`（调试） |

边的 MERGE 键选 `(起点, 类型, 终点)` 与项目既有约定一致——快照边 id 本就是 `type|source|target`，二者同构。

### 3.3 验证

对独立测试库连续运行 **3 次**：

| 运行 | 退出码 | 节点 | 边 | 报错 |
|---|---|---|---|---|
| 第 1 次（建库） | 0 | 300 | 609 | 无 |
| 第 2 次（幂等） | 0 | 300 | 609 | 无 |
| 第 3 次（幂等） | 0 | 300 | 609 | 无 |

**结论：幂等 PASS**——计数稳定、无 `already exists`、无异常。测试库已清理。

## 7. 经验沉淀

1. **"静默降级"是最危险的缺陷形态**。fcose 缺失依赖后被 `try/catch` 吞掉，功能从未启用却毫无报错。**凡是"可选增强"路径，都必须有断言守住**，否则会长期以为自己有该功能。
2. **"离线可用"不能靠下载文件达成**。必须同时确认：① 服务端会发这些文件（原服务无静态路由）；② 加载后功能真的可用（fcose 依赖链）；③ 渲染不依赖次要资源（CHTML 的字体文件）。三者缺一，离线就是假的。
3. **验证必须双向**。只有"断网场景 PASS"不够——反向对照（连本地副本一起拿掉）才能证明测试本身有检测能力，而非空过。
4. **云实例的"不可达"要先分清层级**：先看该云厂商主域是否解析，再看实例子域。本次正是靠这个顺序，把"网络不通"的误判纠正为"Aura Free 闲置暂停"。
5. **测试台也是代码，会被产品改动打破**。A4 引入 `document.write` 后 A3 测试台立刻失败——这是测试台缺口而非产品缺陷，补桩即可；但若不补，就会误以为是回归。
