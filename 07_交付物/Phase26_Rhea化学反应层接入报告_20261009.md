## 二、老板裁定项：`MX:math:derivative_power` 显式对齐

**裁定**：把 `MX:math:derivative_power` 显式对齐到人工策划的 `MC:fo:power_rule`。

**事实核查后发现**（重要）：这两个 `MX:math:*` 节点其实是同一条幂法则的**两半**：

| 节点 | 名称 | 含义 |
|---|---|---|
| `MC:fo:power_rule` | `d/dx x^n = n x^{n-1}` | 人工策划的**完整公式**（`curated_seed`） |
| `MX:math:derivative_power` | `d/dx(xⁿ)` | LLM 假设层的**左侧表达式概念** |
| `MX:math:power_rule` | `n·xⁿ⁻¹` | LLM 假设层的**右侧结果概念** |

二者已由 `proves` 边相连（`MX:math:derivative_power → MX:math:power_rule`）。本轮按既有范式（`MC:fo:power_rule —same_as[seed_to_existing/manual_curation]→ MX:math:power_rule`）**补上另一半**：

```
MC:fo:power_rule —same_as[seed_to_existing]→ MX:math:derivative_power
                   （alignment_note: 同一幂法则的左侧表达式概念，与右半成对）
```

**落地链路**：改源头（`10_种子数据/build_math_calculus.py` + `extra_external`）→ 重跑种子（13 节点 / 18 边）→ `sync_seed_delta.py`（**0 噪声**：0 props 变更 / 0 新节点 / **1 新边**）→ `apply_delta.py --apply`（2×6/6 自检 PASS）→ 推 Aura（Δ+1）→ 对账零差异。

## 四、为什么选 Rhea + ChEBI

在可达的化学源中，选 Rhea 的理由是**它是唯一能产出「化学原生结构」且零 schema 改动的源**：

1. **方向语义天然确定**：Rhea 方程以 `=` 明确分隔反应物/产物 → 可**复用既有** `reactant_of` / `product_of`，无需人工判方向。
   - ⚠ 陷阱：Rhea 的 `chebi-id` 列是**按首次出现顺序去重**的（同物种跨区室 `sulfate(out)`/`sulfate(in)`、同聚合物不同聚合度 `tRNA(n)`/`tRNA(n+1)` 只列一次），故切分点须取「**去重后的左侧物种数**」。已实测 939 条上两种口径完全一致。
2. **EC 号 = 不同维度**：每条反应带**酶分类号**（EC），是不同于 `has_quantity` 的新化学维度，作为**节点属性**落地（**不新建边类型**，避免「为凑指标而造 schema」）。
3. **ChEBI 参与物带分子式/质量/SMILES/交叉引用** → 可建 `composed_of` 连到 Phase 8 真实元素层（`EK:el:*`），**把化学子图锚定进主图**。
4. **零 schema 改动**：全部复用 `Reaction` / `Molecule` / `reactant_of` / `product_of` / `composed_of` / `same_as` 六个既有类型（符合「新维度优先复用既有类型」铁律）。

## 六、关键设计决策

### 6.1 防孤岛守卫（**本轮踩坑后新增**）
首次应用后审计立刻报出 **3 个连通分量**（新增 2 个：size=5、size=3，共 8 节点）。根因：这些反应的参与物分子式含 **R 占位符**（如 `C3H6O6PR2`），被旧版 `is_generic` 判断一律跳过 `composed_of` → **无一锚定元素层 → 成孤岛**。

**两处修复（都在源头）**：
1. **区分「聚合物」与「部分结构」**：
   - `is_polymer`（`(C11H20O12P)n`，计数是**重复单元**）→ 仍跳过 `composed_of`；
   - 含 R/X 占位符者（R 以外 C/H/O/P 计数**精确**）→ **建「部分结构」`composed_of`**，标 `partial_structure=True`、置信度 0.98→**0.7**。→ 组成边 4475 → **5092**。
2. **守卫**：只保留「**至少一个参与物能锚定主图**（有 `composed_of` 或名称桥）」的反应；否则连反应带化合物一起剔除。本轮修复后**守卫未丢弃任何反应**（0 条），但它是防止未来再次制造孤岛的必要约束。

修复后：**连通分量 1 / 孤立 0 / `--strict` EXIT=0**。

### 6.2 学科标注显式化
新节点一律写显式 `domain=chem.*`（`graph_export.subject_of` 中**显式 domain 优先**），并在 `graph_export._NS_SUBJECT` 补 `RH`/`CH` → 化学兜底键 —— **防止重演上一轮「物理切片命名空间被误标为数学」的事故**。

### 6.3 ChEBI 交叉引用**不含 PubChem CID**（实测结论）
原设计打算用 `obo_xref` 里的 `pubchem.compound` 桥到 `PC:mol:<CID>`。**实测发现 OLS4 的 ChEBI 术语 xref 只有 kegg.compound / cas / drugbank / hmdb / gmelin 等，没有 PubChem** → 该桥 0 命中。改用「**人工策划标签精确匹配**」（宁缺毋滥，只覆盖 14 个已真实化分子），得 5 条真桥。

### 8.1 本轮**未解决**的（优先级最高）
1. **跨域桥接**：绝对跨域边仍 869 条，`has_quantity` 占 784（90%），「化学↔物理」占 93%。**加质量只提升均衡，不产生新跨域边**。下一轮应专门做**跨域桥**：
   - 化学侧：ChEBI 化合物的**热化学量**（NIST Chemistry WebBook 可达）→ 与 `PQ:*` 物理量建立**带语义的**桥（而非又一个 `has_quantity`）；
   - 数学侧：**DLMF（可达）** 的特殊函数公式 → 与 PhysicsBabel 物理方程建立 `same_as`/`derived_from` 桥（**数学↔物理**，当前仅 29 条，是最薄弱的一边）。
2. **名称桥偏少**（仅 5 条）：因 ChEBI 用质子化态命名（`ATP(4-)` vs `ATP`）。**下一步**：引入「质子化态容忍」的匹配（需人工裁定口径，不可自动放宽）。

### 8.2 本轮**未做**的
3. **数学侧源未接入**（仅完成探测与定标）。下一轮首选 **DLMF**（数学公式，与物理公式可桥）或 **OEIS**（需先论证与主图的连接路径，否则会造孤岛）。
4. `RH` 的 EC 号目前只是属性；若将来要「酶↔反应↔化合物」成链，需评估是否引入 EC 层级。
5. Rhea 全库约 1.9 万条反应，本轮取 939 条（约 5%）。扩容前须评估 **Aura 免费实例配额**（当前 9656 节点 / 49881 边）。
