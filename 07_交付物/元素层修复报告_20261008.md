## 二、缺陷 1 · ElementKG 符号解析用错字段，导致氧元素丢失

### 现象

`EK2:el:S` 节点自相矛盾——`symbol=S`，但 `name=Oxygen`、`atomic_number=16`、`weight=15.999`（氧的质量）。且 **EK2 层 12 个元素中没有任何氧节点**。

### 根因（已用原始 CSV 验证）

`公共数据集/10m_elementkg_release.csv` 中共 **13 个 element 实体**，全部带权威 `NAME_IS` 字段：

| 实体 | HASNAME | NAME_IS | HASATOMIC | HASWEIGHT |
| --- | --- | --- | --- | --- |
| E73 | Oxygen | **O** | **16** | 15.999 |
| E93 | Sulfur | **S** | 16 | 32.06 |

- ElementKG 给 Oxygen 的 `HASATOMIC` 写的是 **16**，实为**族号**（氧在 16 族），不是原子序数；
- `11_真实数据/elementkg10m_ingest.py` 的 `_set_elem_prop()` **未读取 `NAME_IS`**，
  随后回退用 `ATOMIC_TO_SYMBOL[HASATOMIC]` 反查符号 → `16 → "S"`；
- 节点 id 按符号生成 `EK2:el:{sym}` → E73(Oxygen) 与 E93(Sulfur) **撞 id**，
  `elem_props` 两条目产生同一 id，最终只剩一个，字段被污染。

> 附带确认：这不是源数据问题——CSV 里两个实体各自正确，13 个实体的 `NAME_IS` 齐全且无重复。
> 缺陷完全由解析脚本引入。

### 修复

| 文件 | 改动 |
| --- | --- |
| `11_真实数据/elementkg10m_ingest.py` | `_set_elem_prop()` 增加 `NAME_IS → symbol`；符号解析改为**优先权威 `NAME_IS`**，仅在缺失时回退反查并打 `[WARN]` |
| 同上 | 元素节点改由权威参考表校正 `atomic_number`/`name`，源值保留为 `ek_atomic_raw`/`ek_name_raw` 以便追溯 |
| 同上 | 内联 118 项 `ATOMIC_TO_SYMBOL` 字面表改为引用 `element_reference`，消除重复表 |

修复后：

```
EK2:el:O   Z=8    w=15.999  name=Oxygen   raw_atomic=16(族号,保留)
EK2:el:S   Z=16   w=32.06   name=Sulfur
```

## 三、缺陷 2 · 14 个元素缺原子量

| 来源 | 元素 | 修复方式 |
| --- | --- | --- |
| `IC:el:*`（无机切片） | Na / Cl / Fe | `seed_inorganic.json` 补 `atomic_mass` + `atomic_weight` |
| `BC:el:nitrogen`（生化切片） | N | `seed_biochem.json` 同上 |
| `EK:el:*`（ElementKG OWL） | Cn Ds Fl Lv Mc Mt Nh Og Rg Ts | `elementkg_ingest.py` 引自权威表补齐（OWL 无 `hasWeight` 字面量） |

新增权威元素参考表 **`11_真实数据/element_reference.py`**：118 项（符号 / 名称 / 原子序数 / IUPAC 2021 标准原子量），
提供 `by_symbol()` / `by_atomic_number()` / `weight_of()`，含 118 项完整性自检。此前散落在各脚本里的硬编码表统一收敛到此。

同时把每个 Element 节点的 `atomic_mass` 与 `atomic_weight` **双键对齐**（补齐缺失键、不覆盖已有值），
使下游无论读哪个键都能取到值（`phase9_deepen.py` 本就按 `atomic_mass → atomic_weight → hasWeight → hasAtomic → weight` 顺序回退）。
