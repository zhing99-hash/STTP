## 3. 设计要点（与方案 §6 的对应）

### 3.1 零构建的原生 ES Module

```text
06_PoC/
  graph_view.html          壳（<script type="module" src="js/main.js">）
  js/  core.js  style.js  api.js  modes.js  subgraph.js  viz.js  panels.js  evidence.js  main.js
```

★ 方案的 §6.1.1 列了 **6 个**模块；实际是 **9 个**。多出的 3 个（`core.js` / `style.js` / `panels.js` 的分离）不是随意拆的：

| 多出的模块 | 为什么要单独一个文件 |
|---|---|
| `core.js` | 把「五态 / 参数 / 合并 / 会话 / 模式判定」抽成**零 DOM 的纯逻辑** ⇒ `node` 可直接 `import` 做**可失败断言**（53 条），无需引入 jsdom/Playwright |
| `style.js` | 配色与形状是**可被跨层比对的真值**（前端 24 种边配色 **==** 规范图实测 24 种 type）⇒ 单独成文件才能被解析比对 |
| （`panels.js` 承担原计划的"面板 + 搜索"） | 与方案一致 |

★ 代价与收益：文件数 +3，换来「不装任何第三方依赖也能对前端做**运行时**断言」。

### 3.2 五态 = **颜色 + 图标 + 文字**三重编码（验收 V8）

| 状态 | 颜色（对深色底对比度） | 图标 | 文字 |
|---|---|---|---|
| `ok` | `#3fb950`（**7.29**:1） | 对勾圆 | 正常 |
| `no_result` | `#8b949e`（**6.02**:1） | 减号圆 | 无结果 |
| `truncated` | `#d29922`（**7.33**:1） | 警示三角 | 已截断 |
| `timeout` | `#f0883e`（**7.31**:1） | 时钟 | 超时 |
| `error` | `#f85149`（**5.52**:1） | 八角叉 | 错误 |

- 五态**颜色两两不同、图标两两不同、文字两两不同**（`F3/F3b/F3c/F25d/F25e/F25f` 六条断言）。
- 对比度全部 ≥ 4.5:1（WCAG AA），由 `F4` 用自实现的 WCAG 公式现算（**不是**写死的结论）。
- 状态行根元素带 `data-state="<status>"`，供 DOM 断言（`S14`）。
- ★ **timeout 用橙红而非纯红**：与 `error` 的真红在色觉上也可分 —— 这是"不只靠颜色"的加强，不是偏离方案（方案要求"超时/错误=红"，橙红属红系）。

### 3.3 视觉编码**分列**（方案 §6.2-7）

| 通道 | 编码什么 |
|---|---|
| 节点**填充色** | 学科（数学/物理/化学/跨学科） |
| 节点**形状** + 描边色 | 类型（Formula/Molecule/Element/… 19 种） |
| 边**颜色** | 语义关系 **`type`**（24 种） |
| 边**线型** | `explicit_or_inferred`（实线/虚线） |
| 边**琥珀色** | `stale`（证据过期） |
| **徽标**（卡片内） | `verification_level`（7 档） |

★ `verification_level` **不上图**（避免与学科/类型/关系抢通道），只在详情卡与证据卡以徽标呈现 —— 这样"可信度"与"优先分"能分别读出。

### 3.4 三条入口 + 概览

| 入口 | 交互 | 端点 |
|---|---|---|
| ① 找点 | 顶部搜索（防抖 180 ms，**过期响应丢弃**防竞态）→ 点候选 → ego 1 跳 | `/api/search` → `/api/subgraph?mode=ego` |
| ② 展开 | 选中节点 → 「＋ 展开邻居」（优先用服务端 `expand_token`） | `/api/subgraph?mode=expand` |
| ③ 问路径 | 起点/终点（可「取选中」）→ 高亮 | `/api/subgraph?mode=path`（**不**用 legacy `/api/path`） |
| ④ 筛一块 | 查询面板 → 生成子图 | `/api/subgraph?mode=filter` |
| ⑤ 概览（降级） | 「概览」→ 聚合元图 → 点块下钻为一次 filter | `/api/overview?mode=aggregate` |

★ **`mode=filter` 无条件时前端先拦**：后端对 `mode=filter&trust=all`（无任何条件）刻意返回 400（防全图倾倒）。
`core.validateParams` 在发请求**之前**就拦住，并把文案渲染成「请至少选一个筛选项（…）——「全图浏览」已取消，全貌请看「概览」」，
而不是让用户看到"系统故障"。★ 这是"刻意 400"在用户侧的落地，也保证 `bad request` 不污染五态。

### 3.5 模式判定：live 绝不碰全图（验收 V1）

```text
① 先探 /api/stats  →  可用 ⇒ 立即 live（**不探测** /graph_data.json）
② 否则（或 ?mode=bundle）→ HEAD /graph_data.json（只要存在性，**不下载** body）
③ 都不可用 ⇒ offline（如实说"没有图数据"，不假装可查询）
```

- `F22` 断言：live 模式的**请求序列里不出现 `graph_data.json`**（mock fetch 记录 URL）。
- `F23/F24/F24b/F24c` 覆盖「后端挂 → 有样例 ⇒ bundle」「都没有 ⇒ offline」「强制 bundle 但样例缺 ⇒ 回落 live（不白屏）」。
- `V1a/V1b` 静态断言：整图加载被 `det.mode === "bundle"` 分支包裹，且只经 `api.bundle()`。

### 3.6 会话记账与硬门（方案 §6.2-3/10）

- `ego` **增量**累加；`filter` / `path` 视为**新视图**（先清零）。
- **恰好等于上限即 `full`** ⇒ 禁用展开按钮 —— 否则会出现"按钮可点但一定失败"的坏状态（`F16b` 断言）。
- 「返回上一层」= 弹栈 + **回滚会话计数** + 由剩余栈项重放合并重建视图（不缓存整图）。
- 前端计数只用于**即时禁用**；`syncFrom(stats.session)` 以**服务端回传值**为准。

### 3.7 「可带走」（替代 Remotion，零新依赖）

PNG（`cy.png`，含 `snapshot_id` 水印）/ SVG（`cy.svg`）/ JSON 快照（子图 + 证据 + `snapshot_id` + `query_hash` + 每步参数 ⇒ 可离线复现同一次查询）。

## 5. ★ 本轮发现并登记的问题（D14–D24）

### D14（最重 · 如实边界）真实浏览器渲染**未实测**
本项目零第三方依赖（§0.1 拒构建链）⇒ **未装 Playwright / jsdom**。
因此**布局、像素、真实交互链路、浏览器计算样式**均**未实测**，自检里记 **SKIP 且不计通过**。
已覆盖的替代证据：**纯逻辑（node 53 条）** + **运行时渲染函数**（五态/横幅真实渲一次）+ 静态结构 + **跨层一致性** + HTTP MIME + 真实响应字段对照。
★ 若评审要判"前端是否真的可用"，请以本报告 §4 的证据链为准；要更强的证据需先引入无头浏览器（属**新依赖**，须另起裁决）。

### D15 旧前端配色表**已漂移**（本轮校正）
旧 `graph_view.html` 的 `EDGE_TYPE_COLOR` 有 **25** 项，其中 `depends_on` / `same_latex_normalized` 在**规范图里已不存在**，
且**缺 `uses_operator`**（实测 11 条）。⇒ 本轮按实测 **24 种**重建，并由 `X1` 断言守住（前端配色键集合 **==** 规范图实测集合）。

### D16 前端验证档 `rank` 数值**原写错**（被跨层断言抓出）
初版 `VERIFICATION_BADGE` 只有 5 档且 `rank` 全错（`rule_checked` 写成 5，正确是 4），并缺 `unverified` / `human_reviewed`。
`X7`（键集合 **+ rank 数值**逐值比对 `queries._RANK`）直接判红 ⇒ 已修。
★ **这条本身就是"跨层断言不是形式主义"的实证**：没有它，这个错误会一路带到生产。

### D17 `detectMode` 未透传 `fetchImpl`（依赖不可注入）
初版 `probeBundle` 静默回落到全局 `fetch` ⇒ 在注入依赖的场景里测出假的"样例不可用"，`F23/F24b` 判红。
⇒ 已改为把 `Api` 的 `fetchImpl` 透传下去。★ 教训：**"能注入"是可测试性的前提**。

### D18 `mode=filter` 无条件 ⇒ 400 是**刻意**的（前端先行拦截）
见 §3.4。前端 `validateParams` 先行拦截 + 可读文案；`D5`（后端报告）在此闭环。

### D19 `bundle` 探测用 HEAD，但服务端仍会**构建**整个 JSON
`do_HEAD → do_GET`（`load_graph_data()`），只是不写 body。⇒ 46 MB 图下探测仍有一次**内存/时间**开销（未优化，登记）。

### D20 `/api/overview` 的 `nodes[]` **没有 `label`**
只有 `{id, subject, type, n_nodes}` ⇒ 前端在渲染前**自行补齐** `label = "学科::类型"`。
若将来要统一投影口径，需改后端（本轮不动后端契约）。

### D21 前端会话计数是**提示性**的，权威在服务端
`filter`/`path` 被前端视为"新视图"重置本地计数 ⇒ 与服务端的模式判断**可能短暂不一致**。
状态行显示的一律是 `stats.session` **服务端回传值**（`syncFrom` 对齐）；前端那份只驱动"按钮是否可点"。

### D22 `pending_frontier` 只是**下界**
`F26b` 断言：横幅必须把它标为"下界"，且**不得**出现「还有 N 个」这类措辞。

### D23 前端边配色与 `X1` 依赖**不入库**的规范图
`06_PoC/etl/normalized.json` 被 `.gitignore` 排除 ⇒ **干净检出下 `X1` 必然 SKIP**（与 D13a 同源）。
`X` 段其余断言只依赖已入库的前端文件与 Python 源码 ⇒ 在干净检出下仍可运行。

### D24 前端静态资源的**行尾**可复现性（本轮已修 + 已实证）
本机 `core.autocrlf=true`，而 `.gitattributes` 原只锁 `*.json`（`-text`）与 `11_真实数据/*.py`（`text eol=lf`）
⇒ **`06_PoC/js/*.js` 与 `graph_view.html` 无属性**：`git checkout`（含 clone）会把 LF 改写成 CRLF，
于是「本机验过的字节 ≠ 检出后的字节」，**铁律 #53 的「逐字节一致」在**前端上不成立。
实测确认：`git checkout -- 06_PoC/js` 后 9 个文件共 **2446 处 CRLF**、体积也随之变化。

**两件事必须分开陈述**（避免把「加固」说成「修缺陷」）：
- **(i) 自检本身对行尾鲁棒 —— 这是实测结论，不是假设。** 把 9 个 js **全部转成 CRLF** 后再跑：
  `bash sttp.sh frontend` ⇒ **仍 PASS 55 / FAIL 0 / SKIP 2**；`node frontend_core_check.mjs` ⇒ **仍 53/0**。
  即 CRLF **不会**导致任何断言失败（正则/分块解析均未隐含依赖 `\n`）。
- **(ii) 仍要锁**：前端是**浏览器逐字节加载**的静态资源 ⇒ 为让「仓库字节 == 检出字节」，
  `.gitattributes` 新增 `06_PoC/js/*.js  text eol=lf` 与 `06_PoC/graph_view.html  text eol=lf`（带同源注释）。
  锁定后重新检出：**9 个文件 CRLF 计数 = 0，且字节数与验过大小时刻完全一致**。

> 供下次评审：本项**不是**未修缺陷，也**不是**导致自检失败的行尾缺陷；它是「可复现性」口径的统一
> （与 D1 的成因同源，但 D1 是**证据哈希**依赖字节、本项是**交付资产**依赖字节；D1 的根因仍**未修**）。
