## 1. D58 · 让「某一步没真正执行」也自述解释器

### 1.1 病灶（登记原文的收窄）

D57（Phase 53）修的是「**缺依赖**」诊断自述解释器；同族的 D58 是「**某一步根本没有执行**
（SKIP）」的场合。两者**语义不同**：前者说「我缺件」，后者说「我没跑」。
Phase 53 只修了前者，把后者登记为 D58，并写明「铁律 **#92**（同一条纪律须覆盖链上每个入口）」。

**实测（本轮第一步就是去数，而不是直接改）**：链上真正会产出「非通过」的入口有 **5 个**：

```
06_PoC/release/verify_release.py          ← 已自述（Phase 53 修的）
06_PoC/frozen_gate.py                     ← ✗ 不自述（D58 本体）
06_PoC/tests/a4_offline_render.py         ← ✗
06_PoC/tests/phase51_task_flow_e2e.py     ← ✗
06_PoC/tests/phase45_install_selfcheck.py ← ✗
```

⇒ **5 个入口只有 1 个自述**。#92 要的就是「不是改一处就完事」。

### 1.2 修法：把文案收成**唯一实现**，五个入口全部引用

新增 `06_PoC/interp_note.py`（**零第三方依赖**，因为它要在「缺依赖」时还能被导入）：

| 函数 | 用途 |

五个入口各自 `import interp_note as IN`（`sys.path.insert(0, HERE)` 后）。
★ `frozen_gate.py` **刻意不套 `try/except`** —— 「连自述实现都导不进来」这种状态**不允许静默**，
必须硬失败（fail-closed）。`verify_release.py` 保留本地名 `interp_note` / `dep_detail`
（转指 `IN.note` / `IN.dep_detail`）⇒ **调用点与既有断言名一字不改**（避免为了重构而改动 #87 的名字集合）。

### 1.3 ★ 防漏网：新增仪器 `interp_selfreport_check.py`（`bash sttp.sh interpcheck`）

只改五处**不叫收口**，叫「这次改全了」。要让它**下次漏了能被抓住**：

  含未跟踪文件（否则「新写的入口还没提交」正好落在盲区里）。

| 断言 | 含义 |

| `Q1b` | 每个声明入口路径真实存在 |

## 2. D64 · 发布链的**时序自锁**（本轮新登记）

### 2.1 病灶

`bash sttp.sh release` 的原次序：

```
[1/4] 重建样例      ← 样例是**被跟踪**文件，重建就会让工作树变脏
[2/4] 生成清单      ← 生成前的前置断言：工作树必须干净（E21）
```

⇒ **只要图谱一变，重建样例就必然脏，前置断言就必然 RC=2**。
更糟的不是失败，而是**失败文案**：它写着「**正确次序 ③ `bash sttp.sh release`**」——
**正是刚刚失败的那一步**。按字面执行 ⇒ 重建 ⇒ 又脏 ⇒ 又失败 ⇒ **必然死循环**。
而「先单独重建样例并提交，再生成清单」这一步**从来没有被写下来过**。

★ 这不是本轮的纸上推演：**Phase 54 现场就踩到过**，当时是**手工绕过**（先把样例提交了事），
**没有登记**。本轮把它补登记为 D64，并**先复现再修**。

### 2.2 复现（旧行为）

向 `06_PoC/etl/normalized.json` 注入一个无害探针 `_phase55_probe`。
★ 选这个文件是因为它**既被 gitignore、又未跟踪** ⇒ 注入它**不污染** `git status --porcelain`
（否则「脏树」判定会因为注入本身而红，复现就不干净了）。

```
[1/4] 重建样例        ⇒ sample_normalized / sample_graph 两个文件变脏（被跟踪）
[2/4] 洁净度前置断言   ⇒ RC=2，**不写清单**
      文案：正确次序 ③ bash sttp.sh release   ← 与刚失败的那一步是同一个
```

两次复现后主图**逐字节还原**并核对：
`sha256 = 21f13596a4c818f74bcbbe16e324507abfa7964d813d3313f17e6e476727205f`。

### 2.3 修法（三层）

**(a) `06_PoC/release/pipeline_outputs.py` —— 发布链产物的唯一事实源（#88）**

| 导出 | 含义 |
|---|---|
| `SAMPLE_DIR_REL` / `SAMPLE_FILENAMES` / `MANIFEST_REL` | 产物的**名字**只在这里写一次 |
| `sample_paths(repo_root, out_dir=None)` | 需检查的产物清单 |
| `git_blob(repo_root, rel)` | `git show HEAD:<rel>` ⇒ **权威字节**来自仓库，不来自工作区 |
| `read_bytes(repo_root, rel)` | 工作区字节（**不做行尾翻译**） |
| `regenerated(repo_root, paths, blob_of=, read_of=)` | 差异清单；两个 `of` 可注入 ⇒ **可构造性测试** |

改之前，`make_sample.py` 与 `make_manifest.py` **各自硬编码**同一份文件名单
（改一处忘一处 = 静默漏检）。现在两边都 `import pipeline_outputs as PO`。
★ 刻意**不**把 `manifest.json` 放进 `regenerated()` 的判据：它每次重建的 `created`
与 `git_head_at_build` 必然变 ⇒ 放进去等于**每次都自红**（详见 §2.5）。

**(b) `--check-regenerated`：新的一步，位于「重建之后、出清单之前」**

`make_manifest.py` 新增 `check_regenerated()`，断言三件：

| 断言 | 含义 |
|---|---|
| `M7` | 产物**声明自证**：非空 / 全在发布目录内 / 全部真实存在 |
| `M9` | ★ **判据非真空**（构造性）：合成两份输入，**「确实不同」必须被报出、「确实相同」必须不被报出** |
| `M8` | 产物**已提交**：与 `HEAD` 逐字节一致 |

失败文案给出**可照抄**的下一步：

```
git add 06_PoC/release/sample && git commit     # 先提交样例
bash sttp.sh release                            # 再重跑（此时树干净，清单才会出）
```

**(c) 次序显式化 + 逐项传退出码**

`sttp.sh release` 改为 **`[0/4]` … `[4/4]`**，每步 `|| exit $?`（铁律 **#62**）：

```
[0/4] 依赖预检          [1/4] 重建样例
[2/4] --check-regenerated（本 Phase 新增）   ← 本步是必需的，不是锦上添花
[3/4] 生成清单          [4/4] 发布校验
```

**(d) `make_sample.py` 侧的反向断言**

三个产物名一律取自 `PO.SAMPLE_FILENAMES`；写入后**反向断言**
（实际写出的文件名集合 ≠ 声明集合 ⇒ `return 3`）。否则「改了声明忘了改写法」两边都不报警。

### 2.4 ★ 刻意**拒绝**的偷懒写法（记下来，防止下一轮有人"优化"掉）

最省事的写法是：**把样例从脏判定里排除**（"反正是自己生成的"）。
**拒绝**。那样做的实质是**放宽 fail-closed** —— 清单会声称 `working_tree_dirty_at_build: false`
而样例其实未提交，**这句话的含义被掏空**。保留两趟、把次序讲清楚，比悄悄弱化判据诚实（铁律 #20 同族）。

### 2.5 ★ 如实评估：`--check-regenerated` 拦得住什么、拦不住什么

- **拦不住**：Phase 54 当时的状态。当时改的是 `normalized.json`（未被跟踪）、**样例没有重建**
  ⇒ 树是干净的 ⇒ `M8` 全绿。**这个补丁并不能"预防" Phase 54 的踩坑。**
- **它的真实价值**是**自我解释性与可执行性**：失败文案不再把人送进死循环，而是给出
  「先 add + commit，再重跑」这一条**唯一正确且可照抄**的下一步。
- **`M9` 的必要性**：`R11` 注入的退化是把 `regenerated()` 换成**恒真空**（永远返回 `[]`）——
  它在输出上与「真的没有差异」**完全不可分**。只有 `M9` 这种**构造性**守卫（喂它一份
  已知不同的输入，断言它必须报出来）能抓到。**这一点不夸大**：没有 `M9`，`--check-regenerated`
  一旦被人改坏，会以「全绿」的样子长期存在。

### 2.6 复现（新行为）

同一次注入之后：

```
[2/4] ⇒ M8 红（"与 HEAD 不同 2 项"）
        并打印可照抄的下一步
[3/4] 不执行（fail-closed）  ⇒ RC=2
```

干净树上 `--check-regenerated` **RC=0**（`M7`/`M9`/`M8` 全绿）。

## 3. D62 · 名字核对工具对「同 ID 家族」的盲区（并把盲区关上）

### 3.1 登记时的认识 vs 实扫到的体量

D62 登记原文只指认**一种成因**：`norm()` 的正则 `^[A-Za-z]{1,4}\d+[a-z]?` **会吞掉尾随数字**
⇒ `F42b2` 与 `F42b` 归一化后同名。

本轮**实扫全部 6 个文件**后，真正的大头是**同家族命名**（与尾随数字无关）：

| 文件 | 条目 | 唯一 ID | 说明 |
|---|---|---|---|
| `phase45_install_selfcheck.py` | **31** | **1** | 全部归成 `A05`（`norm("A05-1 …") == "A05"`） |
| `verify_release.py` | 29 | 16 | 13 个重复 ID 家族（`A3` / `B1` / `C1` / `F1` / `H1` …） |
| 全仓合计 | 约 **88 条**断言 | — | 落在同 ID 家族里 ⇒ ID 层差分对它们**不可靠** |

**后果不是报错，而是静默**：在 `phase45_install_selfcheck.py` 上，
**删掉任何一条断言，`bash sttp.sh names` 都看不见** —— 而这正是 #87 执法工具存在的**唯一理由**。
（Phase 54 真踩到过：采集器报「条目 +9 / 唯一 ID +8」，**这个不一致本身就是信号**，但当时靠**人肉**发现。）

实测输出（本轮证据）：

```
文件: 06_PoC/tests/phase45_install_selfcheck.py
  条目 31→31 ｜ 唯一 ID 1→1
  新增 ID（0）: （无）
  删除 ID（0）: （无）
  ⚠ 1 组同 ID 家族：A05 ⇐ 31 条（唯一 26）；★ 字面重复 {'A05-14 …': 3, 'A05-13 离线 wheel 构建探针': 2, …}
```

### 3.2 判据为什么**不能**是「一遇碰撞就失败」

第一版设计是「有碰撞 ⇒ 退出码 3」。**跑一下就知道不能**：本仓 6 个文件**立刻全部 RC=3**
⇒ `gatecheck` 的 `[0/3]` 当场常红。那是**把噪音当信号**（#90 的镜像错误：全红也会让人开始忽略红）。

故定为三层，**逐层递进**：

| 层 | 做法 | 作用 |
|---|---|---|
| ① | 碰撞**显式列出**（`S7`） | 至少让人知道「这里差分不可靠」 |
| ② | 族内按**全名**补差（`blind_group_changes`，`S7b`） | ★ **这一层才真正把盲区关上**；没有它，①只是承认无能 |
| ③ | 结构性告警 + 建议把 ID 改成互不歧义 | **根治**，但不在本轮（见 D65） |

退出码 `1`（有删除）现在**包含**「族内按全名补报出来的删除」。

### 3.3 ★ 本轮自己踩到、随后关上的**第二层盲区**（`S7c`）

`blind_group_changes()` 第一版用的是**集合**差。跑真实样本时才发现 A05 组里存在
**字面完全重复**的条目（`A05-14 …` ×3、`A05-13 离线 wheel 构建探针` ×2、
`A05-1 pyproject…` ×2、`A05-12a …` ×2；31 条 ⇒ 唯一名 **26**）

⇒ 集合差对「**删掉 3 条重复中的 1 条**」**依然隐形** ——
那只是把盲区从 **ID 层**平移到了**全名层**，**并没有关上**。

改为 `collections.Counter` 的**多重集**差，并加 **`S7c`** 构造性守住：
样本里放两条**字面相同**的断言，删掉其中一条 ⇒ **必须**报出 1 条删除。

> 这条是 #102 的活体案例：**「说出这里不可靠」不等于「把信息补回来了」**。
> 只做前者，读者会以为已经处理过了 —— 比什么都不做**更危险**。

### 3.4 断言 6 → **10**（名字集合逐条核对，删除 0）

| 新增 | 含义 |
|---|---|
| `S7` | 归一化碰撞必须被**显式列出**（条目数 ≠ 唯一 ID 数） |
| `S7b` | 组内补差：同族但**名字不同**的一条被删 ⇒ 必须报出 |
| `S7c` | **重数**补差：**字面重复**条目被删一条 ⇒ 仍必须报出（集合差会漏） |
| `S8` | 负对照：无碰撞 ⇒ 两表皆空（**证明 S7/S7b/S7c 非恒真**） |

★ `S6`（自指）的白名单同步扩到含 `S7/S7b/S7c/S8` ——
**新加的断言若采集不到，本文件就会重演「自己写下的守卫悄悄消失而无人知晓」**（自指的第二次失败）。

### 3.5 顺手订正的**过期陈述**

`norm_collisions()` 的 docstring 还写着「把信号变成断言（`S7`）与**退出码（3）**」——
那是**判据返工前的旧设计**（返工原因见 §3.2）。一并改写，并补上「为什么不直接以碰撞为失败」的理由。
（铁律 **#74** 的同族：过期陈述会被后来者当权威。）

## 5. 铁律候选（拟入候选池，尚未并入 Top 95 正文）

**#102 关掉盲区 = 「说出不可靠」+「把信息补回来」，缺一不可。**
只把「这里不可靠」说出来的补丁**没有关上盲区**，甚至更糟 —— 读者会以为已经处理过了。
构造性证据：本轮的 `S7`（说出）× `S7b`/`S7c`（补回）必须成对；
`S7` 单独存在时，「删掉同族一条」依然无人知晓。

**#103 最难发现的退化是「恒真空」，不是「报错」。**
把判据换成 `return []` 之后，它的输出与「确实没有问题」**逐字节相同**，
任何只看结果的检查（含全绿回归）都抓不到。
同族的「沉默失效」还有一种是**探针锚点命中 0 次**（探针从此什么都不验，也不报警）。
两者必须**分别**接住：`M9`（构造性合成输入）与 `RS`（锚点恰好命中一次）。

**#104 构造性证据必须与它守护的修复同一次提交落地。**
漏带的后果不是编译失败，而是那个提交**失去全部论证** ——
断言名、断言体、全绿回归都还在，**证据已经空了**（#100 的形式还在、内容已空）。
本轮真发生：`R10`/`R11` 本该随 D58/D64 提交，被漏在外面，**补交时才自曝**。
