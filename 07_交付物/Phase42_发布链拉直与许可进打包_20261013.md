## 1. A01 —— 发布链 fail-closed + 逐项退出码

### 1.1 复核为真的缺陷

| 位置 | 缺陷 |
|---|---|
| `sttp.sh` `release-full` / `dimaudit` / `lineage` | 三个分支**多步串跑但无 `set -e`、不传退出码** ⇒ 前一步 FAIL 被后一步 PASS 掩盖 |
| `06_PoC/release/verify_release.py` | `--full` **只核前端快照 sha256，不核规范图（权威图）**，且缺失一律记 `WARN` ⇒ `--release` 下形成 **fail-open** |

### 1.2 修复

- `sttp.sh`：三分支加 `set -e` 并对**每一步显式 `|| exit $?`**；`release-full` 由 2 步细化为「[1/2] 发布校验 → [2/2] 主图门禁」，任一步非零即整体非零。
- `verify_release.py`：新增 **H1b 规范图 `normalized.json` sha256** 校验；`--release` 下所有缺失/不一致改为 **FAIL**（不再有 `warn_only` 放行路径）。

### 1.3 负对照（可红证明）

| 注入 | 期望 | 实测 |
|---|---|---|
| 篡改 `11_真实数据/element_reference.py`（来源内容变更）→ `bash sttp.sh lineage` | 非零 | **RC=1**，命中 `Phase13.Gate.B2/B5`（703 条断言受影响） |
| 伪造 manifest 里规范图 sha256 → `bash sttp.sh release-full` | 非零 | **RC=1**（**H1b FAIL**；H1/H2 仍 PASS、WARN 0 ⇒ 正是「后一步不掩盖前一步」的证据） |

## 2. A02 —— 判分器 / 求解器的输入域守卫

### 2.1 复核为真的缺陷

`12_评测/eval_runner.py::_grade_value` 结构化分支用 `abs(got − exp) > tol` 判错；
`NaN`/`Inf` 参与比较时该式**恒为 False** ⇒ 非有限值被**穿透判为 `correct`**（铁律 **#63**）。

### 2.2 修复

- `_grade_value` 结构化分支：先做**有限性 + 取值域**检查，非有限值**显式判 `incorrect`**（拒绝分支变显式）。
- 求解器输入域：`s_compute_dG_from_K` / `s_compute_K_from_dG` / `s_compute_dG_at_composition` / `s_compute_dG_from_dH_dS` 增 **`T > 0`** 检查；`pKa / Ka / Q / ratio / Kw` 保持 `log_domain` 守卫。
- `--selfcheck` 新增「边界 / 域」段：**22/22 通过**。

### 2.3 负对照（非空证明）

| 输入 | 修复前 | 修复后 |
|---|---|---|
| `NaN` / `Inf` 作为数值答案 | 判 `correct` | 判 **`incorrect`** |
| `T = 0 K` / `T = −298.15` | 照常作答 | **`refuse`** |

## 3. A03 —— 许可进打包（政策由程序执行）

### 3.1 复核为真的缺陷

`make_sample.py` 抽取离线样例时**不看许可**（无白名单、无派生递归），而样例是**入库并分发**的
⇒ 与 `DATA_LICENSES.md` §二「待核对、不入发布包」的承诺不一致。

### 3.2 修复（三段式：登记 → 打包 → 复查）

**① 三态登记（唯一权威）→ `11_真实数据/source_registry.py`**

- 新增机器可读再分发三态 `REDISTRIBUTABLE / INTERNAL_ONLY / FORBIDDEN`；
- `redistribution_closure(sid)`：**血缘闭包取上游最严者**（派生对象不得比上游宽松 —— 即「派生递归」）；
- 未列出 / 未登记 ⇒ **`FORBIDDEN`（fail-closed，不猜测）**；
- 自检由 7 条扩到 **10 条**，新增：**⑧** 三态表覆盖全部 31 来源（含唯一性/合法值）、**⑨** 派生 ≤ 上游严格度、**⑩** 与 `DATA_LICENSES.md` 文本不脱钩。
- 结果：31 来源中**血缘闭包 = 可再分发 16 个**。

**② 打包过滤 → `06_PoC/release/make_sample.py`**

- 新增 `--profile {public_demo, internal_research}`，**默认 `public_demo`**（发布物必须用它）：
  只保留「**边来源 + 两端节点来源**」的血缘闭包均为 `redistributable` 的边；
  **缺 `props.source` ⇒ 视为不可再分发**（fail-closed）。
- 新增 `--selfcheck`：**合成图注入 12 条**（未登记来源 / 缺来源 / `internal_only` 必须**真被剔除**；`internal_research` 必须不过滤）⇒ 判据**非真空**（独立于真实样例，铁律 #14）。
- 后置审计 `audit_redistribution()`：对保留集**独立重算**，残留违规即 **RC=4**。

**③ 发布复查 → `06_PoC/release/verify_release.py`**

- **A4** manifest 声明的 `license.profile` 必须 = `public_demo`；
- **A5** **独立重算**样例内每条边 / 每个节点的来源血缘闭包（**不听构建器自述**），违规数必须为 0；
- **A6** 剔除计数已登记且**非真空**（0 边 ⇒ 白名单形同虚设）。

### 3.3 结果（如实披露）

| 项 | 值 |
|---|---|
| 全图 | 9657 节点 / 48712 边 |
| **剔除** | **43295 边 / 6820 节点**（22 个边来源、10 个节点来源） |
| 保留（public_demo 样例） | **170 节点 / 255 边**（跨学科边 36；物理 103 / 化学 49 / 数学 18） |
| 后置审计违规 | **0** |
| `internal_research` 样例（不发布） | 380 节点 / 701 边（与 Phase 37 一致，未回归） |
| 发布校验断言 | **28 条**（`--full` **31 条**），FAIL 0 / WARN 0 |

**为什么样例只剩 170 节点**：头两大来源 `PhysicsBabel`（24104 边）与 `ElementKG2.0`（7797 边）
在 `DATA_LICENSES.md` §二里是「条款未见明示 ⇒ 待核对、不入发布包」，`chembl_api`（CC BY-SA 3.0）
与 `Phase13.Gate.B*`（上游 PhysicsBabel）同为受限 ⇒ 按政策只能剔除。
**这是政策生效后的真实可分发规模，不是缺陷**；`internal_research` profile 保留了完整的 380/701 供内部复现。

### 3.4 负对照（可红证明）

| `source_registry.py --check` | 全过 | **10/10**（注入反例时 ⑧⑨⑩ 分别精确报错） |

### 3.5 顺带暴露的残留问题（已登记，未在本轮修）

- 节点 `props.source` 存在 **5 个未登记/畸形字符串**：`ek`、`pb`、`wd`、`llm_hypothesis`、
  `dimension_table(algebra: entropy/amount) 派生`（共 22 个节点）。前四者是**短名别名未归一**
  （cf. 铁律 #39「命名缺口架空验证器」）；最后一个疑似**来源字段被写入散文**。
  在 fail-closed 下这些节点**永不可发布** ⇒ 已列为后续「命名对齐」工单输入。
- 边来源计数 `excluded_by_source` 以**边自身来源**为键；一条可再分发来源的边仍可能因**端点受限**被剔除
  （如 `ChEBI` 5092 条大部分因端点是 PhysicsBabel）。解读时须与节点来源表并看。
