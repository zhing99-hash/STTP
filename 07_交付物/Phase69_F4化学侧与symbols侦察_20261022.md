## 二、F4 · 化学侧

### 2.1 规模与字段现状

图内化学侧节点：**Molecule 2,133 ｜ Reaction 1,708 ｜ FunctionalGroup 76 ｜ Element 118**（总 9,750）。

### 2.2 SMILES：两个字段并存，口径没定死

| 字段 | 覆盖 | 说明 |
|---|---|---|
| `canonical_smiles` | **2,086 / 2,133 = 97.8%** | 标准 canonical 写法（`C1=CC=C(C=C1)C(CN)O`） |
| `smiles` | **22 / 2,133 = 1.0%** | 只有 22 条，且与上者**不重叠** |

★ 门槛只写「SMILES ≥ 90%」，**没说算哪个字段**。按 `smiles` 算就是 1.0%（看起来要补 1,911 条），
按 `canonical_smiles` 算就是 97.8%（**已经达标**）。这是 D100 同族：**一句没有判据的陈述**，
在化学侧的表现形式是「同一个概念有两个字段，没人规定哪个是权威」。

47 条缺 `canonical_smiles` 的构成值得单独看：
`MX:chem:co2` / `MX:chem:methane` / **`MX:chem:combustion`**（source=`llm_hypothesis`）、
`MO:ch4` / `MO:o2`（curated_seed，有 `smiles` 无 `canonical_smiles`）。
其中 **"combustion" 是反应不是分子** —— 它本就不该有 SMILES，却在分母里。

### 2.3 Reaction 名称：**不可达**（核心结论）

按 source 拆开，缺口高度集中：

| source | 条数 | 有 name | 有 equation |
|---|---|---:|---:|
| Rhea | 939 | **939 (100%)** | 939 |
| ElementKG2.0 | 758 | **0 (0%)** | 0 |
| curated_seed | 11 | 11 (100%) | 11 |

**缺的 758 条全部来自 ElementKG2.0。** 顺次排除三条可能的补救路径：

**① 是不是 ETL 漏抽？—— 不是，源头就没有。**
查 `11_真实数据/elementkg10m_raw.json`（1,602 节点 / 800 个 Reaction）：
Reaction 节点的**字段里有 `name`，但 800 条值全是 `None`**。
所以这不是「数据在那儿没取回来」，是**数据源本身不给反应起名字**。

**② 能不能从 SMILES 反推参与物？—— 认不出。**
758 条里只有 **148 条含反应箭头 `>>`**，**610 条（80.5%）连方向都没有**
（不知道谁是反应物、谁是产物，无法拼 `A + B → C`）。
且 ElementKG 用的是带原子映射的显式氢写法（`[CH:1]1[C:11]2...`），与 canonical SMILES 是两套表示。
用 RDKit 2026.09.1 剥映射并 canonicalize 后实测：

```
抽样 400 条 EK 反应：
  分子片段总数 1439，可识别 400 (27.8%)
  反应级：全部认出 0 ｜ 部分认出 218 ｜ 一个都认不出 182
```

**反应级「全部认出」是 0 条** —— 没有一条反应的所有参与物都能被认出来。

**③ 能不能从图边补？—— 只有 59 条拼得出来。**
这里有个反转：758 条 EK 反应**全部有出边到 Molecule**
（`reagent_of` 1,807 / `reactant_of` 636 / `product_of` 71），图结构其实知道谁参与了反应。
但按「反应物 + 产物」是否齐备分：

| reactant_of ＼ product_of | P=0 | P>0 |
|---|---:|---:|
| **R>0** | 446 | **59** |
| **R=0** | 241 | 12 |

**同时有反应物和产物边的只有 59 条（7.8%）** —— 只有这 59 条能拼出完整名字，
例如 `N,N-dimethylformamide → 4,5,6,7-tetrahydro-1H-indole-2-carbaldehyde`。

**可达上限**：950 + 59 = **1,009 / 1,708 = 59.1%**。
要够到 95%（1,623 条）还差 **614 条**，而这 614 条**没有任何可靠依据** ——
它们既没有名字来源，也常常没有反应方向，参与物还大半认不出来。

> ★ 与 F3（applicability 目标 1,500 不可达）**完全同构**：
> 门槛 95% 会把「给 614 条凭空起名字」奖励成达标。
> 区别只在于 F3 是做完后才发现，F4 这次是**在侦察阶段拦下的**。

### 2.4 化学计量：同源同缺口

`n_reactants` / `n_products` / `rhea_id` 都是 **939 条**（= Rhea 那一批），
`equation` 也是 939 —— 与 Reaction name **同一批节点、同一个缺口**。
补化学计量与补名称是同一件事的两面，不会各自独立变好。

### 2.5 化学侧判据覆盖：**零**

- `red_probe.py`：无任何化学相关探针（chem / mol / rxn / smiles / reaction 均无条目）
- `gatecheck` / `frontend`：无 SMILES 或 Molecule 相关断言
- 也就是说 F4 的三条验收**目前没有任何机器在咬** —— 报告里写多少就是多少。

## 三、C · 82 条空 symbols

### 3.1 构成

| 项 | 数 |
|---|---|
| 空 symbols | **82 / 5,090**（1.61%） |
| 其中有 `latex` | **81** |
| 其中有 `symbol_table` | **78** |
| 其中 latex 含等号 | 70 |

学科分布分散（physics.mechanics 8 / math.numbertheory 9 / chem.acidbase 6 …），
id 前缀 CE 13 / NT 9 / CM 6 / TH 6 / EM 6 —— **不是某一批数据的集中故障**。

### 3.2 关键发现：符号其实已经推出来了

```
FO:emc2 | latex = E=mc^2
   symbols              = []            ← 空
   symbols_rule_version = s2            ← 规则跑过
   symbols_source       = None
   symbol_table         = [{"sym":"c","quantity":"c (speed of light)","src":"edge_target"},
                           {"sym":"E",...}, {"sym":"m",...}]   ← 三个符号都在
```

`F=ma`、`F=G m₁m₂/r²` 同样：`symbol_table` 里有完整符号，`symbols` 却是空列表。

**所以这不是「推不出符号」，是「推出来了但没写回 `symbols` 字段」。**
两个字段同源（都来自 s2 规则），只有一个被填 —— 与 D102（两套实现口径漂移）同族。

★ 这修正了我 2026-10-21 的判断。当时我说「可能牵动 Phase 61 推导规则本身」，
实测证明**规则没问题，问题在派生写回**，修复面比预估小得多。

### 3.3 另有一条空壳

`pb:newton_second`：**无 latex、无 name**，只有 `applicability_status` / `discoverer` 等。
它挂着 Formula 标签却不是公式，**不该待在 5,090 的分母里**。

| Reaction 三态覆盖 | 无 | **1,708 / 1,708** | `named_from_source` 950 ／ `derived_from_edges` 59 ／ `unnamed_no_evidence` 699 |

三态覆盖全部反应是有意为之：**「没标状态」会被读成「没查过」**（D101 同族），
所以 950 条源头有名的也必须标上 `named_from_source`，即便名字本身不动。

**`symbols` 排序规则（侦察 V4，落地时照此实现）**：按符号在 `latex` 中**首次出现位置**排序，
不是 `symbol_table` 的顺序（4,999/5,000 条顺序不同）。自检 S1 用这条规则对
5,000 条历史数据重算，**重现 5000/5000** —— 证明规则是量出来的，不是猜的。

**12 条标 `symbols_incomplete`**：它们的 `symbol_table` 里有 `sym=null`
（`reason: glyph_not_in_formula` —— 量识别出来了，但字形在公式里找不到，规则故意不指定）。
这些符号**没有补**，只在节点上标了"不完整"和未确定条数。
★ 不完整 ≠ 完整：补了 3 个符号却不说"还有 1 个没确定"，读者会以为这个公式的符号全齐了。

### 实施中交的学费（4 条，全部记入通律）

1. **#107 · 判据不许把「未确定」当成「缺失」。** C1 第一版把 `sym=null` 用 `str()`
   转成 `'None'` 算进符号集合 ⇒ 12 条「越界」报红。照着修的唯一出路是把 `null` 写成
   `'None'` —— 那是编造。改为：判据跳过 null，另标 `symbols_incomplete`。
2. **#108 · delta 判据要看「合并后的最终态」，不能看「本轮产出」。** C4 第一版写
   「本轮 `sym_derived > 0`」：重跑时已补过的不再产出 ⇒ 判据误报红，而数据其实是对的。
   delta 必须幂等：同一份输入跑两次，结论一致。
3. **#110 · 判据的打印格式与锚点位置，都是接口。**
   - selfcheck 打印裸 `FAIL S1`，而 `red_probe` 只认 `[FAIL]`/`❌` 行 ⇒ **判据确实红了，
     但探针看不见**，R34/R35 报「没变红」。改成 `[PASS]/[FAIL]` 后立刻通过。
   - `report_number_check` 的 S3 把负对照锚点写死成 `**5,008 / 5,090 = 98.39%**`，
     本轮把数字提到 99.82% 后锚点落空；落空后 `return 1` 又把 S2 挡掉 ⇒
     **R32 以「没变红」的形式假红**。改成动态取锚点（解析当前值，再改成与它不同的值）。
4. **#109 · 门槛达不达得到，要在动工前量出来。** 见 §二。
