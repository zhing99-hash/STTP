### 3.3 失效机制 —— `11_真实数据/lineage_invalidation.py`

**来源变更 → 定位受影响断言 → 重新验证**：

1. 对每个来源**重算当前内容哈希**，与证据里记录的 `src_hash` 比对；
2. 不等 ⇒ 该来源**已变更** ⇒ 所有 `evidence[*].src == 该来源` 的边为**待重验**；
3. **血缘传递**：若下游来源 `imports_from` 已变更来源，其断言一并受影响；
4. `--reverify` 对受影响边在新图上重跑 `classify_all`，报告档位变化；
5. `--selfcheck` **变异注入**自检（见 §4）；有已变更来源 → **非零退出**（可接 CI）。

**当前实测**：已变更来源 0 ⇒ 受影响断言 0（预期：刚记录哈希）。
**⚠ 血缘缺口**：7 个来源（6 个模型 + 哨兵）⇒ **116 条断言无法传递失效**（如实披露）。

### 4.4 收尾期发现并修掉的两处**自身缺陷**（对照 #43 / #53）

复现包落地时按 #46「先全量预演再落地」做收尾，发现并修掉两处**本轮引入的**缺陷：

**（一）delta 携带冗余 props → 推送超时。** `phase41_lineage_delta` 原先把**每条边的完整 `props`**
写进 delta（47.3 MB）。但 `apply_delta.py` 对 props 是**浅合并**（`merged.update(delta.props)`），
未出现于 delta 的键本就会原样保留 ⇒ 全量 props 纯属冗余。
改法：只交付**真正改动的键**（实测恰为 `verification_evidence` / `source` / `source_inferred_from`
三个），生成器新增 `--base` 指向变更前基线（`normalized.before_lineage.json`）。
**体积 49.6 MB → 25.9 MB（−48%）**，且经**全量等价性验证**：

| 验证 | 结果 |
|---|---|
| `before_lineage ⊕ slim` vs 当前图：**逐边 props 不一致数** | **0 / 48 712** |
| 同上：节点不一致数 | **0 / 9 657** |
| 对当前图复跑 `apply_delta --dry` | 边 **更新 0 / 已存在 48 712**（幂等） |

> **瘦身后的 delta 仍不入库**（`.gitignore`）：本机到 GitHub 上行实测 **≈ 4 KB/s**
> （100 KB POST 用 26.5 s），服务端 **约 49 s** 回 `HTTP 408` ⇒ 单个提交的 pack 增量必须 **≲ 100 KB**。
> 实测：含 delta 的 pack 715 KB（POST 后 49 s → **408**）；不含 delta 的同一批改动 pack **68 KB**（**15.7 s 推送成功**）
> —— 隔离实验已坐实「唯一差异即该 26 MB 对象」。SSH 22 端口关闭、SSH-443 无密钥、代理 10808 仅 6.5 KB/s，均不可解。
> 故按既有惯例（`*_aura_delta.json` 同样不入库）把**大体积派生 delta 留本地**，
> 由 `phase41_lineage_delta.py --base <Phase 41 前基线>` **确定性重算**（该基线本就不在仓库内，
> 该 delta 在干净 clone 处**本就不可能重放**，入库只具存档意义）。

**（二）★被登记为 locator 的源码未锁行尾 → 干净 clone 上哈希漂移。**
登记表的 `content_hash` 与每条证据的 `src_hash` 都是「**文件原始字节的 sha256**」。
但 `.gitattributes` 当时只锁了 `*.json`（#53 为「发布产物」而设），而 **6 个 locator 指向 `.py`**
（`element_reference.py` / `dimension_table.py` / `si_base_table.py`）。
本机 `core.autocrlf=true` ⇒ 干净 clone 会把它们变成 CRLF ⇒
**「重算哈希 == 存档哈希」必然不成立** ⇒ 失效机制会把**未改动的来源误判为已变更** ⇒
R10 的完成定义（「来源变更能定位受影响断言」）在克隆环境**当场失效**。

- 修：`.gitattributes` 增 `11_真实数据/*.py  text eol=lf`（**零重归一化噪声**：这 3 个文件本就 `i/lf w/lf`）。
- 守：`source_registry.selfcheck()` 增两条**可红**判据 ——
  ⑥ `check_locator_stability()`（每个 locator 必须匹配已锁行尾的 glob）
  ⑦ `check_gitattributes_declares()`（`.gitattributes` 必须**真的声明**这些锁，防「判据与配置脱钩」）。
- 非真空证明：删掉 `.gitattributes` 那行 → ⑦ **FAIL 缺 `['11_真实数据/*.py']`**；
  临时把 `BYTE_STABLE_GLOBS` 收窄为 `('*.json','*.lock')` → ⑥ **精确命中那 6 条 locator**。
- **干净检出正/负对照（铁律 #53 的实跑，`core.autocrlf=true`，本地 `--no-hardlinks` clone）**：

  | 检出点 | `element_reference.py` 行尾 | 重算 `content_hash` vs 存档 | `source_registry.py --check` |
  |---|---|---|---|
  | **`6d0c41a`（修复前）** | **★ CRLF**（`i/lf w/crlf`） | **不匹配**（逐字节已变） | — |
  | **`69835ea`（修复后）** | **LF**（`attr/text eol=lf`） | **5/5 全部 MATCH** | **7/7 PASS** |

  > 注：负对照必须**强制重新物化**（`rm` + `git checkout -f --`）—— 直接 `git checkout <旧提交>` 时
  > 该文件两版**内容相同**，git 不会重写它，行尾仍是首次检出时的值，会让「修复前」假通过。

> 与 #53 同源：**哈希要可复现，前提是被哈希的字节本身可复现**。#53 管的是发布产物，
> #61 把它推广到**一切被登记为证据输入的字节**。

## 5. 诚实边界

1. **`src` 是「断言的提出者来源」**，不是「验证所消费的第二来源」。后者在 `detail` / `verifier`
   中已有描述，但本轮**未拆成结构化字段** —— 因为无法机械确证每一次复算读了哪个源的哪一版。
2. **无 locator 的来源 9 个**（6 个模型 + `wikidata` + `schema-axiom` + 哨兵）**无内容哈希**
   ⇒ 这些断言**不参与失效检测**，已如实计数，不计入「已覆盖」。
3. **血缘缺口 7 个来源 / 116 条断言**：模型产物的训练快照版本从未记录，**无法传递失效**。
   这是 R10 暴露的**真实欠账**，不是本轮能补齐的（需回溯每轮训练所用快照，已不可考）。
4. **`upstream` 只登记有据可依的关系**（verifier 字面可查）；不确定者置 `lineage_recorded=False`，
   **不猜测**。
5. **失效检测的强度受限于「原始文件是否留存」**：`*_raw.json` 部分不入库（见 `DATA_LICENSES.md`），
   在干净检出（clone）处这些来源无哈希可算 ⇒ 登记表自检在 clone 处会少 20 个可哈希来源。
   同理 **`06_PoC/etl/normalized.json` 不入库** ⇒ 干净 clone **无法直接跑** `sttp.sh lineage`；
   克隆处的行尾稳定性由 §4.4（二）的两条判据静态守住，而非靠实跑一遍。
6. **R10 是 P2**：不改变「99.6% 是规则门槛达标率、不是跨域任务正确率」的既有披露。
7. **Aura 未推送**：Phase 40（字段迁移）+ Phase 41（血缘）两次 delta 已落盘
   （`06_PoC/etl/neo4j/phase4*_*.json`），**待属性维对账器就绪后批量推送**（
   `reconcile_aura_edges.py` 属性维对账 + 非零退出仍是待办）。
8. **`phase41_lineage_delta.json` 不入库**（26 MB 派生中间产物，理由见 §4.4）⇒
   仓库里**没有**这一步的逐条存档；**能追溯的是生成器 + 报告 §3.2/§4.4 + delta `meta`**，
   不是「任意克隆都能复算出同一份 delta」（该基线图本就不在库内）。

## 6. 沉淀（新铁律）

* **#59 证据的「来源身份」必须与证据同时落库**（`source_id` + `version` + **内容哈希** +
  `verifier_version`），否则「来源变更 → 定位受影响断言」在**结构上不可能**。
  ★ **`impl`（谁验的）≠ `src`（读的是哪个源、哪个版本）** —— 只记验证器名会让证据在来源变更时**不可定位**。
* **#60 能传递才叫血缘**：来源表必须记录 `imports_from` 且**无环**；对**无法传递**的依赖
  （如模型产物的训练快照版本未记录）必须**显式计为缺口**，**不得默认纳入**已覆盖。
  ★ 判据必须**非真空**：用「变异注入 → 恰好标记该来源的断言 + 纯血缘传递」证明，而非只看「0 条受影响」。
* **#61 哈希要可复现，前提是被哈希的字节本身可复现**（#53 的推广）：
  凡被登记为「证据输入」的文件，必须与发布产物同等锁行尾；否则
  `content_hash` / `src_hash` 只是**本机字节**的哈希，在 clone 上会把**未改动的来源误判为已变更**。
  ★ 判据要**连配置一起断言**（`check_locator_stability` **+** `check_gitattributes_declares`），
  否则「检查项」与「实际配置」脱钩，判据会变成空转。
