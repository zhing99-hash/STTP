## 1. 问题

同一元素在图谱里最多有 **3 个节点**，来自 5 个命名空间：

| 命名空间 | 数量 | 来源 | 字段数 | 说明 |
| --- | --- | --- | --- | --- |
| `EK:el:<Symbol>` | 118 | ElementKG2.0 | 23~26 | **符号全覆盖，属性最富**（周期、族、电负性、态…） |
| `EK2:el:<Symbol>` | 13 | ElementKG2.0 | 12 | **同源的第二次重复导入**（带 `ek_atomic_raw` 等 raw 字段） |
| `EL:<小写符号>` | 3 | curated_seed | 13 | H / C / O 骨架，带 `period` / `group` |
| `IC:el:<英文名>` | 3 | curated_seed | 12 | Cl / Na / Fe 骨架 |
| `BC:el:<英文名>` | 1 | curated_seed | 12 | N 骨架 |

**15 个符号有 2~3 个节点，共 20 个冗余节点。** 实际危害有三：

1. **`composed_of`（分子组成）被打散**。C/H/O 的组成边指向 `EL:*`、N 指向 `BC:*`、其余多指向 `EK:el:*` —— 查询与推理必须先做 `same_as` 跳转才能拼出完整分子式。
2. **GNN 嵌入被稀释**。同一元素有多个嵌入，训练信号分裂。
3. **`same_as` 被用错**（见 §4，最严重）。

---

## 2. 策略：规范化合并（canonicalization）

选 `EK:el:<Symbol>` 作为唯一规范节点，依据是三条硬事实：

- **覆盖完整**：118 个节点对应 118 个唯一符号，无遗漏；
- **命名自洽**：`id == "EK:el:" + props.symbol`，118/118 严格成立，可作确定性规则；
- **属性最富**：23~26 字段，是其他命名空间的 2 倍，合并时天然作为「优先方」。

合并流水线（`normalize_elements.py`）：

```
1. 选规范节点      symbol -> EK:el:<Symbol>
2. 属性并集        规范节点优先、别名补缺（记录 same_as_aliases / alias_sources / merged_node_count）
3. 边端点重定向    别名 -> 规范节点
4. 丢自环 + 丢跨符号 same_as
5. 按 (source,type,target) 去重并合并属性（保留 merged_edge_ids / merged_kinds）
6. 重写涉及别名的边 id 并兜底去重
7. 删除别名节点
8. 产出 Aura delta（nodes / delete_nodes / edges / delete_edges）
```

`--dry-run` 为默认行为，`--apply` 才落盘（落盘前自动备份到 `normalized.before_elemmerge.json`）。

## 4. 关键发现：A2 的 GNN 在**不同元素之间**猜出了 `same_as`

`same_as` 的语义是「两个节点指同一实体」。**不同元素符号之间绝不成立。** 但 A2 产出的边里有 13 条是这样：

```
EK:el:Cl --same_as--> EK:el:O     ← 氯 = 氧？错
EK:el:N  --same_as--> EK:el:H     ← 氮 = 氢？错
EK:el:Na --same_as--> EK:el:C
EK:el:H  --same_as--> EK:el:C
EK:el:O  --same_as--> EK:el:H     （共 13 条，全部 kind=gnn_typed_inferred）
```

来源链路：`gnn_infer.py` 的 Part A 对候选对调用 `gate_check()`；Element×Element 分支**只判同周期/同族**，两者都不满足时返回 `None`；Part A 落到 `else` 分支，**直接采信 GNN 的类型预测 `same_as`** 并入库。

触发条件很隐蔽：`EL:c` / `EL:h` / `EL:o` / `BC:el:nitrogen` 这几个别名节点因挂着大量 `composed_of` 入边（分别是 661 / 670 / 503 / 375 条），在图上呈"超级枢纽"形态，嵌入高度相似 → ComplEx 对 `same_as` 打分偏高。

### 4.1 双重修复

- **清存量**：本轮合并时显式丢弃 **13 条** 跨符号 `same_as`，并记入 Aura delta 的 `delete_edges`。
- **堵增量**（`gnn_infer.py` 第 516 行起）：门控加硬约束——元素符号不同且既不同周期也不同族时，返回 `REJECTED` 而非 `None`，Part A 会因此跳过；同符号跨命名空间则返回 `VERIFIED` 的 `same_as`。

> 注：门控修复只做了语法校验，未重跑 150 epoch 重训验证（重训成本高，且存量错边已清）。下次重训时会自然生效。

## 6. 顺带修掉的两个服务端缺陷

本轮在验证阶段踩到并修复了两个**与 A5 无关但影响运维**的真问题。

### 6.1 `graph_export.py` 在 import 时替换 `sys.stdout`，会让服务全局失联

原实现：

```python
sys.stdout = io.TextIOWrapper(sys.stdout.buffer, encoding="utf-8", errors="replace")
```

这是经典的 **GC 关闭底层 fd** 陷阱：新 wrapper 接管同一个 `buffer`，旧 wrapper 失去引用被 GC 时**连带关闭底层文件描述符**，此后进程内所有 `print` 抛 `ValueError: I/O operation on closed file`。

`viz_server.py` 在 `/api/stats` 里 `import graph_export`（本轮 A3 的类型口径修复引入），于是**第一个 `/api/stats` 请求之后，服务对所有请求都返回空响应、连访问日志都打不出来**（`_send` → `log_request` → `print` 抛异常）。排查过程：`netstat` 显示在监听、`curl` 返回 `HTTP 000 empty reply`、服务日志里 `/api/stats` 一行都没有。

改为原地改编码：

```python
for _stream in (sys.stdout, sys.stderr):
    try:
        _stream.reconfigure(encoding="utf-8", errors="replace")   # 不替换对象，无 GC 副作用
    except Exception:
        pass
```

### 6.2 `/api/stats` 的类型分布与快照对不上

`viz_server.py` 的统计直接用 `labels[0]`，但图里 **1658 个节点的 labels 是 `["Entity", "Reaction"]`** —— 首标签恒为 `Entity`，于是 Reaction/Molecule/Symbol 全被统计成 `Entity`，与 `graph_data_phaseNN.json` 的类型分布对不上。改为调用权威转换器的 `graph_export.pick_type()`（走 `TYPE_PRIORITY`）：

```
修复前  Entity 1658 · Element 118（其余类型被吞）
修复后  Formula 5059 · Reaction 809 · Molecule 753 · Element 118 · PhysicalQuantity 105 · Symbol 96 · FunctionalGroup 76 · Unit 33
```
