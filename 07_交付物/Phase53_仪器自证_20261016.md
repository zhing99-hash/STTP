## 2. D55 · 新增构造性可红性仪器 `06_PoC/tests/red_probe.py`

### 2.1 为什么必须新增一台仪器

`bash sttp.sh names` 核对的是**名字集合**，它证明"没有断言被删"。但一次静默退化可以长成这样：

```python
rep.add(True, "F37k 端点客户端预算 == 契约 client_budget_ms", "")   # 判据被换成恒真
```

名字没变、总数没变、`names` 报"删除 0" —— 而这条断言从此**永远绿**。
这不是假想：#87 的动机场景（"加 2 删 1"）只是它的**弱化版**（至少还有"删"这个动作可捕）；
"判据被换掉"连动作都不可见。

### 2.2 做法

对**关键断言**逐个注入"已知缺陷"，断言**目标断言必须真的变红**：

```
突变事实源（产品/工具） → 跑该断言所在仪器 → 目标断言必须 [FAIL] → 逐字节还原
```

若某条断言的判据被换掉 / 被短路 / 被删（只是名字还在），注入缺陷后它**不会变红** ⇒ 仪器 FAIL。
**第一个报出来的人是它，而不是三个月后的评审。**

★ 这是"仪器的仪器"的**第三种**，三者互补：

| 仪器 | 注入什么 | 证明什么 |
|---|---|---|
| `gatecheck`（`_gate_selfcheck_phase31.py`） | 假**边** | 不变量**有能力红** |
| `assert_name_diff --selfcheck`（S1–S6） | 已知**答案** | 核对器**会数**（含"总数不变但实删"） |
| **`red_probe.py`** | 已知**缺陷** | 关键断言**有能力红**，且判据**没被换掉** |

### 2.3 注册表（v1，7 条）

| ID | 类型 | 注入 | 期望 |
|---|---|---|---|
| R1 | mutate | `core.js` `ENDPOINT_CLIENT_BUDGET_MS.search` 3000→**9999** | `F37k` 变红 |
| R2 | mutate | `core.js` 去掉 `put("snapshot_id", …)` | `F37h` 变红 |
| R3 | mutate | `assert_name_diff.diff_pair` 的 `removed` 改成**恒空** | `S2` 变红（#87 的原始动机） |
| R4 | mutate | `verify_release.dep_detail` **丢掉解释器** | `G3` 变红（D57 的常驻守卫） |
| R5 | expect | 跑 `a4_offline_render.py --url http://127.0.0.1:1/` | **RC=2** 且打印前置自述（D56） |
| R6 | expect | 跑 `phase51_task_flow_e2e.py --url http://127.0.0.1:1/` | **RC=2** 且打印前置自述（D56） |
| RN | mutate | `core.js` 追加**纯注释**一行 | **零 FAIL、RC=0**（负对照） |

两条 `expect` 探针**不改文件** —— 它们注入的是"**已知前置缺失**"，验的是**退出码纪律**：
前置缺失必须非 0。这与 mutate 探针是同一个思想（"注入已知坏东西，看判据真不真会红"）。

仪器自身还有三条自检（也是可采集的断言行）：

- **RS 锚点自检**：注册表每条 mutate 探针的锚点在当前事实源里**恰好命中一次**
  —— 锚点会随事实源演进而漂移，而"探针过期"与"断言死了"**必须分开报**（#74）。
  覆盖**整个注册表**，不受 `--only` 影响。
- **RR 还原自检**：被碰过的文件**逐字节**等于初始内容（#97：不许弄脏工作树）。
- **R0 注册表自检**：ID 序列 / 唯一性 / 字段齐备与源码里的字面量声明一致。

### 2.4 安全（不许弄脏工作树）

- 每条 mutate 探针**独立备份 + `try/finally` 逐字节还原 + sha256 校验**；
  **还原失败 ⇒ 立刻中止并 RC=3** 且显式告警（不静默继续、不让污染扩散）。
- 读文件一律 `newline=""`（**不做行尾翻译**）—— 还原必须逐字节一致，CRLF 也不能被改写。
- 实测：`RR` 报"被碰过 3 个文件；全部逐字节一致"，跑完 `git status` 对这三个文件**为空**
  （`core.js` / `assert_name_diff.py` 完全不出现在 `git status` 里）。

### 2.5 退出码

`0` 全部按预期变红 ／ `1` 有探针**没变红**（判据可能已被换掉）／
`2` 缺前置（node / playwright，记 SKIP **不计通过**）／ `3` 还原失败（工作树可能已被污染）。

### 2.6 接线（同时进两个入口）

- 独立目标：`bash sttp.sh redprobe [--only R1,R4] [--list] [--json OUT]`
- **挂进 `gatecheck`** 的 `[1/2]` 步，并**刻意放在 `require_authority` 之前**
  （它不依赖权威图 ⇒ 干净检出里也能跑）—— 与上一轮 `assert_name_diff --selfcheck` 同一考虑。
  实测 15 s，代价可接受。

### 2.7 断言可采集性（#98：执法工具自身必须在被执法的集合里）

本仪器是"防判据被换掉"的工具，**它自己的断言若采集不到，它就可以悄悄退化而无人知晓**。
采集器（`assert_name_diff.collect`）取的是「`rep.add(...)` 的**第 2 个实参**，
且必须是**字符串常量**或**以字面量开头的 f-string**」⇒ 断言名必须写成**字面量**。
故 `emit()` 里 **10 行断言名全部写死**，并由 **R0** 断言注册表 ID 与声明一致
（防止"注册表改了、断言行忘改"静默）。实测 `bash sttp.sh names`（旧侧为空文件）采集到 **10 条 ID**。

## 3. ★ 本轮的意外强证据：新仪器**首跑即抓到 D56 的真缺陷**

`red_probe.py` 写完、`R6` 注册好之后，**第一次完整运行**（D56 尚未修）的输出是：

```
  [PASS] R5 页面不可达 ⇒ offline 必须 RC=2 且自述前置（D56）
         RC=2（期望 2）；前置自述已打印
  [FAIL] R6 viz 未跑 ⇒ taskflow 必须 RC=2 且自述前置（D56）
         RC=0（期望 2）；输出缺：前置 ★ 前置缺失却返回 0 ⇒ **SKIP 与 PASS 在退出码上不可分**（#101）
  red_probe: PASS 9 / FAIL 1 / SKIP 0

```

这一条的价值有三层：

1. **它证明这台仪器不是空转** —— 它不是"注册表写好了、全绿"的那种自证（#90 的反面）：
   它在**修好之前**确实报红，修好之后转绿，两个方向都有实测。
2. **它是 D56 的独立复现** —— 与"读代码发现 `return 0`"是两回事：仪器是**注入前置缺失后**

3. **它恰好就是 #100 想防的那类退化的镜像** —— `taskflow` 的"前置缺失 ⇒ 0"是一种
   **判据与语义不符**（语义是"缺前置 ⇒ 不可判定"，判据是"没 FAIL ⇒ 0"）。
   `names` 对此完全无感（`B0a/B0b` 的名字一个字没变）；`red_probe` 一跑就报。

## 4. D56 · 非自包含仪器：前置自述 + fail-loud

### 4.1 病灶（硬证据）

| 仪器 | 自包含？ | D56 之前的退出码文档/行为 |
|---|---|---|
| `subgraph` / `frontend` | ✅ 自起 `ThreadingHTTPServer(("127.0.0.1", 0))` | — |

两者**口径不一致**：同一条纪律（"缺前置不是通过"）在一台仪器上做对了、在另一台上做漏了
—— 这是**#92 的形态**（两处各自都对、合起来是缝）。

### 4.2 修法

- `phase51_task_flow_e2e.py`：
  - 新增 `precond_banner(which, name, detail, how_to_fix)`：显著打印**前置块**
    （前置名 / 观测值 / **恢复命令** / "退出码 2 = 前置缺失，既不是通过、也不代表前端有问题"）。
  - **B0a（playwright 缺失）与 B0b（viz 不可达）两条路径都改为 `return 2`**（原为 0），
    并把 banner 打印在 `rep.dump()` **之前**（让读者先看到原因，再看那一屏 SKIP）。
  - 文档头退出码订正为「0 = 无 FAIL **且前置齐备**；1 = 有 FAIL；**2 = 缺前置**」。
  - `ArgumentParser` 加 `epilog`，`--help` 里直接写明**非自包含**与 RC 语义。
- `a4_offline_render.py`：同样加 `epilog`、在两条前置缺失路径补齐 RC 语义说明
  （它本来就 `return 2`，本轮只补"自述"）。
- `sttp.sh`：`taskflow` / `offline` 两个目标的注释与用法行写明「★ 非自包含 ⇒ 缺前置 **RC=2**」。
- `README.md`：命令表补 `taskflow` 行（此前**没有**），`offline` 行补"非自包含 + RC=2"。

### 4.3 边界（登记为 D60）

本轮**只做到"前置显式 + fail-loud"**，**没有**做"自动起 viz 服务并在结束时回收"。
后者才是真正的"自包含"，但它要处理端口占用、服务生命周期、失败清理 —— 是一步独立的工作
（登记 **D60**）。当前状态在报告与 `--help` 里**都说清楚了**（这就是 D56 登记时要求的
"须在 `--help` 与报告里说清"）。

  代价是"改一处须改两处"，故登记。
- ★ **一条方法学观察**（写成铁律候选 #100 的注解）：本轮**没有**用"再加几条断言"来回应 D55。
  因为 D55 的问题恰恰是"**断言的数量与名字都不再可信**"。多写一条"容器里装着容器"的断言，
  只会把同一个不可信放大一层；**必须换一种证据**（注入已知缺陷）才能闭合。
