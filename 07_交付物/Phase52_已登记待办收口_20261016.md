### 2.5 `assert_name_diff.py` 自检 · 「谁来核对核对器」

**动机**：本脚本是铁律 #87 的**执法工具**，但它自己一直**没有断言覆盖** ⇒ 工具坏了没人知道，
而它给出的「无删除」结论会被直接采信。这是铁律 #90 的形态（「全绿」也可能是测量器坏了）。

**修**：新增 `--selfcheck`，在临时目录造**已知答案**的样本对：

| ID | 断言 |
|---|---|
| S1 | 加 1 删 1 ⇒ `added=[A4] / removed=[A2]`（分列正确） |
| S2 | ★ **条目总数不变（3→3）但实删 2 条** ⇒ 仍必须报出 —— #87 的**原始动机场景** |
| S3 | 负对照：只加不删 ⇒ `removed` 为空（证明删除检测非恒真） |
| S4 | ESM `check("NAME", …)` 第二条注册通道同样可解析 |
| S5 | 可红性：朴素判据（只比总数）在 S2 上判「无变化」⇒ 证明集合差分不可省 |

**入口**：挂在 `bash sttp.sh gatecheck` 的 `[0/1]` 步 —— 且**刻意放在 `require_authority` 之前**

**实测**：6/6 PASS，RC=0；S6 的**构造性**验证（把 `S4` 改名）⇒ 真红、`缺 ['S4']`、RC=1。

## 3. 本轮**新发现**（诚实登记）

### 3.1 X16g 自身的缺陷：我自己上一轮写下的自检**从未运行过**

X16g 首跑即 `FAIL`：`/api/search: 前端 None ≠ 契约 3000`。根因是**我写错了**：
契约端点表的键是**全路径**（`/api/search`），而前端常量的键是**短名**（`search`），
我却拿全路径去匹配短名块 ⇒ 必然取不到。

**为什么没被发现**：它是我上一轮**加进文件但没跑**的一条断言（当时 `frontend` 的结果没取回）。
⇒ **教训**：新写的断言**必须首跑一次**；「写下了」与「跑过了」是两件事。
（与铁律 #38 同源：PASS 只说明「当前没红」，而**没跑过**连这句都不成立。）

**修**：按 `/api/<name>` 约定从**事实源自身**派生短名（不硬编码映射表，铁律 #88），
并补一条**反向断言**（前端不得留契约未声明的残余预算键 —— 铁律 #88 的配套要求）。
**可红性**（受控变异，改后按 sha256 还原字节一致）：把 `search` 改成 `9999` 并注入一个
`__probe_extra` ⇒ X16g 真红，且两侧都报出：
```
search: 前端 9999 ≠ 契约 3000；前端多出契约未声明的预算键：__probe_extra
```

### 3.2 E21 残余（新登记，已修）· 发布链在**生成侧** fail-closed，在**校验侧**对脏树放行

**实测证据**（在脏树上）：
```
bash sttp.sh release            → RC=2（拒绝出清单；E21 已生效）
bash sttp.sh release-full       → RC=0 全绿！31 条 + 108 条
```
`verify_release.py` **完全没有**洁净度判定（无 `dirty` / `porcelain` 相关代码）。
⇒ 同一条发布链，一个 fail-closed、一个对同样的脏树完全放行。
**这正是铁律 #92 的形态**（两处各自都对、合起来是缝）：读 `release-full` 全绿的人会得出
「发布链验证通过」，而同一棵树上还有**未提交、未声明**的改动。

**修（单一实现，避免两处各写一套）**：把「什么算脏」抽成 `make_manifest.py` 的
`dirty_report()`（**唯一实现**，含「排除清单自身」这条口径），并以 `--check-dirty` 暴露
（干净 RC=0 / 脏 RC=2）；`release-full` 新增 `[0/3]` 步调用它、**只传播退出码**（铁律 #62）。
`release-full` 同时**消费**`--allow-dirty`（原先会把它透传给 `argparse` ⇒ `unrecognized arguments`）。

**实测**：
```
脏树  release-full                  → RC=2（新行为；原为 RC=0 全绿）
脏树  release-full --allow-dirty    → RC=0 · 洁净度提示如实打印「**不干净**（12 项）…显式放行」
                                        → 发布校验 31 条 FAIL 0 · 主图门禁 108/0/0
干净  --check-dirty                 → RC=0
```
★ 放行路径也**不得打印「工作树干净」** —— 那是不实陈述（第一版我写成了「工作树干净；--allow-dirty
显式放行」，已订正）。

## 6. 铁律候选（拟入 Top 95 之外的候选池）

- **#96 · 发布链的 fail-closed 断言必须覆盖链上**每一个**入口**。
  「生成侧 fail-closed」不等于「校验侧 fail-closed」：实测同一条链上，
  `release` 脏⇒RC=2 而 `release-full` 脏⇒RC=0 全绿。**缝就在两处各自都"做了判定"之间**（同 #92 族）。
- **#97 · 自检的留痕不得写入被跟踪路径**。
  否则两个仪器会互相拆台：`install` 弄脏树 ⇒ `release`（按 E21）拒绝出清单。
  凡「跑一次就产生文件」的仪器，产物一律落**入库外**路径；入库的那份只能是**冻结快照**。
- **#98 · 执法工具自身必须在被执法的集合里**。
  `assert_name_diff.py` 是 #87 的执行器，但它的自检断言若不可被自身解析器采集，
  它就可以悄悄退化而无人知晓（S6 的存在理由）。
