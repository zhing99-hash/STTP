## 2 · T7 = 0.0% 的双重根因（本轮核心勘察）

第 18 轮的北极星把 T7 定义为
「`same_as` / `proves` / `derived_from` / `defines` / `related_to` 五类边中两端点学科不同者，
门槛 `human_reviewed`」，实测 **0 / 53 = 0.0%**。逐条复查后确认是**两处口径缺陷 + 一处内容缺口**：

### 2.1 门槛不可达（口径缺陷一）

`human_reviewed` 是受控词表**最高档**（要求人工复核）。在一个**自动化重建**的图里，
没有任何流水线会写入 `human_reviewed` —— 该门槛使 T7 **恒为 0**，
不区分「没有桥」与「有桥但没人工签字」。这是**把测量工具做成了永远测不出数的工具**（铁律 #16）。

### 2.2 类型窗口漏掉主桥（口径缺陷二）

跨学科连通性在本图中**主要靠 `has_quantity` 承载**（化学物质 → 物理量表节点），
而旧口径的 5 类窗口里**没有 `has_quantity`**。于是：

| 口径 | T7 集合 | ≥门槛 | 达标率 |
|---|---:|---:|---:|
| 旧（5 类型窗口 + `human_reviewed`） | 53 | 0 | **0.0%** |
| 新（**任意类型** + `rule_checked`） | **962** | **861** | **89.5%** |

新口径把 T7 集合从 53 扩到 **962**（×18.2），其中 **899 条是化学↔物理**——
即「分子 → 物理量」桥。**旧口径把 94% 的跨域边排除在测量之外。**

### 2.3 内容缺口：桥确实有水分（真实缺陷）

即便修正口径，Phase 28 时点 869 条跨域边里 ≥`rule_checked` 的也只有 **6 条**。
这不是口径问题，是**内容问题**：784 条「分子 → 物理量」桥里，**700 条指向 `PB:pq:molar_mass`**，
其 `value` **本可由「元素原子量 × 化学式计数」确定性复算**，却因分类器只认 `rationale` 模板、
不认「可复算」本身，被一律打成 `model_inferred`。

### 2.4 口径修正的**反向对照**（铁律 #16，已留档）

`06_PoC/task_trust_audit.py` 新增 `--legacy-t7` 开关，**同一份数据、同一时刻**打印两套口径：

```
【反向对照 · T7 口径变更留档】
  旧口径（5 类语义边，门槛 human_reviewed）  :  53 条 /  0 达标 /  0.0%
  新口径（任意类型跨域边，门槛 rule_checked）: 962 条 / 861 达标 / 89.5%
  → 旧口径的 `human_reviewed` 金标准子集（新口径下）：0 条
```

T7 定义同时改为：
> **跨域桥（跨学科端点）** = 两端点学科不同的**任意类型**语义边 —— **本项目的核心命题**，门槛 `rule_checked`。

并新增输出「**跨域边的学科对 × 证据档**」，防止「加同域质量只改占比」（铁律 #18）。

## 3 · 用同一把尺子抓出的四类真实缺陷

判据只有一条，且**与提出者无关**：
> 把边的 `rationale` / `value` / `unit` 当成**断言**，用**独立于产出方**的实现去**复算**它。

### 3.1 自相矛盾的跨域桥 —— 62 条（源头根治）

**现象**：同一条理由被**原样粘贴**到多个互斥目标上。

| 断言形态 | 例子 | 目标 | 条数 |
|---|---|---|---:|
| 显式类声明「属**质量**类物理量（组成校验）」 | `PC:mol:962` | `PQ:ke` 动能 | 18 |
| 同上 | `PC:mol:962` | `CM:pq:energy` 能量 | 13 |
| 同上 | `PC:mol:962` | `TH:pq:energy` 能量 | 11 |
| 同上 | `PC:mol:962` | `TH:pq:internal_energy` 内能 | 11 |
| 同上 | `PC:mol:962` | `PQ:energy` 能量 | 9 |
| **数值断言**「摩尔质量 507.1813 g/mol」 | `PC:mol:5957` | 能量类目标 | **20** |
| | | **合计** | **62** |

> **⚠ 本轮踩坑（已冻结为反例）**：第一版判据只认字符串「属…类物理量」，
> **漏掉 20 条**同类缺陷（它们写的是**数值**而非类名）→ 补上「数值断言亦构成类声明」。
> 这正是「一条理由 / 多个互斥目标」的**同族缺陷有多个表达形态**。

**修复（铁律 #15：下游打补丁 = 源头有错）**

| 位置 | 修复 |
|---|---|
| `09_科研扩展/9_inference/gnn_infer.py` (B5) | 质量类关键词表 `("mass","weight","energy")` → **`("mass","weight")`**（`energy` 是 42 条伪桥的直接来源） |
| `09_科研扩展/9_inference/llm_hypotheses.py` | 新增**透传守卫**：分子 → 物理量的 `has_quantity` 只允许锚定 `molar/mass/weight` 类目标，否则 **DROP** 并留痕 |
| `06_PoC/etl/normalized.json` | delta 撤回 **62 条**（`delete_edges`） |

### 3.2 陈旧的摩尔质量值 —— 18 条（独立复算抓出）

| 分子式 | 记录值 | 独立复算 | 说明 |
|---|---:|---:|---|
| `CO3-2`（碳酸根） | 28.01 | **60.008** | 28.01 = CO（电荷剥离正则吃掉了末尾 `3`） |
| `MnO4-`（高锰酸根） | 70.937 | 118.936 | 70.937 = MnO |
| `N3-`（叠氮根） | 14.007 | 42.021 | 14.007 = N |
| …（共 18 条，**全部为多原子阴离子**） | | | |

**根因**：旧版电荷剥离正则 `\d*[+-]\d*$` 的 `\d*` **贪婪**吞掉了「末尾元素下标」
（`gnn_infer.py:468-473` 已在 Phase 27 修好，但**存量 `value` 从未重算**——铁律 #22 的又一例：
改正派生字段 ≠ 撤回原始断言）。

**修复**：值改为「独立复算 ≡ PubChem `pubchem_molecular_weight`」**双确认**的正确值，
附 `verification_note` + `evidence[]`，等级 `cross_source`。
**留痕保护**：delta 的「是否重写」判定**只看 4 个核心字段**，
不让本轮新算出的通用说明**覆盖**上一轮的修正说明（否则等于抹掉证据）。

### 3.3 抽象类节点的假桥 —— 2 条

`BC:mo:protein`（式 `(C2H3NO)n`）与 `BC:mo:dna`（式 `(C10H14N5O7P)n`）是**抽象类节点**，
**本就没有单一摩尔质量**；两条边却都写 `value = 43.025`（**同一个占位常数**）→ 是假话。
判据确定：**独立复算不可行 且 分子式是聚合体/抽象简写** → 撤回（`reason=abstract_class_no_molar_mass`）。

### 3.4 WebBook 桥「取中位数编造值」—— 16 条（自证价值）

**现象**：多条文献**分歧超出容差**（如 CH₄ 气相熵：`Colwell J.H., 1963 = 188.66±0.42` vs
`Chase, 1998 = 186.25`，差 1.20 > 0.42 的不确定度），吻合集为空，
旧生成器却仍写出**取两者中位数 187.455** 的边，且 `n_references = 0` ——
**值既不来自任何单一文献，也不满足"多源一致"，是静默编造**（铁律 #13 的变体）。

**如何发现**：把「落库档位必须等于重算档位」冻进反例集后，
审计打印出 `independent 文献 0 条` 而边却有值 → 逐条追查定位。

**修复**：吻合集为空时**不再取中位数**，改为采用**单条权威文献**（优先 `Review` 综述、其次最新年份），
`n_references = 1`，并在 `evidence[]` 里**显式记录分歧未被消除**。
→ 16 条从「合成值」变为「具名单源值」，全部 `rule_checked`（**不升** `cross_source`）。

### 3.5 顺带修好的「字段缺失 ≠ 不可用」（铁律 #17 同类）

`MX:chem:co2`（`name = CO₂`）/ `MX:chem:methane`（`name = CH₄`）有完全正确的摩尔质量值
（44.009 / 16.043），但节点**没有 `formula` 字段** → 无法复算而被降级。
新增**保守**回退 `formula_from_name()`：把下标/上标归一后**只有能被独立解析器接受**的串才认
（`Water`、`n-Butanol` 等自然语言名一律不认）→ 这 2 条桥升级为 `rule_checked`。

## 5 · 新接入：NIST Chemistry WebBook 热化学桥

选源标准 = **能否产跨域桥**（不是"能不能抓"）。

**先做可行性勘察，得到一条关键负结果**：
`DLMF` 的「特殊函数」桥在物理侧**产量 ≈ 0** —— PhysicsBabel 的 5000 条公式经检查
是**纯单项式（幂积）**（15050 个公式串中仅 6 条含显式函数调用，**无任何特殊函数**：
Bessel / Γ / erf 全无；`γ`/`ω`/`ρ` 是希腊字母**变量**而非常数）。
→ 资源转向 **WebBook 热化学**（化学↔物理，正是最大的一块跨域面）。

**适配器**：`11_真实数据/webbook_ingest.py`（直连可达，实测 3/3 HTTP 200）

- 抓取 `?Name=<name>&Units=SI&cTG=on` 的**气相热化学表**（ΔfH°gas / S°gas）
- 增量缓存（每 10 页落盘，中断不丢）、歧义页跳过、**化学式必须与节点一致**（防同名异物）
- **同一物理量常给出多条独立文献**（不同作者/不同测量）→ **天然支持 `cross_source` 阶梯**
- 抓取规模：候选 **1093** 个 → 处理 **420** 个（`no_thermo 301 / ok 110 / 化学式不符 5 / 网络失败 4`）

**证据阶梯（两级，均与提出者无关）**

| 档 | 判据 | level |
|---|---|---|
| ① | 单位（`kJ/mol` / `J/mol*K`）经 `dimension_table` **独立复算**与目标真量纲一致 | `rule_checked` |
| ② | 页面内 **≥2 条独立文献**在容差内吻合（含各自不确定度） | `cross_source` |

**产出**：**157 条桥 / 104 个分子**

| 物理量 | 目标节点 | 条数 | 档位 |
|---|---|---:|---|
| 标准摩尔生成焓 ΔfH°(g) | `PB:pq:molar_energy` | 90 | 69 `rule_checked` + 21 `cross_source` |
| 标准摩尔气相熵 S°(g) | `PQ:molar_entropy`（**新建**） | 67 | 67 `rule_checked` |
| | | **157** | |

**派生节点**：`PQ:molar_entropy` 由 `dimension_table` 的**量纲代数**派生（`entropy / amount`），
**不外部硬编码**：

```
molar_energy  = energy / amount              = L²MT⁻²N⁻¹
molar_entropy = (energy/temperature)/amount  = L²MT⁻²Th⁻¹N⁻¹
```

> `molar_entropy` 原本**不在**真值表（消元反解只能覆盖"在方程里独立出现"的量）
> → 若不补，桥的量纲复算会**静默退化为「不可判定」**。
> 因此在 `dimension_table.py` 新增 `DERIVED`（量纲代数派生表，逐条写明来源式，可复核）。

## 6 · 分层模型扩展（`verification_model.py`）

| 段 | 内容 |
|---|---|
| **A5** `molar_mass_*` | 分子 → 摩尔质量：独立复算 → `rule_checked`；再与 PubChem 一致 → `cross_source`；不一致 → `unverified` |
| **A6** `rationale_target_mismatch` | `rationale` 承载的**确定性语义载荷**（显式类声明 **或** 摩尔质量数值断言）必须与目标真量纲自洽 |
| **A7** `webbook_*` | WebBook 热化学桥：**单位量纲独立复算**（本模块自带单位解析器，**不 import 产出方**）→ `rule_checked`；`n_references ≥ 2` → `cross_source`；单位与目标量纲不符 → `unverified` |
| 辅助 | `dim_matches_class()` —— **含「每摩尔」形式**（`molar_* = * / amount`） |
| 辅助 | `formula_from_name()` / `src_mass_formula()` —— 分子式**有序回退**：PubChem → formula → 名称 |

> **⚠ 本轮最重要的一次自我纠错（已冻结为反例）**：
> `dim_matches_class` 的第一版写成 `want != got`。但 `molar_mass = M·N⁻¹ ≠ M`，
> 于是「分子 → 摩尔质量」桥**全部**被判自相矛盾 —— **一次假 FAIL 762 条（其中 700 条是好边）**。
> 若没跑门禁，就会**静默删掉 700 条真桥**并把它记成「修复」。
> → 已冻结为 `P1-level-numeric-mass-on-molar-mass-ok`（正对照）。

> **⚠ 第二次自我纠错（A7 的由来）**：首版把 WebBook 桥的档位写成落库值，
> 但分类器**不认识**这类证据 → 重算为 `source_asserted`。
> 于是全图出现 **157 条「落库 `rule_checked` / 重算 `source_asserted`」的静默不一致**。
> 修复方式不是改数据，而是**让分类器真正学会独立复算**（A7）→ 落库 == 复算，0 条不符。

**门禁白名单的边界（有意的克制）**
`GATE_SCOPE_OK["R-PHY"]` **只放**量纲门禁自己的范围：
```python
"R-PHY": {"dimensional_strict_equal", "dimensional_mismatch"},
```
> 曾试图把 `molar_mass_*` / `formula_participation_*` 加进去，`P0-6-attrib-has-symbol-phy-bogus`
> **立刻 FAIL** —— 那等于给 Phase 27 已坐实的**虚假归因**开后门。**已回退**并加警示注释。
