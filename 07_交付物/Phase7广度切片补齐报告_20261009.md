## 一、为什么做这一项（决策记录）

本轮开工前先做了一轮证据收集，推翻了三个「看起来显然」的候选方向：

### 1) Aura 仍不可达 —— 先确认，避免误判

`853a33bc.databases.neo4j.io` 仍为 **NXDOMAIN**（实例闲置暂停），`console.neo4j.io` 可解析但 resume 需人工操作。
→ 所有云端写操作（B2 七步推送 / B1 PhysicsBabel 尾部）继续阻塞。

### 2) 发现**沙箱出口白名单**（本轮最重要的环境认知）

同样的探测方式，结果呈稳定二分（三轮复测一致，排除抖动）：

| 可达 ✅ | 被拦截 ❌ |
| --- | --- |
| `github.com` / `api.github.com` / `raw.githubusercontent.com` / `codeload.github.com` | **`query.wikidata.org` / `www.wikidata.org` / `en.wikipedia.org` / `commons.wikimedia.org`** |
| `cdn.jsdelivr.net` / `fastly.jsdelivr.net` / `cdnjs.cloudflare.com` / `unpkg.com` / `esm.sh` | **`neo4j.io` / `console.neo4j.io`** |
| `pypi.org` / `files.pythonhosted.org` | **`huggingface.co`** |
| **`arxiv.org` / `export.arxiv.org`** / `zenodo.org` / `doi.org` | **`ncbi.nlm.nih.gov` / `pubchem.ncbi.nlm.nih.gov`** |

结论：**路线图 §5 第 2 优先的 Phase 9（Wikidata 真实对齐）此路不通** —— 不是网络断开，是出口策略不放行。
（副产物：DoH 诊断会被代理拦（`dns.google` 经代理 502），不能当 DNS 诊断手段。）

### 3) 否掉「扩容 PhysicsBabel」—— 用数据否掉的

直觉以为「扩充物理方程=规模化=好事」，实测后**否掉**：

- parquet 有 232 万行，`plausible=True` 的有 **46,720** 条；现行 `MAX_EQ=5000` 是**按行序截断**。
- 但按域统计：现有 5000 条对每个域的覆盖率都是 **≈10%**（mechanics 5000/45417、em 3211/32722、thermo 637/6558、chemistry 319/3521）——即**它是一份无偏的 10% 均匀抽样，并非"选错"**。
- 更关键：**该数据集 100% 的方程都含 `mechanics` 域**，而图谱物理已占 **73%（5175/7120）**。扩容只会让学科失衡更严重 —— 与「跨学科」北极星背离。

另有一条**差点被误当成缺陷的字段语义**：

- `score` 字段与 `complexity` 的相关系数是 **−0.995**（score 9.0 ↔ complexity 1.0；score 2.8 ↔ complexity 6.7）。
- 即 **`score` 是"复杂度取反"（越简单分越高），不是质量分**。若照"按 score 降序取优"去做，会把 `m = k₀·v⁻¹·p` 这类**平凡移项**全部选进来。
- 这正是项目记忆里那条教训的又一次验证：**外部数据源的字段语义不可想当然**（前例：ElementKG 的 `HASATOMIC`）。

### 4) 于是回到路线图 §5 第 1 优先：Phase 7「先广后深」

清单逐条核对后发现 —— **13 个切片里已有 11 个**（经典力学/热学/电磁/量子/相对论/光学/统计力学/有机/无机/代数/微积分/几何），
唯二缺失的是 **化学平衡** 与 **数论**。补齐即完成 Phase 7 里程碑，且是**离线可做、零风险**的一项。
