## 3. 引用完整性修复说明（22 → 36 节点）

### 3.1 缺失端点识别

扫描 `with_inferred.json` 全部 52 条边的 `source`/`target`，相对 22 个既有节点
求差，得到 **14 个缺失端点**（均为 Phase 3 的 LLM 假设边引入）：

| id | 推断 Label | ntype | domain |
|---|---|---|---|
| `MX:sym:c` | Symbol | symbol | cross |
| `MX:chem:co2` | Molecule | molecule | chemistry |
| `MX:chem:methane` | Molecule | molecule | chemistry |
| `MX:chem:combustion` | Molecule | molecule | chemistry |
| `MX:phy:newton2` | PhysicalQuantity | physical_quantity | physics |
| `MX:phy:acceleration` | PhysicalQuantity | physical_quantity | physics |
| `MX:phy:kinetic_energy` | PhysicalQuantity | physical_quantity | physics |
| `MX:phy:energy` | PhysicalQuantity | physical_quantity | physics |
| `MX:math:binomial` | MathConcept | math_concept | math |
| `MX:math:expand` | MathConcept | math_concept | math |
| `MX:math:pythagorean_identity` | MathConcept | math_concept | math |
| `MX:math:trig_unit` | MathConcept | math_concept | math |
| `MX:math:derivative_power` | MathConcept | math_concept | math |
| `MX:math:power_rule` | MathConcept | math_concept | math |

> 注：`INFERRED:HYPO-GRAPH-001`（gauss_bonnet→riemann_curvature）引用的是既有节点，
> 故不新增端点；其余 7 条假设边正好贡献 14 个新端点。

### 3.2 合成节点字段补全

每个合成节点补齐：`confidence=1.0`、`explicit_or_inferred='inferred'`、
`source='llm_hypothesis'`、`ntype/name/domain/meaning/local_id` 等；并统一附加
通用 Label **`Entity`**（便于建立全局唯一约束 + ntype/domain 索引）。
既有 22 节点同样附加 `Entity` 标签，保持结构一致。

## 5. 部署步骤摘要（详见 neo4j_deploy.md）

1. **前提**：Java 17 + Docker；`pip install "neo4j>=5.0"`。
2. **(1) 起容器**：`cp .env.example .env` → `docker compose up -d`。
3. **(2) 等 healthy**：`docker compose ps`（STATUS=healthy）。
4. **(3) 导入**：方式 A 离线 `neo4j-admin import`（复制 CSV 进 import 目录）；
   或方式 B 在线 `python load_neo4j.py`（默认载入 `neo4j_ready.json`）。
5. **(4) 建索引/约束**：`cypher-shell -f load.cypher`（含约束/索引 + 校验查询）。
6. **(5) 冒烟 + 校验**：`python verify_deploy.py` → 节点=36 / 边=52 / 路径非空。
7. **(6) 前端对接**：`viz_server.py` 的 `get_backend("auto")` 自动走 Neo4j；前端零改动。

复现（一行流）：
```bash
cd 01tuopu/03_知识层
python build_neo4j_ready.py      # 生成 36 节点/52 边 CSV
python preflight_neo4j.py        # 静态校验：0 重复 / 0 悬空
# 在含 JVM 主机：
docker compose up -d && python load_neo4j.py && cypher-shell -f load.cypher && python verify_deploy.py
```

## 6. 已知限制

1. **本沙箱无 Java / Docker**：无法实跑真实 Neo4j。所有产物已通过静态校验；
   “实际连接验证”（`verify_deploy.py` 的 6 类查询）**待含 JVM 部署主机**执行。
2. **`MX:chem:combustion` 语义**：按前缀规则标为 `Molecule`，但其语义是“燃烧反应”。
   若后续采用 Schema §4 的 `Reaction` 超边建模，可将其重分类为 `Reaction`。
3. **离线导入不直接执行约束/索引**：`neo4j-admin import` 只建图，仍需 §5 跑
   `load.cypher` 补建约束/索引（已写入手册）。
4. **`same_as` / Wikidata 对齐**：本阶段仅预留 `same_as` 属性与约束位，跨源对齐为后续阶段。
