# Phase 76 · F13 学科导航：把「必须知道名字才能查」变成「可以往下翻」

**日期**：2026-10-23　**范围**：`/api/nav`（后端 v1，上一轮）+ 导航抽屉（本轮）**状态**：前端完成，判据全绿

---

## 一、问题

外部评审的 F13 原话是：**「必须知道名字才能查」**。在这轮之前，页面上进入图的方式只有三条：搜索框（要知道名字）、任务入口（要知道名字）、概览（只到「学科 × 类型」这一格，不可下钻）。**没有任何一条路能回答「物理学里都有什么」**。

而这件事**本来是有数据的**：节点上有 `subject`（物理 4,983 / 化学 4,442 / 数学 300 / 跨学科 25）、有 `domain`（`physics.em` 等）、有 `attrs.domain_tags`（5,090 条）。三层都在快照里现成，**第二、三层此前没有任何入口**。

### 1.1 一个被否掉的方案（记录在案，因为它改变了设计）

最初的设想是**前端聚合**：9,750 个节点在浏览器里汇总，零后端改动、离线可用。

**这条走不通，证据在代码里**：

- `06_PoC/js/core.js:45`：`bundleGraph` 只在 `mode=bundle` 下读取，**live 模式永不请求** `/graph_data.json`；
- `BUNDLE_MAX_BYTES = 8 MB`，对全图是**拒绝**而不是截断（铁律 #66「规模是设计约束」）。

live 页面手上**没有全图** ⇒ 前端聚合得先下 85 MB，正是 #66 要消灭的行为。**数据面只能在后端**，这不是偏好问题。

## 二、判断

1. **导航的价值是「不漏人」，不是「能点」。** 最容易犯的错是某几个节点谁都不收，而页面上只会少一格 —— 没人看得出。所以计数必须能对账。
2. **单归属与多值必须用两套式子。** 前两层（学科、领域）每个节点恰好落一格 ⇒ `sum_items == scanned` 必须成立；第三层 `domain_tags` 是多值的（5,090 个带标签节点里 **4,289** 个有 ≥2 个标签）⇒ `sum_items > scanned` 是**正常**的，可核的式子换成 `tagged + untagged == scanned`。
3. **「分类名不存在」与「这一类里没有东西」是两件事。** 前者是名字打错了，后者是数据为空。界面表现都是空列表，但用户该做的动作完全相反。
4. **叶子层（领域标签）不是死路。** 即使不能继续下钻，也必须给出代表节点让用户点进去。

## 三、处置（本轮：前端）

### 3.1 后端（上一轮已就绪，本轮未改）

`Backend.nav(level, parent, limit)` + `GET /api/nav`：每格只给「计数 + 前 `limit` 个代表节点」，**绝不返回全图**。

### 3.2 前端：新模块 `06_PoC/js/nav.js`（纯逻辑 + 排版，node 可断言）

| 导出 | 职责 | 为什么单独存在 |
|---|---|---|
| `NAV_LEVELS` / `NAV_LEVEL_LABEL` | 层序与三层中文 | 层名**只有这一份**（D114）；层序与后端逐值相等由 X18a 求差 |
| `nextLevel` / `currentLevel` | 下一层 / 当前层 | 末层返回 `null`，叶子层因此拿不到「下钻」按钮 |
| `navPush` / `navClip` / `navTargetOf` | 栈 → 请求 | **「点击之后发什么请求」的唯一来源**（见 §3.4） |
| `navItemsOf` / `navStatsOf` | 取条目 / 取计数 | 非法项**剔除**、缺字段给 `null`（不臆造 0） |
| `navNotice` / `navEmptyText` | 四种「空」各说各的话 | D115 / D118 / D119 |
| `navHTML` | 渲染 | 只排版，中文数字都来自后端或本模块的常量 |

### 3.3 页面接线

- 头部新增「浏览」按钮（**只在 live 模式出现**：bundle/offline 下没有 `/api/nav`，宁可不出按钮也不给点了没反应的入口 —— 与「任务入口只在 live 挂」同一条纪律）。
- 左栏新增 `#nav-drawer`：面包屑（`全部学科 / 化学 / chem.reaction`，逐层可回）+ 条目列表 + 每格前 6 个代表节点。
- 点代表节点 ⇒ 走**现有** `runEgo` 链路（不新开渲染路径）；空结果由刚做完的 F12 诊断接手。
- `loadNav()` 带**竞态序号** `seq`：连点两格时两个请求都在飞、先发的后回 ⇒ 不设序号会把「学科层的结果」画到「领域层」的标题下面。

### 3.4 真浏览器不在零安装路径上 ⇒ 把行为下沉成纯函数

环境里没有 Playwright（`MODULE_NOT_FOUND`），`taskflow` / `offline` 在本机只能 SKIP（D14 的既有状态）。这意味着**「点了之后发什么请求」这条链路没有端到端判据**。

处置：把 DOM 事件剥掉，只留「栈怎么变、请求怎么推」—— `navPush` / `navClip` / `navTargetOf` 三个纯函数，`main.js` 只做 `navTargetOf(state.nav.stack)`。判据 F46z–F46ae 咬住它们。

★ 这不是「为了好测而抽象」：栈里**必须**同时存 `level` 与 `key`，回退时才知道「第 1 层是学科还是领域」。若只存 key 靠 `stack.length` 反推，将来层级从三条变四条，历史栈全部错位。

### 3.5 条目过多：折叠，但不隐藏

实测「化学」下有 **29** 个格子（28 个领域 + `(无领域)`），其中 **19 个合计只有 35 个节点**。全部铺开是一屏 29 行，`chem.reaction`(1,697) 被淹没在一堆 1 里。

处置：超过 10 个时，后 19 个收进 `<details>`，摘要写「另有 19 个领域（合计 35 个节点）」。**折叠 ≠ 删除** —— 展开全在，F46ag 咬住「被收起的条目仍然渲染」。

### 4.1 三个必须说清的数据事实

1. **`domain_tags` 只长在 `Formula` 类节点上。** `physics.em`(3,217)、`physics.mechanics`(719)、`physics.thermo`(643)、`chem.general`(319) 都有；而 **`chem.reaction` / `chem.compound` / `chem.molecule` / `math` 是 0 条**。所以第三层在化学三大格、数学主格上**必然是空的** —— 界面必须说「这一格没有领域标签」，不能说「无结果」。
2. **`domain_tags` 的第一项就是自身 `domain`。** `physics.em` 下排第一的标签是 `physics.em`(3,217)、第二是 `physics.mechanics`(3,211)。所以第三层对物理节点而言，多数是「自身 + 一个相邻领域」，信息量有限但可核。
3. **导航第一次把数据的碎片暴露出来。** 化学 29 格里 **19 格合计 35 个节点**；`chem`(15)、`chemistry`(3)、`chemistry.aq`(1)、`chem.unit`(1) 这些和 `chem.reaction`(1,697) 平级共存。在搜索框时代没人看得见这件事。**本轮不修数据**，但这个观察是 F13 的副产品，登记在此。

## 六、学费

- **D117　计数语句的位置错了，对账式就会以「看起来合理」的方式撒谎。**
  上一轮第一版把 `scanned += 1` 写在「无标签 ⇒ `continue`」**之后**，于是整格无标签时报出 `scanned=0 / untagged=1697`，`tagged + untagged == scanned` 当场不成立 —— 而**没有任何输出异常**：`items=[]`、`status=no_result`，看起来就是「没有标签」。是 V22f 那条对账断言把它顶出来的。

- **D118　「多值」不是免检牌。**
  多值层的 `sum_items > scanned` 是正常的，但**这不能成为「计数对不上」的通用借口**：多值层必须有**自己的**对账式（`tagged + untagged == scanned`），且它不成立时照样报红。否则「多值」三个字会变成一张通行证，把所有漏人都解释掉（D110b 的同族）。

- **D119　模板句 + 具体数字 = 一条会随数据变真假的口号。**
  多值层的说明句第一版写「各格之和 **N > 扫描 M** 是正常的」。在 `chem.reaction`（`sum_items=0`、`scanned=1697`）上，这句话变成了「0 > 1697 是正常的」—— **一句假话，而且没有任何判据会拦它**（它只是一段文案）。修法两条并用：① 句子只陈述**恒成立**的关系（「不必相等」而不是「大于」）；② `sum_items === 0` 时**不输出**这句，交给空态去说「全部没有领域标签」。F46i / F46k 咬住这两条。

- **D120　端到端验收依赖不在零安装路径上时，「行为」必须下沉成纯函数，否则这条链路等于没有判据。**
  本轮没有浏览器（Playwright `MODULE_NOT_FOUND`），`taskflow` 只能 SKIP。「点击 → 下钻 → 发什么请求」这条链路在浏览器里是行为、在代码里是字符串拼接 —— 不剥出来就永远没人验证。故 `navPush` / `navClip` / `navTargetOf` 三个纯函数进 `nav.js`，`main.js` 只剩事件绑定。★ 代价也如实说：纯函数证明不了「按钮真的挂在 DOM 上、点了真的会触发」—— 那一段仍依赖 F46n/F46o 这类「渲染出带 `data-*` 的按钮」的静态断言 + 真浏览器验收（本机缺依赖，SKIP）。

- **流程**：本轮又被**中文字符串里的 ASCII 直引号**咬了两次（`"下钻到…"`、`"另有 N 个"`），全部改成「」。这是 Phase 74/75 之后的第三次，规则不变：代码里的中文引号一律用「」。

## 七、剩余边界

1. **没有真浏览器验收。** 本机 Playwright 缺失 ⇒ `taskflow` / `offline` SKIP，「点击真的会触发」未在浏览器里验证过。补它需要把 Playwright 拉进零安装路径或换一条无依赖的 DOM 断言路径。
2. **`domains` 过滤未做。** 抽屉能「翻」不能「筛」：点代表节点是 ego，不能「把这一格全部 1,697 个节点筛出来」。要做必须同步改 `_empty_diagnosis` 的 `_passes` 与 `EMPTY_RELAX_ORDER/LABEL/WHAT/TO` 四张表 —— 不是加一个参数就完事（否则放宽建议会漏掉这个新条件）。
3. **第三层在化学三大格、数学主格上恒空**（`domain_tags` 只长在 `Formula` 上）。界面已如实说「全部没有领域标签」，但**根因是数据**，不是导航。补标签需要回到 ETL（G2 的 line of work）。
4. **导航暴露了领域碎片化**（化学 19 格合计 35 个节点；`chem` / `chemistry` / `phys` 与 `physics.em` 平级）。这是数据质量问题，本轮只登记不修。
5. **连续下钻的历史不留存**（只有当前栈）。关掉抽屉再打开，栈还在（`state.nav.stack` 未清），但刷新页面即丢失，且不进 URL ⇒ **不能把「我在哪个学科」发给别人**。要可分享得把栈写进 `location.hash`。
6. **`limit=6` 是硬编码。** 抽屉宽 288px，6 个代表节点刚好；没有任何判据咬住这个数（改大了只是变丑，不会错）。
7. **`.env` 的服役快照仍不在 git 里**（Phase 75 §0.3.33 遗留①，未变）。
