# STTP 每个节点的跨学科联系：产品与研发补充方案

2026-10-29；状态：设计建议，尚未开发、审稿或发布。衔接 [原有公式保留、数据采集与持续探索方案](STTP_原有公式保留_数据采集与持续探索方案_20261029.md)。

> **用户修订，2026-10-29：取消固定三个学科入口。** 节点详情直接按可扩展学科目录列出所有科目的相关内容，内容少时全部展示，没有内容的科目为空；不为凑数造关系。以下有关「三个入口/栏目」的历史提法均以本修订及 [mAtlas 参照与节点界面修订](STTP_mAtlas参照与节点界面修订_20261029.md) 为准。

## 1. 目标与原则

把跨学科联系从可选功能提升为节点页面核心：每个公开的公式、物质、元素、概念或现象，在同一详情区直接列出可配置目录中的全部学科，以及各科已核对且允许公开的知识点、公式、解释、条件、出处及下一步链接。

**列出学科不等于每个节点都已有各学科的可靠关系。** 某项暂无合适的、可公开且经过审查的关系时，该科内容为空，可反馈需求或继续其他方向；不因为要显示各科而编造边。它可能是确无适当联系，也可能只是本版尚未收录，两者不能混说。分类可有交叉：数学方法属于知识解释方向，不强制它与公式的本科学科是两个截然不同的领域。

已有公式和内部图按上一方案完整保留；跨学科说明、审稿记录和链接是与旧节点 ID、快照关联的增量层，公开页面、搜索、API、推荐、导出只能读取经许可和审查的公开投影。不能从产品页面泄露受限制数据的名称、ID、数量或证据。

## 2. 节点页面与用户操作

页面结构：

```text
节点名称 / 学科标签 / 一句话说明 / 来源
公式与变量（如适用） / 适用条件 / 一个例子

跨学科探索（同页列出可配置目录中的全部科目）
数学：已审核的知识点、公式、说明与来源
物理：已审核的知识点、公式、说明与来源
化学：（暂无已审核内容）
其他科目：按目录继续列出，有内容直接展示、无内容为空
选择任一相关内容 → 查看条件与来源 → 继续探索

路径：起点 > 当前节点 > 已走过的节点  | 返回 | 加入收藏
```

每个栏目可以包含多条卡片，一条卡片只说明一个具体关系；例如「共同使用物质的量」与「在给定假设下由 A 推导 B」不能共用同一种「证明」标签。用户点击卡片可进入目标节点；一次按需加载 1 跳、每页建议 10–20 条，支持分页、搜索和返回；一个用户可连续探索多个节点，但不是一次加载全库。图视图与文字列表双向同步，移动端优先可读列表。每次显示当前快照、条件和来源入口；无结果、未收录、版本过期和系统错误分开呈现。

简要展示的关系类型：`定义/使用的变量`、`数学形式/运算`、`有条件的推导`、`模型应用`、`物质或反应参与`、`测量/单位`、`类比`、`背景文献`。其中类比或共同用法不是因果、等价或证明；推导必须记录方向、前提和证据。来源待审、授权不清、模型推断和公式同名不自动成为公开事实。

## 3. 一条完整示例：理想气体状态方程

用户进入 `pV=nRT`。此示例是**建议策展内容，不是已验证现有数据库链路**：

| 学科入口 | 展示内容 | 说明和可继续探索的方向 |
|---|---|---|
| 物理 | 压强、体积、温度与理想气体模型 | 在理想气体适用近似下描述状态；可点压强、绝对温度及分子运动 |
| 数学 | 恒定 p、n 时，变形为 `V=(nR/p)T` | 给出代数变形和线性比例，条件是 p、n 恒定、p 非零，T 使用开尔文；数学变形不是新物理定律 |
| 化学 | 气体的物质的量、摩尔质量 | 在同样模型和条件下，由 `n=m/M` 可将其与气体质量、摩尔质量联系；可继续查看气态氧或其他具体物质，不能误说液态水直接满足理想气体公式 |

公式涉及的变量和基本单位须清晰：BIPM 将热力学温度与物质的量分别对应开尔文和摩尔，见 [SI 基本单位](https://www.bipm.org/en/measurement-units/si-base-units)。理想气体关系与摩尔质量的结合可参考 [OpenStax 原教材章节](https://openstax.org/books/chemistry/pages/9-3-stoichiometry-of-gaseous-substances-mixtures-and-reactions)。此处是方案示例，正式上架前要核对原始依据、表述和展示许可，取得相关学科审稿记录。

## 4. 另一个示例：水分子节点

「水 H₂O」的化学卡可解释分子组成及其来源；数学卡可解释计数比例或摩尔质量的加权求和；物理卡可介绍经核对的水的状态及相关物理量。具体性质必须明确温度、压力、相态和单位；H₂O 的元素比例不等于分子空间结构、质量比例，或决定所有性质。若具体物理数据与出处未审，则物理栏目显示暂无，不以模型生成数值填补。ATP 的已知结构与分子式冲突处理仍遵循上轮发布门槛。

## 5. 内容模型与旧数据衔接

基于旧节点建立新记录，不覆盖 `normalized.json` 或原始数据；存储形式由 WorkBuddy 根据代码现状决定。示例仅说明逻辑字段：

```json
{
  "node_id": "<现有稳定节点ID>",
  "source_snapshot": "sha256:<内部输入快照>",
  "disciplines": ["物理", "化学"],
  "links": [{
    "target_node_id": "<经过审核的公开节点ID>",
    "discipline": "数学",
    "relation_type": "conditional_derivation",
    "explanation": "在指定前提下进行代数变形",
    "conditions": ["p 和 n 恒定", "p 不为零"],
    "evidence": [{"source": "<来源>", "locator": "<公式号或页面>"}],
    "science_review": "approved",
    "rights_review": "approved_for_public_display",
    "reviewer": "<审查记录标识>",
    "reviewed_at": "<日期>"
  }]
}
```

公开快照应有独立 ID，绑定内容包、节点和边、审稿版本、数据及来源许可；所有 links 的两端、关系、解释、证据和引用均需可公开，未审记录不得加入公开投影。源头有错误时保留旧快照与更正记录、新版本重新生成；无需为三类入口复制原节点三次。

关系审查维度分开：科学语义、内容完整性、可再分发权利、适用条件、来源独立性、学科审稿和呈现状态。维护员可见 `candidate / needs_review / approved / rejected / withdrawn`，但公开结果只暴露允许披露的信息，不暴露被拒或内部受限记录。

## 6. 建设和发布顺序

1. **保护现有资产**：按照原方案完成清点、备份、SHA-256、旧 ID 与快照对账。已有 2026-10-28 快照为 5,090 个 Formula 标签节点，不应以此假定所有公式已有跨学科资料或许可。
2. **选试点**：先选 5–10 个节点作为工作目标，围绕 1–2 个主题按实际证据补充；每节点按目录列出全部学科，内容可以为空。5–10 为建议批量，不是已经完成数量，也不是强制每学科都配公式。
3. **创建候选联系**：依据原文及可核查数据提出关系；同符号、相同量纲、同名和文献共现只能成为候选，不能自动作为等价或因果。
4. **审稿与许可**：分配数学、物理、化学相关审查人，记录具体原文、公式号、条件、批注和复核日期；确认使用范围。先由人工策展；工具辅助解析、不能自动发布。
5. **交互与回归**：实现完整学科列表、动态邻居和出处；验证「有关系」「无已审关系」「多个可选关系」「回环」「来源失效」「访问受限」等状态；静态只读公开包优先，不直接发布现有单机服务。
6. **邀请测试**：5–10 位目标用户按真实问题逐点探索，观察能否分辨关联类型、复述前提、打开来源、继续与返回。未经用户试用的满意度和学习效果均不得宣传成结果。

首发候选仍暂定 `v0.66.1-beta.1`，须核验实际标签是否可用、满足之前的科学/许可/版本/安全门槛后才发布。按已审核公开内容逐步扩充，不以覆盖率强迫创建没有依据的关系。

## 7. 度量与失败条件

面向公开快照、分学科、分节点类型分别统计：① 公开节点中至少 1 条经过双端点和关系审查的跨学科链接的节点数/公开节点总数；② 数学、物理、化学栏目分别有已审核内容的节点数/公开节点总数；③ 已审跨学科关系中有条件和来源的数/已审跨学科关系总数；④ 用户能正确解释所选关系及其条件的人数/参加该任务人数。

「栏目存在率」只检查界面，不等于科学关联覆盖率。不能将跨学科比例作为必须 100% 的发布目标：它可能激励人工造边。对暂无可靠联系的节点保留真实空状态，明确这是知识覆盖缺口；以审稿质量、用户理解和有价值的联系优先。

## 8. WorkBuddy 任务

| 任务 | 具体输出 | 验收要点 |
|---|---|---|
| 多学科节点详情 | 全部学科直接列出相关内容、空状态、来源、逐级继续探索、返回和列表视图 | 同一节点唯一身份；跨页面/画布状态一致；手机可用 |
| 关系与审查模型 | 增量节点和边说明、来源、条件、审稿及版权状态 | 原始数据不覆盖；公开前双端点和内容审核通过 |
| 小批试点 | 策展 5–10 个候选节点与跨学科关系；保留无关系情况 | 逐条附原始出处、适用前提与学科审查，许可明确 |
| 公开数据服务 | 已审只读包、按需加载、游标/版本与分页 | 不能通过搜索/统计/推荐/导出发现内部受限数据；连续探索不混版本 |
| 验收 | 单位与定义域反例、审查/许可缺失、重复/循环、分页、空和错误状态、用户反馈 | 自动检查与人工审稿分列，缺前置不得当通过 |

## 9. 四项要求

### ① 专家补做项

数学专家审跨式变形及定义域，物理/化学专家审模型边界、状态和物质身份；科学教育专家审是否让用户误以为关联就是因果；知识图谱与许可专家审同名歧义、来源共同血缘和公开权限。若独立反例显示某条联系不成立，应撤销该联系；通过明确前提、原始依据和独立审查后，可关闭对应问题。以上为建议，并非已完成专家审稿。

### ② 最原始素材

本轮已读取上轮审计、旧方案和 BIPM、NIST、Rhea 官方资料；示例参考 OpenStax 教材原章节。已有图和评估报告是项目加工/汇总材料。每条将公开的公式仍需取得对应上游原文、完整公式和条件、版本、页码/记录 ID 与授权；用户理解需要真实访谈和操作原始记录。未取得的不得当成已有证据。

### ③ 方法与工具

| 问题 | 输入 | 步骤 | 工具及版本 | 输出 | 通过标准 |
|---|---|---|---|---|---|
| 原公式保留 | 全量原文件、旧图及 ID | 计划哈希、备份恢复与新旧映射对账 | Git、SHA-256、Python，执行时记录版本 | 清单和恢复日志，未执行 | 原件不变、映射无未解释缺失 |
| 关系是否成立 | 公式原文、定义域、物质/量状态 | 计划专家检查、构造反例及必要的符号/量纲验证 | 领域专家，SymPy/pint/RDKit，版本待记录 | 逐关系审稿与回归记录，未执行 | 来源与前提支持所写关系，独立复核通过 |
| 学科列表和持续探索可用 | 公开快照与用户任务 | 计划逐节点、分页、回环、权限、不同设备测试 | 浏览器、接口测试，版本待记录 | UI 与 API 测试日志，未执行 | 真实空状态、版本一致、不泄露受限数据 |
| 用户理解 | 5–10 位拟招募用户的具体任务 | 计划观察、口头复述关系及前提 | 访谈记录，设备待定 | 原始记录及分子/分母，未执行 | 预先确定任务阈值，反例可推翻设计 |

### ④ 独立验证

A 上游原始材料与 B 项目图对账仅证明保真；C 项目文档是建议；D 的独立领域审稿、权利授权、用户观察和外部重建必须留存真实记录。当前没有针对本新设计的独立审稿或用户试用结果。

反驳条件：若某条学科链接经原文及专家证实不成立，应撤销，不为栏目填充率保留；若用户普遍把关联误解为因果或推导，应修改关系说明和界面；若审稿或授权未完成，栏目以诚实空状态展示，相关内容不得公开。
