# STTP v0.66.0 全面测试评估与发布整改报告

评估日期：2026-10-29；被测资料截至：2026-10-28；读者：项目负责人、WorkBuddy 开发人员及科学顾问。

## 决策摘要

**结论：暂不将现有 v0.66.0 宣布为可公开试用的科研可靠版本。先修复公开样例的 ATP 数据错误、科学判断与发布证据问题，再制作有明确边界的邀请制预览版本，开展真实用户验证。** 可以立刻组织访谈和由项目人员陪同的内部演示，但不得将目前完整图直接公开或对外宣称结果已获科学验证。

依据不是对项目路线的否定：样例和全图发布校验分别报告 33/33、36/36 通过，但独立结构核对发现公开样例的 ATP 分子式和结构不一致；冻结题库 40/40 通过，但题库外单位与数值反例失败。工程验收通过仅证明检查所覆盖的条件，不能代替科学正确性和真实客户价值。

本次目标是覆盖项目主要领域及发布链，并对无法执行之处明确标记；**不声称对 229 个源码文件逐行审计、不声称完成所有科学数据的逐条专家复核、也不声称完成公网和云端生产验收**。以前的主要样例和运营检查不足以代表全面验收，本报告增加完整图、上游原表、原始本体、数学物理化学反例、前端操作和发布检查。

## 3. 主要问题和整改

### P0-1：公开样例 ATP 结构与分子式矛盾

`BC:mo:atp` 在公共 200 节点样例中；分子式为 `C10H16N5O13P3`，结构经 RDKit 计算为 `C10H14N5O7P`，仅一个磷。参见 [化学核对明细](chem_semantics.json)。这是**同一节点两个字段相互矛盾**，即使格式校验 33/33 全绿仍存在。应回到可核对的权威 ATP 原始结构记录，核对质子化态、分子式、结构和来源，并复核涉及该节点的边及导出物；在更正前将它从任何对外演示删除或明显标注错误。验收：顾问独立签认原始 ID 与结构，RDKit 元素组成与指定态公式一致，重新生成样例、清单及散列，增加明确针对本节点的回归和反例。

其他 7 个差异不能直接当成全部错误：`BC:mo:amino_acid` 名称称通用氨基酸，但示例 SMILES 和分子式不同；4 个 ElementKG 卤素记录可能涉及上游 SMILES 的隐式氢；2 个 ChEBI 记录需核对芳香性/氢与来源。132 个解析失败全部来自 ChEBI，需分类确认是否为泛化结构或数据缺陷，不能直接计错误率。若独立原始记录和不同 RDKit 配置证明某一差异来自约定而非错误，则该记录的缺陷判断撤销。

### P0-2：科学答案与评测范围表述不可靠

`12_评测/eval_runner.py:128` 将 `/` 替换为空格：`m/s` 被计算为 L·T，而非 L·T⁻¹；`J/mol/K` 的摩尔和温度指数被算成正数；`mol/mol` 被算成 N²。含显式负指数的 `m s^-1` 对照能算对。该缺陷在当前评测运行器内实际复现，不等于所有前端 API 都走这段代码。整改：采用具有明确语法和括号规则的单位解析器；无量纲应有明确表示；覆盖 SI 大小写、连除、指数、括号、异常输入。

`verification_loop.py:393` 对 `x/x = 1` 在不假设 x 非零时给出 VERIFIED 和「实数域恒成立」，但 x=0 处左式未定义；`(x²−1)/(x−1)=x+1` 对 x=1 同理。证据尾部虽写「未覆盖定义域奇点」，仍与「实数域恒成立」冲突。将结论改为「在共同定义域内经符号化简相等」，显式保存非零等条件；无法提取定义域时转待复核。反例 `sqrt(x²)=x` 已正确拒绝，说明修复了正性假设的部分问题。

运行器对 `delta_g_kj=NaN` 返回 answer NaN、无穷大焓返回 answer Inf；极端值引发 OverflowError；`s_sign_to_direction` 以负 ΔG 推断 `K>1` 及正向自发，只有字段明确为标准反应吉布斯能并约定标准态时，K 的判断才有依据；实际组成下自发方向应使用 ΔrG 与 Q，不可混同。为每个数值输入做有限性、单位、标准态、温度及溢出处理；超出适用域一律拒答或明确异常。见 [反例输入与结果](science_probes.json)。

### P0-3：发布物与可重现身份不足

`VERSION` 与 README 为 `0.66.0`，`pyproject.toml:30` 包版本仍为 `0.45.0`；README 称 Python 3.11+，实际包约束为 `>=3.11,<3.12`。安装包仅包括 `sttp_cli` 薄封装，须找到仓库根，不能把它描述为脱离仓库即可使用的自包含 wheel。统一版本、支持矩阵和安装方式；锁环境按平台记录并验证。由第三人在 Windows 和至少一个 Linux 干净环境按发布说明操作，记录 clone/tag、安装时长、依赖、启动、查询、退出码、产物哈希。当前仅取得可用 3.11.9 环境，并非陌生用户 30 分钟验收。

**实际数据包构建失败：** 隔离副本的版本台账上一条绑定图 `f8ebee052d1b…`，现图为 `fec51bf0f201…`，构建器判断该变化应从 `dataset_v1.1.1` 升至 `dataset_v1.1.2`，而配置未升，S11 FAIL，退出 1，临时包未提升。先核实该台账与快照的真实性及版本规则，再按实际变更升版、重新完整构建、离线下载校验并验证散列；本轮跳过确定性步骤，不得声称已验证确定性。日志为 `logs/dataset_build.log`。

`sttp.sh:387` 的第 10 步调用后没有像相邻步骤一样 `|| exit $?`，而脚本使用 `set -u`，并非 `set -e`；静态上存在该步失败后继续执行、后续步骤成功掩盖失败的路径。应在隔离测试仓库注入第 10 步失败并验证总退出码非零，再补失败传播；本次尚未在 Bash 实测此掩盖路径。等价证明检查全跳过退出 0 是已实测的另一个风险，发布模式下应返回前置缺失码并列 SKIP 数。

输入包的 A1 已看到脚本自称 14 个步骤；A2 评测声明增加图哈希是改进，但输入包将其描述为全面证明仍不充分：报告要同时绑定任务、代码、依赖、数据、运行参数、环境及结果，重新执行时对比实际读取的输入，而不是仅比较报告字段。对所有用于发布、许可和科学声称的关键报告实行这一规则；需要实际数据变化、删除输入、同规模不同内容三类负对照。门禁数量不是质量目标。

### P1：可信分级、前端、化学语义与安全

- 当前无 Git 副本：35,183/48,813 条有依赖记录的边均为 `needs_review`，13,630 无记录；按同一快照、同一证明和 ledger 参数独立循环计算，与服务侧边级状态差 0/35,183。无证明与有证明在本环境差 0；这**不能**回答开发仓库曾相差 32,609 条是否修复。取得原仓后在相同 HEAD、图哈希、registry、attestations 条件下按 edge ID 对比，列出差异，不用总数代替逐项对账。全图不是都科学错误，只是证据身份此处不可确定。
- Rhea 接入把等号两侧转成 reactant/product，相关 4,534 条边的字段中没有独立化学计量数或区室字段。等号左右只是书写方向，不能单独推出反应在实际条件下不可逆、可发生或跨膜方向；保留原方程、计量、区室、方向和条件并设 unknown。上游原始 Rhea 记录本轮未取，方向准确性未判定。
- 数学图中 Formula 5,090 个，但只有 30 个节点有非空 applicability 字段；该字段覆盖率 30/5,090 不等于 30 条公式物理正确。应先针对目标用户任务补完整命题、假设、变量定义及原论文证据，而非按节点量扩张。
- 从吉布斯路径任务切换至乙醇组成任务，所选 `OM:mo:ethanol` 导出参数仍为 3 跳；完整图返回 40 节点/39 边并截断，多跳扩展带入其他分子；任务说明称一跳即可得到 H/C/O。本次只证明切换场景下保留了三跳，不证明全新用户首次默认也是三跳。初始图形部分位于画布外，点「适应」后才看全。应在切换到组成任务时明确重设为 1 跳，先展示可读的组成清单和来源，再提供扩展；内容为空、截断、过期与缺证据分开解释。`乙醇` 中文查询返回 no_result 而 `ethanol` 有命中，应补中英同义词与可见提示。
- 本地 HTTP 服务返回 `Access-Control-Allow-Origin: *`，无鉴权；自身也提示无 session_id 时不记账、不限流。严禁直接改成公网服务；若要公开 API 必须加鉴权、配额、日志脱敏、租户隔离、访问控制与安全评估。Python 官方明确不建议将 `http.server` 用于生产：[文档](https://docs.python.org/3.11/library/http.server.html)。`_parse_math` 调用 SymPy `parse_expr`，本次以无害输入 `__import__("builtins").sum([1,2,3])` 得 6；其是否从公网可达尚未证明。不要把不可信文本传入该解析器，官方亦说明它使用 eval：[SymPy 文档](https://docs.sympy.org/latest/modules/parsing.html)。

## 4. 对输入包十二问的明确答复

1. **v0.66.0 是否发布？** 当前不作公开科研试用版；修 P0 后发布邀请制 `v0.66.1-beta.1` 候选，前提是核对现有标签和版本策略。若 0.66.0 已发布，不能覆盖同名资产，应发布新版本；若尚未发布，也可以选择标记 0.66.0-beta，但必须全链统一并冻结。
2. **公开边界是否自曝其短？** 透明披露是加分，使用可读的范围和任务示例说明「已覆盖／未覆盖／如何查原文」，避免使用「残体」「全部卖点消失」等未经客户验证的结论。
3. **版本号？** 0.66 不表示 66% 完成；0.x 通常代表仍可变化，beta 标签能更清晰传递试用成熟度。版本身份必须统一：[SemVer](https://semver.org/)。
4. **最小发布阻断？** 修正公开 ATP 与相关展示、科学错误及其宣称；补真实可分发数据核查；可复现版本和安装；修正失败/跳过的门禁出口；完成核心用户流程与可用的反馈渠道。A1 步数文案属 P2，但若影响流程解释应修；A2 虚假输入身份对能力宣称是 P0，并非单纯修文案。
5. **GNN？** 立即修改 README，把 GNN/LLM 称为实验功能，主线写检索与证据导航。输入包引用的 GNN 负增量是旧报告结论，本轮未重训，不能声称独立证实所有模型都差；后续只在真实任务需要时重做隐藏集和规则基线比较。

8. **14 道门禁？** 有价值，但把快检查（格式、关键科学回归、核心查询）与慢检查（全量、原始重建、红探针）分层：开发时快跑，合并和发布前全跑；按真实故障记录决定退役，不能删掉仍能发现重要问题的测试。
9. **Skill 优先还是 Web？** 先跟 5–10 名目标用户用人工陪同任务原型比较；Web 和 Skill 都只是入口，先确定证据卡能否帮助实际研究。Skill 不会天然解决数据许可或模型幻觉；未经审核不要把全图接公网 LLM。用可许可数据、只读受限接口和回答逐条引用，输出必须允许拒答。

11. **一周可验证假设？** H1：研究生查一个公式的符号、条件和来源，使用 STTP 比现有办法节省净时间；H2：生化研究人员核对具体反应参与物及溯源时，证据卡降低漏检；H3：跨学科入门者通过路径找到至少一个可核查的新参考。每项先招募 5 人、每人用真实任务，与其原流程交叉比较；若多数人不能完成、净耗时更长、或不愿重复使用，否定相应假设。样本小只能决定继续探索，不能估计总体市场。
12. **只能做一件事？** 邀请 5 位具有同一类真实任务的研究者，安排 30–45 分钟观察式访谈和安全样例操作，记录原流程、任务耗时、错误、复用与是否愿意参与下一轮；先人工实施，不等完整公网系统。
