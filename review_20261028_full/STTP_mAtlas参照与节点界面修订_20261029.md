# mAtlas 参照与 STTP 节点界面修订

2026-10-29；状态：产品方案，未实施。阅读依据：[mAtlas 仓库说明](https://github.com/madvay/mAtlas)、[用户指南](https://atlas.madvay.com/guide/)、[公开数据说明](https://atlas.madvay.com/data/)、[AI 集成](https://atlas.madvay.com/ai/)；本次未克隆项目、逐文件审计或独立运行测试。结合 [STTP 上轮评估](STTP_全面测试评估与发布整改报告_20261029.md) 和 [节点设计](STTP_节点跨学科联系设计补充_20261029.md)。在线材料可能更新，统计均为所访问页面显示值，而非本次独立数算。

## 1. 用户对节点详情的明确修订

不设置数学/物理/化学三个入口。打开一个节点或公式后，在同一详情区内按可扩展的**全部项目学科目录**直接列出各科与该节点相关的已审核内容；每科内容量小时全部展示，无需切换标签。该科无可公开的审核内容时保留科目名称与空内容区，不自动填充，不暗示确实不存在科学联系。学科目录由配置维护，可增加生物、天文、材料、工程等；首版实际有哪些科目依项目目录而定，不硬编码为三项或声称已涵盖所有学科。

```text
理想气体状态方程 pV=nRT       来源 / 条件

数学
 · 恒压、固定物质的量下的比例关系 → 查看节点及条件
物理
 · 理想气体模型、压强与温度 → 查看节点
化学
 · 物质的量、摩尔质量 → 查看节点
生物
 · （暂无已审核内容）
……按学科目录继续

路径：起点 → 当前节点       返回 / 继续探索
```

示例为拟策展内容，不证明本库已经实现。总目录较长时可保持全部学科名可见，空内容用一行表示；已审核内容超过可读阈值时再按组显示「更多」，但不加载整张图。允许用户继续进入相关公式/概念；每条有关系类型、简短说明、方向、适用条件与出处。若整个节点无已审核联系，展示「本版本暂无已核对的相关内容」。仅显示授权可公开数据；空栏不暴露未审或受限数据的数目及名称。搜索、图视图、列表、回退和多跳按前一方案执行。

## 2. mAtlas 与 STTP 的关系

mAtlas 自称为连接数学、物理和化学的、带来源的单一图谱，并同时支持人的探索与机器使用；方向上与 STTP 高度相似。其用户指南展示概念、带类型及说明的关系、来源、主题故事、视图和持续探索。用户指南页面显示 1,330 canonical concepts、2,165 authored relations、45 domains、34 stories/views 和 64 construction junctions；这是该页面自述，不是独立核验的科学正确性，也不可与 STTP 的所有节点/边按相同语义直接排名。[mAtlas 用户指南](https://atlas.madvay.com/guide/)

| 对比维度 | mAtlas 可观察的设计 | STTP 在上轮审计中的情况与机会 |
|---|---|---|
| 核心对象 | 以策展概念、带类型的关系与来源为中心，支持学科交叉 | 拥有公式、元素、分子、反应与大量关联；部分字段和语义还需审查 |
| 使用方式 | 故事、视图、概念页面、筛选、搜索、图和键盘操作 | 已有局部子图、搜索与任务入口；可增加逐节点各科说明及路线 |
| 科学表达 | 节点/关系有语义及说明；多输入构造用 AND 构造结点 | 可借鉴区分公式假设、反应条件、变量绑定；不把多前提拆成多条单独充分的边 |
| 数据与可复现 | content/schema 分版、哈希、节点单条与关系记录、SQLite 和 RDF；latest 会覆盖 | 现有全量规范图、样例、许可分区和 manifest；需修版本、公开投影并保留不可变历史 |
| 用户范围 | 自述提供源数据与专家级主题，也有通用用户导览 | 首版以中文科普和具体问题为切入；这是差异化假设，不是已验证优势 |
| 数据规模 | 指南数值是策展概念及关系口径 | STTP 2026-10-28 快照 9,750 节点/48,813 边，5,090 Formula 标签；其中大量 `has_symbol` 等边，不宜比较谁知识更多或更可靠 |

**商业判断**：相似意味着用户可能有可参考的使用方式，也意味着 STTP 不能再把「跨数理化知识图谱」说成独有。真正可验证的差异可能是中文解释、公式与变量细节、具体化学记录和循序渐进学习体验；需要对照用户试验后才知道是否成立。不能仅靠本项目节点更多宣称更先进。

## 3. 优先借鉴哪些设计

1. **直接的节点详情与语义关系**：从概念进入，列出具体连接、原因和出处；关系不使用一个模糊的「有关」。mAtlas 的指南明确箭头类型、方向和描述不同，图形位置不是证明。[关系指南](https://atlas.madvay.com/guide/)
2. **故事加自由探索**：为用户提供几条步骤式主题路线，但路线中的每个节点可以继续浏览其他已审核关系；可从中途返回，保留路径和快照。
3. **一个节点，多学科身份**：主身份与多个领域标签共存，不复制节点；STTP 直接列出所有学科的相关内容，符合本次修订。
4. **多输入条件**：一个结论需要 A 和 B 等共同条件时，使用显式条件集合或构造节点，图和文本均显示「共同需要」；不能把 A→结论误解为 A 单独充分。mAtlas 用户指南将 construction junction 定义为 AND。[用户指南](https://atlas.madvay.com/guide/)
5. **稳定单节点数据与历史版本**：每个节点和其直接关系可以单独获取；数据、schema、内容、许可证和来源均带版本/哈希。mAtlas 明确其 `/data/latest/` 被新发布覆盖；STTP 要保留不可变历史快照并提供失效提示，而不是只保留 latest。[数据页面](https://atlas.madvay.com/data/)
6. **文字与无障碍**：概念页面、目录、图形之外的列表及键盘路径；移动端直接阅读节点详情，不依赖看清大型画布。

其全局展示及布局可供学习，但 STTP 大图库仍需按节点/分页加载。不要将它的前端全图加载方式视为对 48,813 边的大图库已经实测可行。它的图谱状态布局和边不构成科学证明，也不应把视觉位置当作学科先后或因果。

## 4. 许可和集成方式

项目 README 明确区分：主体软件 Apache 2.0，`content/` 中的编辑内容及由其编译或发布的图、schema、故事等为 CC BY-SA 4.0，第三方材料各有条款。[mAtlas 许可声明](https://github.com/madvay/mAtlas#license)

- **学习设计思想**：参考交互、关系建模和流程；不要直接复制其受版权保护的文字、插图和数据而不处理许可。
- **复用代码**：逐文件确认属于 Apache 2.0 部分、检查依赖并保留许可与 NOTICE；确认实际代码和项目依赖兼容，当前仅为阅读 README，未进行逐文件授权审计。
- **引用或导入其数据**：单独记录来源、版本、哈希、适用许可和修改，确认署名和潜在相同方式共享义务以及最终公开形式；不能把 mAtlas 内容直接换标为 STTP 的 Apache 2.0 数据。是否及何范围构成改编、聚合或涉及数据库权利须针对具体处理和地区核查，必要时咨询专业人士。
- **推荐顺序**：先作为对照学习；在独立隔离的试验样例中验证概念 ID、术语、来源、条件和许可可追溯；确认后再决定是否纳入正式数据。未经确认不导入主图，不将未核实内容公开。

mAtlas 的 AI 页面提供本地工具、数据、Skill 和工作台，并明确没有远程查询服务。[AI 集成](https://atlas.madvay.com/ai/) STTP 后续可以参考其「结构化事实 + 关系原文 + 引用」协议，但首版无需先接入大模型或训练模型。

## 5. 具体给 WorkBuddy 的任务

| 优先级 | 工作 | 可交付与验收 |
|---|---|---|
| P0 | 用本节取代固定三入口设计 | 节点详情同屏按配置列出所有学科；无内容显示为空，非硬编码三个；用户可见内容少时一次完整列出 |
| P0 | 保存现有图与原始公式 | 基线 manifest、原数据哈希、备份与恢复、旧 ID 映射；本任务不得覆盖或清空原图库 |
| P0 | 合法公开投影 | 节点、关系、详情、搜索、图、导出一致只显示已批准内容；审稿缺失或许可不明不得放行 |
| P1 | 关系卡与继续探索 | 每条写关系、方向、解释、条件、来源；点击进入下一节点，一跳分页、回退、去重，空状态清楚 |
| P1 | 两条主题故事和独立节点页 | 选择小批经审核节点；用户从故事进入，仍可自由探索已有关系；显示快照和来源 |
| P1 | 多前提关系 | 建立前提组或构造节点，界面表达 AND；不得将一项前提单独当作充分条件 |
| P1 | 小样对比 mAtlas | 不导入正式图，仅以公开文档和获许可隔离样本做 schema/术语/来源/许可差异；形成去留清单 |
| P2 | 可复现导出与无障碍 | 按节点的静态记录、manifest、版本/哈希、列表与键盘；保留历史快照，明确最新版本与旧版本 |

首版上线仍以既定发布门槛为准：ATP 问题处理、科学反例、版本/数据包、独立审稿、许可、前端、部署及反馈闭环。mAtlas 并不使这些门槛自动达成。若人员和专家及时到位，可在既定 2–4 周 Beta 计划内先验证一个小主题；不是新项目进度承诺。

## 6. 四项要求

### ① 专家补做项

数学与科学专家会核查每条关系的方向、假设、反例和多前提；教育专家会观察列表是否真正帮助理解；图谱专家会核查同名合并和版本；许可专家会看代码、数据与输出的使用方式。反例显示不成立时撤销该关系；若学科目录过长影响使用，则保留全部科目、调整呈现而不隐藏真实内容。以上是建议，不是专家已完成审核。

### ② 最原始素材

本轮实际读取 mAtlas 仓库 README、用户指南、数据与 AI 页面及 STTP 上轮实测报告；未读取 mAtlas 全部源码和数据原始记录。后续应抽查其源内容、对应论文和原始标准、真实许可证与版本；STTP 仍须回到本地 ElementKG 原表、OWL 和对应来源原文、原开发 Git、用户操作原始记录，而不能用任何 AI 摘要代替。

### ③ 方法与工具

| 问题 | 输入 | 步骤 | 工具及版本 | 输出 | 判定 |
|---|---|---|---|---|---|
| mAtlas 功能及许可 | 仓库 README、用户指南、数据页面 | 本轮逐页阅读并与 STTP 既有审计对照 | Web 页面，2026-10-29；未本地运行 | 本方案及页面链接 | 仅作为项目自述与设计证据，不当科学/市场验证 |
| 节点与关系是否正确 | 科学原文和具体节点 | 拟由领域专家核对条件与反例 | SymPy、pint、RDKit 与人工审稿，版本待实测 | 审稿/回归日志，未完成 | 每条公开关系有来源、条件及审核 |
| 科目列表与持续探索 | 公开内容、学科目录、测试任务 | 拟测空栏、多科、多节点、分页和屏幕尺寸 | 浏览器测试，版本待定 | 用户操作与测试记录，未完成 | 无三入口、全部科目显示、空科为空、真实内容可继续访问 |
| 引用和导入许可 | mAtlas 原文件和下游使用方式 | 拟逐文件审查并核对 attribution/SA | 项目许可证及必要专业意见 | 许可矩阵，未完成 | 授权不明不导入、不公开 |

### ④ 独立验证

A 原始论文和数据可检验科学结论；B 项目图/公开内容是待验证产物；C README/指南为项目自述；D 外部专家、权利人、独立用户和干净环境可验证但本轮没有新增这些审稿或试用记录。反驳条件：若 mAtlas 某项功能与其文档或当前页面实际不同，以可复验版本和操作为准；若某条联系经专家反例推翻应删除；若用户无法找到信息，则应调整布局，不能仅凭页面完成宣称易用。
