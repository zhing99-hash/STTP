## 2. 首先解决什么

论文数量应服务于用户问题。优先选取用户最常探索的主题和可清楚说明的公式：气体与温度、浓度与光吸收、水与分子组成、力和运动、电与能量。每个主题同时准备：① 科普或教材入口；② 对应公式及适用条件；③ 1–3 条明确说明关系的相关论文线索；④ 尽可能提供开放全文链接。数字是第一轮策展目标，不是现有成果或对所有公式的承诺。

论文应区分“原始发现/提出”“实验验证”“后续应用”“综述/教学”“仅在标题或摘要中提及”。经典公式的现代应用论文不能冒充原始发现论文；题目或摘要出现名称，也不能自动认定它证明该公式。没有论文时保留空状态，仍可展示标准或教材。

## 3. 增加数量的数据来源

| 来源 | 适合内容 | 实施方式与注意事项 |
|---|---|---|
| [OpenAlex](https://help.openalex.org/access/pricing/) | 跨学科作品元数据、引用、主题与开放版本线索 | 项目已有采集代码。按具名公式、别名和主题批量获取候选，保存 OpenAlex ID、来源、时间、版本；核对当前 API 用量和计费。官方页面当前说明账户有每日免费额度，不能假设大规模无限免费 |
| [Crossref REST API](https://www.crossref.org/documentation/retrieve-metadata/rest-api/) | DOI、标题、作者、期刊、类型和部分许可字段交叉核对 | 用 DOI 单条查询及增量同步，识别出版类型、更正/撤稿线索；摘要可能另有版权。遵守当前速率限制和 `Retry-After`，参见 [官方限流说明](https://www.crossref.org/blog/announcing-changes-to-rest-api-rate-limits/) |
| [arXiv API](https://info.arxiv.org/help/api/user-manual.html) | 数学、物理及相关交叉学科预印本 | 保留 arXiv ID、版本、预印本状态及可能对应的正式论文；按服务规则请求，逐篇检查许可 |
| [Europe PMC](https://dev.europepmc.org/developers) | 化学、生物化学和生命科学交叉文献 | 利用其 API、OAI 或官方批量渠道；其开放获取内容仍需检查文章具体许可，不能对其他内容随意批量下载 |
| 直接来源与人工推荐 | 历史原始论文、权威标准、学会资料、专家建议 | 保留馆藏或出版方稳定链接及章节位置；标准、教材与论文分别标识，不把不存在的 DOI 补造出来 |

元数据开放不等于全文、图表和摘要可任意转载。先做可追溯的题录、短说明和跳转；只有在具体许可允许且记录证据后才复制全文或做相关再利用。Apache 2.0 项目代码协议不会自动改变第三方论文的权利。

## 4. 采集和接入流程

1. **确定知识种子**：建立首批 30–50 个用户可理解的主题、概念和具名公式清单，记录中英文名、同义词、领域、适用条件和已有原始来源。对符号相似但含义不同的公式分开处理。
2. **发现候选**：复用 `11_真实数据/phase68_paper_fetch.py`，结合公式名称、主题词、跨学科关键词、已知论文参考文献与专家推荐。标题/摘要搜索只生成候选，不直接构造“证明”边。
3. **去重与更新**：规范 DOI（包括大小写、URL 与转义）和 OpenAlex/arXiv ID；无 DOI 用标题、作者、年份辅助匹配，疑似重合留待人工确认。预印本与正式版建立版本关联，保留独立记录和来源，不盲目合并。
4. **元数据与权利**：交叉检查题名、作者、年份、出版类型、DOI、开放状态、授权和撤稿/更正。保存源系统、抓取时间、原始标识、许可链接和错误状态；联网失败与“没有结果”分开。
5. **建立可解释关系**：每条论文—知识关系记录关系类型、匹配方式、证据位置或定位片段、审查状态、领域和适用条件；原始发现、实验、应用、教学和仅提及分别处理。用户界面使用“相关论文线索”与“已核查关联”的不同标签。
6. **发布与回滚**：先进入隔离候选区，生成带来源清单的版本；经过必要的项目方审阅与权利核查，再进入面向试用的数据集。未审核的研究线索如供内部探索，应清楚标明状态。保留原图与上一版可回退的索引。

## 5. 四周试点建议

| 阶段 | 目标 | 可检查结果 |
|---|---|---|
| 第 1 周 | 重跑本盘点，选 30–50 个跨数学、物理、化学的主题/公式；抽查现有 101 条关联 | 种子清单、来源缺口、抽查记录；未知与失败单列 |
| 第 2 周 | 对种子分批查 OpenAlex、Crossref，补原始论文和开放链接 | 可重跑的候选池、去重前后统计、额度与失败日志；不覆盖既有可用数据 |
| 第 3 周 | 标注论文关系类型、位置、授权及条件；抽查不同来源 | 项目方/领域人员的审核记录、错误及修订清单 |
| 第 4 周 | 在两版右侧展示来源、论文类型和关系；邀请目标用户试用 | 可查看的试点版本、检索与理解任务结果、修复优先级 |

以 30–50 个种子、每个 1–3 条关联估算，试点可能形成 30–150 条待核查的论文—知识关联；论文可能被多个种子共用，因此不等于新增 30–150 篇论文。实际数量和时间取决于人员、API 配额、资料可得性和复核速度，不能当成已经验证的交付承诺。

## 6. 验收指标与四项要求

**专家会额外做**：对低频公式、同名不同义、量纲不一致、只在综述中出现、预印本与正式版、撤稿和明显反例做抽样；检查公式适用域、关联方向和文字片段是否真的支持所写关系。

**最原始材料**：作者或出版方原论文、历史原始版本、标准的官方文本、实验数据及版权声明；还应收集用户经同意提供的原始问题，而不是只使用系统整理好的同义词。OpenAlex、Crossref 和本项目图谱是检索或整理来源，不自动等于原始科学证据。

**方法与工具**：可用 DOI/OpenAlex/arXiv ID 去重、Crossref 或出版方元数据核对、可追溯的文献匹配与人工标注；用原文位置、量纲检查、明确反例和可复现的检索脚本评估关联。对无法合法取得或读取全文的条目标注缺口，不编造全文结论。

**外部证明**：由未参与采集的人盲审分层抽样，分别报告抽样量、判断标准、正确/错误/无法判断数量；邀请目标用户完成“找到相关论文并解释为何相关”的任务；对照原文与其他权威资料，保留可推翻关系的反例。可跟踪元数据完整率、候选去重率、有明确关系说明的比例、抽样正确率及用户任务完成情况；首次试点前不宣称已有准确率，也不凭论文总数证明科学价值。
