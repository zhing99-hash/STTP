# STTP 原有公式保留、数据采集与持续探索方案

日期：2026-10-29。状态：规划与交付任务书，未实施；供项目负责人及 WorkBuddy 使用。承接 [全面测试评估](STTP_全面测试评估与发布整改报告_20261029.md) 和 [阶段发布规划](STTP_科学知识探索版_阶段发布与研发规划_20261029.md)。

## 1. 决策：保留所有原始资产，新增探索视图

项目转向科学爱好者后，已有公式和完整图仍是核心资产。**不删除、不覆盖、不因更换产品方向而重建成只有三条路径的图库**。三条主题只是首版用户入口；底层完整数据保持可追溯、可恢复、可继续加工，面向用户的内容以单独的、经审查的公开投影逐步增加。

「从任一节点无限探索」的合理目标：只要当前公开知识库中有经过审核且允许展示的关联，用户都可以按需进入下一节点、改变方向或搜索更多内容；不会因加载全图而卡死。实际可探索范围仍受现有数据、许可、科学审查和系统容量限制：走到边界时明确显示「本版本暂无更多已审核关系」，允许跳到其他主题或反馈，不自动编造关系、不承诺每个节点都有无限邻居。

上轮实测的 `normalized.json` 为 9,750 节点、48,813 边，其中 Formula 标签 5,090 个；只有 30/5,090 节点有非空 applicability 字段。该数字是 **2026-10-28 快照**口径，不是对最新开发仓的保证；公式节点不等于可靠的、可公开的 5,090 条独立科学定律。

## 2. 数据分层与原有公式处理

```text
L0 原始档案：原始下载文件、授权、版本、哈希，保留原样
        ↓ 可复现采集和规范化
L1 内部知识层：现有完整图及证据，包含已知错误、未审与受限内容
        ↓ 映射、审查、纠错、内容覆盖，不改原始记录
L2 内容与审查层：中文说明、变量/条件、关系解释、审核和版权状态
        ↓ 按用途白名单生成
L3 公开探索层：允许展示的节点、边、卡片、局部索引及来源
        ↓ 按需加载
L4 用户界面：主题故事、搜索、关系拓展、公式与来源
```

L0/L1 保留，不等于许可允许向公众披露。L2 用覆盖记录绑定 `legacy_id + snapshot_id`，不修改 L1 事实值；L3 是独立构建的产品数据，所有公开页面、搜索、统计、API、导出都只能读取 L3。内部管理功能与公开服务须物理或权限隔离，不能靠前端隐藏。

### 2.1 迁移：先盘点、后投影

1. 在 WorkBuddy 完整 Git 仓确认代码 HEAD/tag、工作区差异和原始资产位置；识别不在 Git 的 raw、OWL、缓存、规范图、阶段快照以及授权材料。禁止根据本报告假设最新工作树一定相同。
2. 对已有资产按文件记录相对路径、类型、字节数、SHA-256、来源版本、数据归属和是否可重建；敏感配置只记录存在与否，不拷贝凭证。原件和新实验目录分开；生成两份独立备份并抽样恢复，不覆盖或删除原件。备份位置、负责人和授权由项目决定。
3. 为每次处理建立不可变 `snapshot_id`。原始文件哈希和内部图哈希各自登记；按节点/边/公式类型、来源、字段非空、许可、状态和可复核性生成基线报告。不同分母分开，禁止把 `applicability_status` 字段存在当成具体适用条件齐全。
4. 在新覆盖表中保留原 `id`、类型、来源及旧值；修订存补丁、原因、审查人、时间、证据和新版本。对 ATP 等已发现错误，新版本通过修订记录修正或隔离，旧快照只读保留并显式标记已知错误，不能继续当正确结果展示。
5. 新旧图对账：唯一 ID 集合、节点/边及属性变化清单、来源与许可、hash 和抽样语义；每处新增、改名、合并、废弃必须可解释。禁止为达到计数一致而填空或将未经核实的关系标为已审核。独立人员在隔离环境用备份重放，验证读回和历史版本可恢复。

**验收**：迁移前后原文件哈希不变；`legacy_id` 100% 能在保留档案中定位；新覆盖表对象均指向存在的旧节点及正确快照；任何丢失、冲突或许可变化形成可审计清单；在一份备份上实际验证恢复而不仅检查备份存在。缺原始来源或历史时标未知，不以「已备份现有文件」宣称恢复全部原始数据。

### 2.2 所有公式不需要一次性人工重写

对全量公式做只读清点、机器分流；人工优先处理本版路径。管理状态建议按**独立维度**记录，而不是给每条公式一个含糊总分：

| 维度 | 示例状态 | 意义 |
|---|---|---|
| 科学内容 | 未核对、机器检查、学科复核、存在争议/已撤销 | 量纲或符号计算仅证明其检查范围 |
| 条件与教学 | 原表达式、变量未绑定、条件不足、讲解可用 | 缺定义域、符号含义、单位时不能补猜 |
| 权利 | 未核、内部使用、允许公开、需署名/其他条件、禁止公开 | 各字段与用途分别审核，适用版本和来源明确 |
| 公开状态 | 不公开、内部候选、已批准、暂停展示 | 发布态来自审核流程，不可从置信度自动推导 |
| 来源质量 | 原文已定位、仅二手、来源缺失、来源变更 | 记录页码/公式号或具体可定位记录，来源变更触发复查 |

按主题而不是按数量排队：先一条问题链涉及的公式和关系，再处理被用户搜索、反馈或反复需要的节点；每周评估审稿能力。未能审查的公式继续存在内部知识层，不进入公开投影；可以记录内部待办，不向公众输出受限条目的标题、ID、关系、数量或证据文本。

## 3. 数据来源与持续采集

### 3.1 先由用户需求确定需要什么

由用户的问题、主题卡、反馈和真实搜索未命中产生候选任务，先问：需要什么概念、公式、实体、关系、条件、来源、解释？记录用途、优先级、预期审核人、抓取成本与是否可能公开；确认前不要为扩张节点数量大规模抓取。

建议首期人工整理「水与物质的量」「理想气体」两条路径。第三条的化学平衡/吉布斯关系在具备物理化学审稿后加入；审稿受阻可用元素周期路径替代。先把每条从问题到来源跑通，再扩大到每周新增主题或修复已知缺口。时间和数量依实际审稿能力调整。

### 3.2 候选上游与获取范围

| 内容 | 首选原始素材 | 获取与核验重点 |
|---|---|---|
| 常数及 SI 单位 | [NIST CODATA 常数资料](https://physics.nist.gov/cuu/Constants/)及 SI 原始定义 | 明确版本、数值、单位、不确定度与适用时间，核对使用和转载条件 |
| 反应与物质 | [Rhea 下载与字段说明](https://www.rhea-db.org/help/download)、ChEBI 原始记录 | 保存来源 ID、版本、结构、计量、方向、质子化和区室；Rhea 有方向映射文件，不把方程的左右写法当作真实不可逆方向 |
| 学术引用 | 原论文、出版方原文与 [Crossref 元数据 API](https://www.crossref.org/documentation/retrieve-metadata/rest-api/) | 元数据只能帮助定位，不能证明论文真的包含某公式；全文及图片版权另核 |
| 标识及多语言别名 | [Wikidata 许可说明](https://www.wikidata.org/wiki/Wikidata:Licensing)及其实体记录 | 稳定实体 ID 与引用；结构化数据与其他文本命名空间的许可不同，不能把所有关联图片/文本当成同一许可 |
| 原有数据源 | 本地 ElementKG 原表、OWL，PhysicsBabel 等项目内已有源及其上游 | 保留源与处理脚本；逐条确认来源版本、权利和允许用途；无法确认时仅内部保存，不进入公开包 |

访问 API 或取得原始文件前重新核对条款、配额、署名、缓存、更新与自动化使用限制；抓取结果可用于内部研究不代表可公开或用于训练。NIST、Rhea、Crossref 和 Wikidata 链接是可检查的起点，本方案未完成针对具体记录的授权与科学核验。

### 3.3 数据管线与审核

`任务 → 来源登记/权利核对 → 保存原件与元数据 → 解析成候选 → 精确/模糊匹配 → 科学规则筛查 → 人工核对与纠错 → 许可审核 → 公开投影 → 回归/发布 → 反馈与上游变更复查`。

每次导入记录：来源 URL、原始 ID、版本/日期、原始文件哈希、抓取时间、解析器代码版本、任务 ID、许可证据、错误记录与输入输出计数。重试幂等；中断可恢复，原始失败行可追溯；新增与修改采用候选记录，不覆盖旧记录。各数据源的文本、结构、图片、关系、引用可有不同权利状态。

匹配规则：来源稳定 ID 或经核实的化学标识优先；同名、同分子式、相似 LaTeX 和共同量纲只能作为候选，**不能自动设为同一实体或等价公式**。例如同符号 `T` 可以是温度或周期；公式在不同条件下写法相似未必全域等价。对冲突保留双方值和证据，排队人工处理；不确定性可见，不用自动生成解释代替出处。

公式补齐顺序：① 识别表达式、来源与上下文；② 变量含义、单位、定义域及条件；③ 代表性例子、限制与通俗解释；④ 与概念/现象/量/相关数学的**具体有证据关系**；⑤ 审稿、许可、发布。新增任何自动计算前补单位、定义域、溢出和 NaN 等反例；SymPy/pint/RDKit 仅辅助检查，不得标记完整科学证明。

## 4. 持续探索的交互设计

### 4.1 用户体验：有方向的连续探索

入口同时支持「按问题开始」「搜索」「主题导航」。进入节点后提供：

1. **当前是什么**：名称、学科、通俗介绍、图标、来源；公式含变量、单位、条件和例子。
2. **沿什么方向走**：按实际关系给出「理解概念」「涉及的物理量」「应用的现象」「相关公式」「化学物质」「历史与来源」等分组；无对应已审边时不显示该分组或解释暂无。
3. **为什么相关**：每条关系解释自身类型和证据，区分定义、推导、包含、参与、应用和相似；可展开原文。`相似/同量纲/共现` 不呈现为严格推导。
4. **继续与返回**：一次展示少量一跳邻居，支持「查看更多」、进入任一邻居、搜索、返回/前进、面包屑和恢复路径；同一节点可能在多条路径出现，按 ID 去重并保留访问历史，循环用「已访问」标识。
5. **探索到边界**：明确「暂无更多已审核内容」，可返回上一节点、去同主题、搜索其他内容或提交缺口；缺失和权限状态不得泄露内部受限数据。
6. **易读替代**：提供列表/卡片和图两种视图；图自动适配、文本可缩放，移动端以列表+详情为主；完整键盘路径、屏幕阅读器可读标签和非颜色独占标识。

建议起始交互：每次 1 跳、每页 10–20 条关系、用户选择后再展开；这是初始设计参数，依据实际性能和用户测试调整。进入新节点不自动扩展两跳；不把有限画布作为整个知识库。用户可选择「更广/更深」，但单次请求和当前画布都有上限；超限时把较早节点折叠为历史卡或移出画布，保留书签、可返回路径和可复现快照。逻辑上可以持续跨批次浏览，不是无限增大单次请求、单个会话或浏览器内存。

### 4.2 示例：从水到气体再到数学

以下为**待核对的策展样例**，不代表当前数据库现有路径：

`水 H₂O → 摩尔质量 → n=m/M → 物质的量 n → 理想气体 pV=nRT → R=NₐkB`。

用户点击「物质的量」后可选「相关单位」「常数」「涉及此量的公式」，选择理想气体公式时必须显示该公式用于理想气体及状态变量的条件；后续可走向温度、压力或玻尔兹曼常数。边的类型和上下文须分别核实；水的状态不能被默认当作理想气体，导航链不表示水在任何条件下都满足此式。每一步能查看原始出处。

## 5. 技术方案：静态 Beta 与动态扩展两阶段

### 5.1 复用现有能力与缺口

当前代码已有 `/api/search`、`/api/subgraph`、`/api/nav`、`/api/formula`、`/api/neighbors` 和前端任务/局部图组件；`viz_server.py` 内有会话预算，缺 `session_id` 时不记账。上轮测试确认有乙醇任务保留上一任务三跳、图首次偏出画布、中文「乙醇」未命中等体验问题。现有能力提供工程基础，不等于已支持节点级分页、连续跨会话历史、公开数据隔离或安全公网。

| 阶段 | 数据与服务 | 可持续探索范围 | 要求 |
|---|---|---|---|
| Beta：推荐 | 已审核 L3 生成只读静态分片及公开搜索索引 | 可在**已发布**节点与关系中继续逐步探索，直到边界；新增数据需重建发布 | 分片可按节点 ID 获取，索引与内容均是公开投影；客户端本地历史；单页上限；不部署内部 HTTP 服务 |
| 后续动态版 | 独立生产 API + 可索引的公开图存储 | 数据更新后可继续探索已批准内容，支持分页、过滤及增量 | 身份与权限、速率限制、审计、监控、缓存、版本绑定、回滚和部署评估；具体技术按容量实测选择 |

静态分片可以扩展出分页目录；如果只有三条主题、一小部分公开图，就只能探索这部分，不能声称搜索了全部内部图库。NetworkX 可先作内存验证；是否迁图数据库取决于数据量、访问、增量更新及运维预算，先做基准再选，不把 Neo4j 当作实现此体验的先决条件。

### 5.2 建议的公开接口契约（后续设计，非现有实现）

以下是给 WorkBuddy 的目标契约，可由静态索引模拟或由生产 API 实现；不可当成已有接口承诺。

```http
GET /public/v1/nodes/{id}?snapshot=<公开快照>
GET /public/v1/nodes/{id}/neighbors?relation=<类型>&limit=20&cursor=<游标>&snapshot=<公开快照>
GET /public/v1/search?q=<关键词>&limit=20&cursor=<游标>&snapshot=<公开快照>
```

邻居响应应有 `snapshot_id`、`node_id`、已公开的 `items`、每条边的关系和解释、来源链接、`next_cursor`、`has_more`、`status`；提供的字段、数量和索引**只能由 L3 数据生成**。无更多结果、未找到、版本已下线、请求不合法、服务暂不可用分别表达；拒绝返回受限条目的 ID、来源、标题、计数或原始证据。`has_more=false` 只指该公开快照与筛选条件下无更多。

游标采用稳定排序（明确关系权重与稳定 ID 决定次序）、绑定公开快照、中心节点、过滤器和用户可访问范围；动态 API 使用签名或服务端不透明游标并校验过期/篡改，静态包用不可变快照和一致分页索引。重试幂等，新增数据产生新快照；旧链接若保留则继续指向旧数据，否则明确提示旧版本不可用并允许用户选择新版，禁止静默混合。权限变化、版本切换或筛选变化时不复用旧游标。

**会话与资源**：仅保存展示路径及必要书签（无账号可本地保存），服务端即使没有 session ID 也要限制请求速率与单次工作量；会话预算不等于安全限流。对节点/边、响应体、页大小、深度、请求耗时、并发和客户端缓存分别设置限制，并按实测调整。每次返回均有可恢复的分页，不因为达到单次预算就永久阻断用户继续探索。无限高并发、无限图大小或无限存储都不是承诺。

## 6. 内容安全、质量和持续运维

- 科学正确性：不能只看边的 `verified`；要说明到底验证了量纲、原子计数、数学变形还是来源存在，哪些条件未检查。无原始依据或许可的内容不公开。
- 回归案例：ATP 同节点分子式/结构冲突；`m/s` 分母、`x/x` 零点、NaN/Inf；切换任务跳数、中文别名、图形适应、路径回退与去重；受限节点从搜索、推荐、边、日志面向用户响应和导出均不可见。
- 性能：基于设备和数据规模测每次首屏、搜索、展开与返回的耗时、响应大小、内存占用和连续访问后稳定性；记录 P50/P95、设备、网络、样本量及数据版本。建议先用小规模测试设目标，不能把预估数写成实测结果。
- 安全和可靠性：静态资源固定版本、检查依赖许可证、HTTPS、限制文件类型、转义文本、防脚本注入、发布包中不含内部图或凭证；动态版增加认证授权、速率限制、错误/监控和回滚。`parse_expr` 不接受不可信文本；若启用解析必须改用受限语法和隔离。
- 外部参考链接可能失效或更版：定期检查并记录访问时间、来源版本和变更，涉及已公开结论时暂停或重新审稿。建立错误反馈、撤稿/纠正、影响范围追踪和历史版本说明。

## 7. 实施计划、依赖与验收

### P0：保护现有资产与盘点（约 2–4 工作日）

在完整开发仓核对 HEAD、资产和权限；创建清单、独立备份及恢复测试；只读统计公式覆盖和许可；生成旧 ID 映射。交付迁移清单、分布、缺口表、回滚演练记录。无完整 Git 或备份不可声称历史已保全。

### P1：可发布的连续探索 Beta（约 2–4 周，含 P0；审稿及时到位）

优先完成一至三条有审稿和授权的主题、覆盖层、静态公开投影和逐节点分页；首页/搜索/图/卡片/详情/来源/返回/反馈。通过上节的科学、隔离、版本、UI 和安全验收后，以 `v0.66.1-beta.1` 或未占用的相邻版本邀请 5–10 人试用。若资料或审稿未齐，允许缩减主题数，不允许用未审内容补足覆盖。此阶段不做全量公开、模型训练或在线自动生成新边。

### P2：扩大公式覆盖（首轮反馈后约 4–8 周的工作量预估）

依据用户搜索和反馈，每批补齐引用、条件、变量、中文、跨学科关系，版本化发布；增加审稿和变更工作台。采集多少取决于数据权利与审稿吞吐，先做小批质量和成本测量，不预设全部 5,090 个公式都会变成可公开卡片。

### P3：规模化服务（仅当用户量和功能需要证明时）

基于实测引入生产 API、存储/索引、细粒度权限、线上审核与监控；评估自然语言入口或可选 AI 解释，只能基于公开、可引用、经审核的证据且必须可拒答。是否发展科研辅助线由研究人员的真实任务、独立评测及数据权利决定，不从科普浏览成功直接推导。

时间假设：1 名了解现有系统的工程师、1 名内容/运营人员和及时响应的数理化审稿支持。数据量、项目人员与专家可用性未核实；如人力或许可不到位则延期或缩小范围。

## 8. 工作拆分与必须交付物

| 编号 | WorkBuddy 任务 | 交付 | 验收 |
|---|---|---|---|
| W1 | 全量资产只读清点、双备份和恢复 | 输入 manifest、备份/恢复记录 | 原文件哈希不变，ID 丢失和冲突有清单 |
| W2 | 公式与关系的内容覆盖和审查状态 | schema、示例条目、审查记录 | 不覆盖原始记录；每条可追溯到快照与来源 |
| W3 | 第一条路径采集和独立科学/许可复核 | 节点边清单、来源、说明、测试 | 条件明确、无未关闭严重错误，权利可查 |
| W4 | 公开投影构建器及静态节点索引 | 版本化公开包、哈希与许可证清单 | 限制内容从所有接口与文件不可见；节点边无悬空 |
| W5 | 首页、节点卡、连续探索与路径恢复 | 前端页面、桌面/手机可用结果 | 按页/按节点加载、可返回、空结果真实、不出现全图加载 |
| W6 | 回归与发布门禁 | 测试记录、负例、版本及发布说明 | 科学反例、权限、快照/游标、性能、回滚按清单验收，跳过不计通过 |
| W7 | 用户试用与反馈 | 观察记录、完成率及主要缺口 | 5–10 名目标用户方便样本，给分子/分母，不推断总体 |

优先顺序 W1 → W2/W3 → W4 → W5 → W6 → W7；内容审稿、开发和用户招募可并行，但公开投影依赖审稿和授权。

## 9. 四项要求

### ① 专家补做项

| 专家会补做什么 | 为什么改变结论 | 做法与完成条件 | 什么条件下可关闭 |
|---|---|---|---|
| 数学专家审符号重名、定义域、相似式和推导方向 | 自动合并会把不同问题误认为同一公式 | 回原定义与证明，给反例及条件，审每条对外推导边 | 原始命题和明确前提下通过独立复核 |
| 物理/化学专家审条件、结构、计量与方向 | 图可连通但不代表科学关系成立 | 核对原结构、相态、温度、量纲、计量、反应方向及上下文 | 相关源与专家审查闭环、冲突解决 |
| 图数据专家审迁移与版本/分页一致性 | 原记录丢失、循环或混合快照会破坏资产与体验 | 清单、双备份恢复、ID 差分、游标与快照故障注入 | 零未解释丢失且可重放、回滚和切换版本通过 |
| 许可与科学教育专家审公开边界和误导 | 可访问资料不一定能分发；好看不等于理解 | 授权台账、内容审稿与用户观察 | 对应用途获得确认；目标用户理解表现可复核 |

上述是预计专家会采取的步骤，并非真实专家已经完成审稿。

### ④ 独立验证

按输入包分级：A 为上游原件复核，B 为内部图/公开投影，C 为项目报告，D 为外部来源/人员。A/B 对账证明保真，不证明原始科学事实正确；D 的独立学科审稿、权利人授权、用户观察、独立环境重建和恢复测试需要真实记录。本方案对这些工作均为建议，尚未完成。

反驳条件：若差分或恢复发现原记录丢失，迁移不可验收；若能证明某条关系仅同名或共现而非所宣称语义，立即撤回对应公开边；若许可证不允许计划用途，相关内容不发布；若用户多轮仍无法发现下一步或看不懂关系，应重做交互；若真实测试显示静态分片不满足访问或更新需求，再转动态服务。
