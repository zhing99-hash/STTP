# STTP 科学知识探索 Demo：功能清单与开发进度

日期：2026-10-29；状态：**负责人已确认，独立本机 Demo 已实现并完成有限验证，公开发布审查尚未完成**。下文保留原定计划；实际实现、差异和测试范围以 [Demo 验收记录](../06_PoC/demo/验收记录.md) 为准。依据 [全面测试评估](STTP_全面测试评估与发布整改报告_20261029.md)、[数据与持续探索方案](STTP_原有公式保留_数据采集与持续探索方案_20261029.md)、[mAtlas 参照与节点界面修订](STTP_mAtlas参照与节点界面修订_20261029.md)及用户最新要求。

## 1. 本阶段目标

制作一个在本机浏览器可运行的中文 Demo，让用户从问题或搜索出发，查看局部知识图谱、选择一个节点，在同一详情区域直接看到**所有已配置学科**的相关知识和公式，点击相关内容逐步探索，并能返回、查看条件与来源。节点对应某科没有可展示内容时，该科留空或显示「暂无已审核内容」。

验收用两个主题：① 水与物质的量；② 理想气体与温度。主题节点、关系、解释和引用为**拟策展内容**，需要先核对当前已有数据以及科学依据，缺少的内容在独立 Demo 数据中小批补充。明确适用条件，不把液态水直接当成理想气体；不强制每个节点都有跨学科关系，不制造未核实连接。需要专家和权利审查的内容先标记「待复核」，未经审核的 Demo 不作为已审核、可公开的正式知识产品。

## 2. 用户流程

1. 打开本机 Demo 首页，看到一句产品说明、搜索和两个主题卡。
2. 选择主题，看到简短问题说明与可操作的局部图及文字列表；不显示完整大图。
3. 点击节点，打开详情：名称、学科标签、解释；若为公式则展示公式、变量、单位、适用条件、例子和来源。
4. 同一详情中列出配置表里的全部学科，每科直接列出已有相关知识、公式与关系说明；内容少时不折叠，暂无内容的科目留空或显示一行说明。
5. 点击某条关联跳到下一节点；保留路径、返回和已访问提示。原计划每次只加载一小批一跳邻居；本次实现先载入整个小型 Demo 数据包，再仅绘制一跳邻居，大图库分批加载留待下一阶段。走到数据边界时明确说明。
6. 使用中英文关键词搜索、选择候选；没有匹配显示真实空结果。反馈先以本地复制/导出文本的方式提供，不默认上传任何数据。

## 3. 功能清单与优先级

| 编号 | 功能 | 优先级 | Demo 验收 |
|---|---|---|---|
| F01 | 新首页：标题、关键词搜索、两个主题卡、项目说明 | 必做 | 进入页面后无需理解工程术语即可选主题；搜索有显式标签和反馈 |
| F02 | 两个主题与路径说明 | 必做 | 每条路径可进入，内容来自独立 Demo 内容包；缺少依据的内容不冒充已核实 |
| F03 | 局部图谱与列表视图 | 必做 | 初始只加载当前主题/一跳邻居；适应画布；同一节点图与列表可互相选中 |
| F04 | 同页学科列表 | 必做 | 不做三个标签入口，按配置列全科目；已有内容直接显示、没有则空；可增加科目 |
| F05 | 节点/公式详情 | 必做 | 根据内容显示定义、公式、变量、单位、条件、来源、审核状态；缺项不编造 |
| F06 | 连续探索与路径 | 必做 | 点击关联进入下一节点；支持返回、去重、明确数据边界；单次加载有限 |
| F07 | 搜索和空结果 | 必做 | 覆盖 Demo 数据的中英文名、别名和 ID；同名时可确认；无结果可回退 |
| F08 | 来源和数据边界 | 必做 | 每条呈现解释、来源、条件与状态；清晰标明 Demo / 待审，不显示受限原始内容 |
| F09 | 响应式与无障碍 | 必做 | 桌面、窄屏可读；键盘可搜索、选择、返回；图有文字替代，颜色不是唯一信息 |
| F10 | 反馈与使用说明 | 必做 | 提供本地复制或下载反馈文本、启动步骤、已知限制；不默认采集用户信息 |
| F11 | 链接分享与图导出 | 可选 | 仅在前述功能稳定后实施；快照、范围、来源随结果保留，内容许可允许 |
| F12 | 全图库公开、账号、AI 对话、训练小模型、商业收费 | 不进入本 Demo | 后续另行规划，当前不为占位宣称功能已实现 |

## 4. 数据与技术实现方案

- **保留原数据**：不删除、覆盖、重新生成原始数据、`normalized.json`、现有样例及历史报告。开发前清点相关文件，保存可核对的文件哈希；用户现有工作区无 `.git`，没有 Git 状态或历史可供依赖，必要时先建立不含凭证的可恢复备份。具体备份存放位置与内容留记录。
- **独立 Demo 内容包**：建议在 `06_PoC/demo/` 下放页面与经挑选的数据，包括节点、边、学科配置、主题、来源和数据版本；保留原节点 ID 和来源映射。两端、关系、解释和引用作为独立记录；本地试验内容明确标识审核状态。不得将外部项目内容当作自有数据或未经许可直接导入。
- **学科配置**：从配置文件读取学科名称、顺序和可选标识，不把三科硬编码到 UI；允许数学、物理、化学、生物、天文、工程等作为初始显示示例，具体是否收录内容由数据决定。科目列表的设计不声称对应学科已经有数据。
- **实现技术**：优先利用现有原生 HTML、CSS、ES Modules 和本地 Cytoscape/MathJax，避免首版引入新框架和构建链。计划本机静态只读启动，例如通过 Python 本机静态服务器，服务仅绑定 `127.0.0.1`。启动说明会根据实际结构和可用 Python 验证，不能以 `file://` 成功代替 HTTP 验证。
- **持续探索**：小型 Demo 优先静态按节点获取预生成数据；每次加载有限的一跳邻居，以稳定 ID 去重与保存路径。将来扩大数据量再按公开快照分片/分页；目前不承诺无限数据、无限请求或全库公开。
- **公开数据隔离**：Demo 默认只读单独内容包，不连接完整内部图、敏感配置及动态服务；资源和引用须符合各自用途许可。后续公开部署前，须另完成来源许可、科学审稿、安全及发布审查。
- **mAtlas 学习范围**：参考其关系表达、故事与单节点内容组织；不直接复制其受版权保护的内容。若未来复用代码或数据，再逐文件核对 Apache 2.0、CC BY-SA 4.0 和第三方许可。

## 5. 拟实施工作与进度

时间为**工作量估算，不是承诺完成日期**；假设当前环境可启动、现有前端模块可以复用、不需要等待长期外部审稿。功能开发可在本地推进，面向公众发布要等待必要的外部审核。

| 阶段 | 预计耗时 | 工作 | 阶段完成条件 |
|---|---|---|---|
| 0. 保护基线 | 0.5–1 工作日 | 确认路径与文件、记录哈希、备份必要文件、核对现有可复用入口 | 记录可核查且原数据未被修改 |
| 1. 数据与交互骨架 | 1–2 工作日 | 制定 Demo 内容包、学科配置、两条主题的少量节点/关系；复用局部图组件 | 两主题能在本地加载；内容边界和来源状态清楚 |
| 2. 页面开发 | 2–3 工作日 | 首页、搜索、图/列表、节点详情、各科学科区、路径和连续探索 | 核心流程可走通；空状态、相互跳转与回退有效 |
| 3. 视觉和设备适配 | 1–2 工作日 | 形成统一视觉系统、图自适应、移动端与键盘操作 | 桌面和窄屏界面完整可用，无遮挡重要内容 |
| 4. 测试与交付 | 1–2 工作日 | 本机启动、搜索、节点/关系/来源、保留资产和反例测试；编写使用说明 | 下列验收通过，保存实际测试结果及未覆盖事项 |

合计预计 **5.5–10 个工作日**，取决于现有代码可复用程度和内容查证速度。先交可运行 Demo 给负责人评阅；外部学科专家和许可审查的时间另计，未完成前不得视为可公开发布。

## 6. 验收与测试

**功能**：两条主题能启动和打开；至少一条路径可从入口走到相关节点并返回；搜索中英文名可选择实体；节点详情直接列出所有配置学科，缺失科目为空；公式和关系有明确的条件/来源/待审状态；局部图与列表相互联动，进入节点可继续探索，遇到边界不伪造答案。

**数据保护**：对比改造前后的原始数据与规范图哈希，原文件未变；Demo 的全部节点/边 ID 有映射或清楚标明策展新增；公开内容与内部受限图分离；原样例中的 ATP 问题不通过任何 Demo 的搜索、图、详情或导出路径暴露为正确事实。若此前已修复，须核对新证据，不凭旧评估假设。

**科学边界**：公式带定义域、变量和条件；相关关系不混淆等价、共现和因果；已启用的单位/数学计算有 `m/s`、`x/x` 定义域、非有限数等相关反例；若 Demo 完全没有计算功能，验证不存在调用并明确未实现，不把屏蔽写成修复。

**前端与运行**：本机独立启动并通过真实浏览器操作，测试桌面及手机窄屏；无图形遮挡、布局溢出、不可读文字、控制台关键错误或无限加载；检查键盘焦点、非颜色标识、返回和无结果。测试条件、数据版本、通过/失败/跳过和截图/日志分列，不能拿静态检查替代用户操作。

**产物**：实际能打开的 Demo、本地启动指南、内容与来源清单、版本/哈希、测试结果、已知问题和下一阶段建议。邀请制或公开版须另外经过科学审稿、内容许可、部署安全与反馈渠道验收，不因本机 Demo 通过自动发布。

## 7. 用户四项要求

### ① 专家补做项

- 数学、物理、化学专家会核对公式定义域、物质状态、关联方向和不成立的反例；若发现关系不成立则撤销，不为填满栏目保留。
- 科学教育与无障碍专家会以真实任务检查学科列表是否读得懂、图与文字是否等价；若用户看不懂关系则修改交互。
- 数据工程和授权专家会核查原数据可恢复、来源权利和公开边界；若备份无法恢复或授权不明，该内容不公开。

以上是计划，尚未获得专家实际审稿。

### ② 最原始素材

先读取项目原始上游数据、OWL、相关科学原文和来源授权、现有源码和真实运行日志；上轮已检查过的 `公共数据集/10m_elementkg_release.csv` 和 `11_真实数据/elementkg.owl` 仅覆盖部分科学内容。开发中为每条 Demo 内容记录原文或权威定义及位置；尚未取得的来源、Git 历史与审稿记录要写明，不以整理后的图或 AI 摘要冒充原始事实。

### ③ 方法与工具

| 问题 | 输入 | 步骤 | 工具及版本 | 输出 | 判定 |
|---|---|---|---|---|---|
| 原数据保留 | 原始文件及规范图 | 开发前后逐文件核对并测试恢复 | SHA-256、Python、Git（如可用）；版本留档 | 哈希与恢复日志 | 原件字节不变、恢复可用 |
| 科学与关系 | 原始文献、公式、条件 | 独立核对并执行相关反例 | 领域审稿、SymPy/pint/RDKit（如启用）；版本留档 | 来源台账和测试日志 | 不伪造、条件明确；缺审稿标待审 |
| 页面是否可用 | 实际 Demo 与浏览器 | 从首页搜索、探索、返回、访问来源及窄屏键盘操作 | 本地 HTTP、浏览器与必要的自动测试；版本留档 | 截图、步骤和通过/失败/跳过记录 | 核心任务可复现、无重大错误 |
| 是否可推广 | 公开包、许可文件和用户体验记录 | 逐来源确认、邀请用户独立试用 | 独立专家、权利人、真实用户 | 审核记录和反馈 | 公开版门槛全部满足，不能仅以自测推断 |

### ④ 独立验证

本地代码与测试是项目方自测；科学结论需学科专家与原始来源核对，内容许可需原始授权或专业意见，体验价值需未参与开发的用户独立完成任务。若复核发现关系错误、原数据改变、隐私/受限资料暴露或关键操作失败，对应功能不能通过验收；尚未进行的审核不可说成已验证。
