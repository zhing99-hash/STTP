# 数据源接入规范（Data Source Ingestion Spec）

> 文档定位：公式知识图谱项目「数据层」的**接入契约**。所有上游数据源在写入标准化中间格式（见第 6 节）之前，必须按本规范完成格式识别、规模评估、获取、解析与字段映射。
> 适用范围：数学 / 物理 / 化学 / 通用（Wikidata）四类共 8 个数据源。
> 配套文档：`02_数据层/ETL管道设计.md`（管道编排）、`06_PoC/sample_mathxiv.json`（PoC 样例）。

---

## 0. 术语表

| 术语 | 含义 |
|---|---|
| 工件节点 (Artifact Node) | 数学上的 theorem / lemma / definition；物理上的 equation / law；化学上的 substance / reaction 等图节点 |
| 依赖边 (Dependency Edge) | 表达"一个工件依赖/推导出/等价于另一个工件"的有向关系 |
| 标准化中间格式 | 统一的 JSON Lines（node / edge 两类记录），详见第 6 节 |
| 符号归一化 | 将 `G`, `G_μν`, `\\mathcal{G}` 等归一到规范符号 `G`（配合 Wikidata Q-id） |
| 采样率 p | 对超大源先抽取 p 比例（默认 1%）跑通管道，再全量 |
| Q-id | Wikidata 实体唯一标识（如 Q11379 = 欧拉数 e） |

## 1. 数据源总览

## 2. 各数据源接入细则

### 2.1 数学 — MathXiv / ArxiTeX KG

| 项目 | 说明 |
|---|---|
| **格式** | JSON。每篇 arXiv 论文一个对象，含 `nodes`（theorem/lemma/definition 等工件）、`edges`（dependencies）、`definition_bank`（符号→定义） |
| **规模** | 与 arXiv 数学类论文同量级（数十万篇，篇均 3~30 节点） |
| **获取方式** | ArxiTeX / MathXiv KG 发布仓库或数据集；建议用 `git lfs pull` 或数据门户批量下载 |
| **解析方法** | `json.loads` 逐文件流式读取；若文件巨大用 `ijson` 增量解析，避免 OOM |
| **采样策略** | 按 arXiv 分类（math.NT / math.AG 等）分层抽样 1% 论文做 PoC；参考样例见 `06_PoC/sample_mathxiv.json` |
| **质量校验** | 每个节点的 `id` 唯一、latex 可编译（LaTeX 语法粗检）、依赖边 `source/target` 必须指向同文件内已存在节点 |

**字段映射表（→ 标准化中间格式）**

| 源字段 | 中间格式字段 | 备注 |
|---|---|---|
| `nodes[].id` | `node.id` | 论文作用域唯一 |
| `nodes[].type` | `node.labels`（THEOREM/LEMMA/DEFINITION） | 大写枚举 |
| `nodes[].latex` | `node.props.latex` | 原始 LaTeX |
| `nodes[].informal_text` | `node.props.informal` | 自然语言描述 |
| `nodes[].proof` | `node.props.proof` | 可选 |
| `nodes[].symbols[]` | `node.props.symbols` | 该工件出现符号 |
| `edges[].source/target` | `edge.source/target` | 指向 `node.id` |
| `edges[].kind` | `edge.kind` | explicit_citation / llm_inferred |
| `edges[].confidence` | `edge.props.confidence` | 0~1 |
| `definition_bank` | 展开为 DEFINITION 节点 | 见 2.1 映射注 |

> 映射注：`definition_bank` 中的"符号→定义"建议同时物化为 DEFINITION 节点（带 `symbol` 属性），以便与 theorem/lemma 形成 `USES_SYMBOL` / `DEPENDS_ON` 边。

### 2.2 数学 — uw-math-ai/math-graph（HF）

| 项目 | 说明 |
|---|---|
| **格式** | 3 个 CSV：`formal_dependency.csv`（1.05 GB）、`informal_dependency.csv`（2.37 GB）、`statement_informal.csv`（5.04 GB），合计 8.46 GB |
| **规模** | 行级：依赖声明数千万级；statement 表最大 |
| **获取方式** | Hugging Face dataset：`uw-math-ai/math-graph`，用 `huggingface_hub` 或 `git clone` + LFS |
| **解析方法** | **禁止整表读入内存**。`pandas.read_csv(useccols=..., chunksize=...)` 分块；或 `polars.scan_csv().select().slice()` 惰性执行；大表优先 `duckdb` 直查（`SELECT ... FROM 'statement_informal.csv'`） |
| **采样策略** | **强制先采样 1%**：`duckdb` 执行 `CREATE TABLE s AS SELECT * FROM read_csv(...) USING SAMPLE 1% (bernoulli)` 落本地小表，跑通管道后再全量。statement 表超大，仅对采样子集做 latex→节点映射 |
| **质量校验** | formal/informal 两张依赖表的 `source_id/target_id` 必须能在 statement 表找到对应 `id`；置信度列（如有）∈[0,1] |

**文件与字段映射表**

| 文件 | 关键列（推测/约定） | 中间格式映射 |
|---|---|---|
| `statement_informal.csv` | `id, latex, informal_text, type` | → STATEMENT 节点（id/latex/informal/labels） |
| `formal_dependency.csv` | `source_id, target_id, relation, confidence` | → DEPENDS_ON 边（kind=formal / explicit_citation） |
| `informal_dependency.csv` | `source_id, target_id, relation, confidence` | → DEPENDS_ON 边（kind=llm_inferred） |

> 注：math-graph 未提供 `proof`/`symbols` 列，符号需在 transform 阶段用 LaTeX 解析器（如 `sympy.latex` / `latex2sympy2`）从 `latex` 抽取，再与 Wikidata 符号表对齐。

### 2.3 物理 — PhysicsBabel / Vashy

| 项目 | 说明 |
|---|---|
| **格式** | 结构化记录（JSON / Parquet，由 π 定理生成，量纲齐次） |
| **规模** | 2,325,320 条方程 |
| **获取方式** | PhysicsBabel 仓库 / Vashy 数据发布；按分片下载 |
| **解析方法** | 列式格式用 `pyarrow` / `polars` 读取；JSON 用流式解析 |
| **采样策略** | 按 `domain` 分层采样 1%（约 2.3 万条）做 PoC |
| **质量校验** | 每条含 `equation_str`、`symbols`、`domain`、`is_named_law`；量纲齐次性可在 load 后抽检 |

**字段映射表**

| 源字段 | 中间格式字段 |
|---|---|
| `equation_str` | `node.props.latex`（或 math 字符串） |
| `symbols[]` | `node.props.symbols` + 派生 SYMBOL 节点 |
| `domain` | `node.props.domain`（如 mechanics/EM） |
| `is_named_law` | `node.props.is_named_law`（布尔） |
| `equation_id` | `node.id` |

> 边生成：命名定律（如麦克斯韦方程组）之间可依据共享符号生成 `SHARES_SYMBOL` 边；与 MathXiv 通过对齐符号+Wikidata 物理量锚定。

### 2.4 物理 — physicslibrary.org FundamentalFormulas（XML）

| 项目 | 说明 |
|---|---|
| **格式** | XML（FundamentalFormulas 导出） |
| **规模** | 千级核心公式 |
| **获取方式** | physicslibrary.org 提供 XML 下载端点 |
| **解析方法** | `lxml.etree.iterparse` 增量解析，避免整树入内存 |
| **采样策略** | 规模小，全量接入即可 |
| **质量校验** | `<formula>` 节点含 `<latex>` 与 `<name>`；缺失 latex 的记录丢弃并计数 |

**字段映射表**

| 源字段（XPath） | 中间格式字段 |
|---|---|
| `formula/@id` | `node.id` |
| `formula/latex` | `node.props.latex` |
| `formula/name` | `node.props.title` |
| `formula/domain` | `node.props.domain` |

### 2.5 化学 — ElementKG 2.0

| 项目 | 说明 |
|---|---|
| **格式** | KG 导出（RDF / CSV / JSON 三选一，建议 CSV 边表+点表） |
| **规模** | >100 万反应、>1000 万物质；主线：元素—官能团—分子—反应—实验 |
| **获取方式** | ElementKG 2.0 发布页 / 数据仓 |
| **解析方法** | 边表 `pandas.read_csv(chunksize=...)`；RDF 用 `rdflib` 解析为三元组后转点边 |
| **采样策略** | 按"元素"维度抽样（如选 C/N/O/Fe 等若干元素及其下游分子/反应）约 1% |
| **质量校验** | 反应节点必须关联 ≥1 反应物与 ≥1 生成物；物质节点含 `formula`/`smiles` |

**字段映射表**

| 源类型 | 中间格式 |
|---|---|
| 元素 / 官能团 / 分子 （element/functional_group/molecule） | CHEM_ENTITY 节点（label 区分） |
| 反应 （reaction） | REACTION 节点 |
| 实验 （experiment） | EXPERIMENT 节点 |
| 关系边 | `PART_OF` / `REACTANT_OF` / `PRODUCT_OF` / `MEASURED_IN` 等 |

### 2.6 化学 — ReactionAtlas（PostgreSQL 26 GB）

| 项目 | 说明 |
|---|---|
| **格式** | PostgreSQL 数据库（dump 或在线实例） |
| **规模** | 26 GB 关系表 |
| **获取方式** | `pg_dump` 导出或直连只读副本；大库建议只 `COPY` 所需表为 CSV |
| **解析方法** | `psycopg2` + 游标 `server_side` 流式读取；或 `COPY ... TO STDOUT` 经管道导入中间格式 |
| **采样策略** | SQL `TABLESAMPLE SYSTEM (1)` 或按 `reaction_id % 100 = 0` 抽取 1% 行 |
| **质量校验** | 外键完整（反应↔物质引用存在）；SMILES 字段可经 `rdkit` 解析 |

---

### 2.7 化学 — Reaction-QM（CSV + HDF5）

| 项目 | 说明 |
|---|---|
| **格式** | CSV（反应/物质元数据）+ HDF5（量子化学属性矩阵） |
| **规模** | 中（属性维度高） |
| **获取方式** | 数据集发布页 / 对象存储下载 |
| **解析方法** | CSV 同上分块；HDF5 用 `h5py` 按 `dataset[sample_idx, :]` 切片读取，避免全载入 |
| **采样策略** | 与 ReactionAtlas 同主键抽样，保证两源反应对齐 |
| **质量校验** | HDF5 行索引与 CSV `reaction_id` 一致；数值无 NaN/Inf 占比超阈值 |

### 2.8 通用 — Wikidata（锚定层）

| 项目 | 说明 |
|---|---|
| **格式** | JSON dump（130 GB）/ Main Graph（105 GB，RDF/SPARQL） |
| **规模** | 亿级实体 |
| **获取方式** | Wikimedia dumps 镜像；或 SPARQL 端点按需查询（`wbsearchentities` / 实体声明） |
| **解析方法** | dump 用 `bz2` 流式 + `ijson` 解析；仅抽取"符号/物理量/数学概念"子集（P31=数学概念/物理量等） |
| **采样策略** | **不采样全量**，而是**反向索引**：以"标准化符号表"为键，仅检索命中实体（Q-id + 标签 + 别名），写入符号锚定表 |
| **质量校验** | 锚定实体须有 `label` 与至少一个 `alias`；符号消歧由人工规则 + 置信阈值 |

**字段映射表（锚定用）**

| 用途 | 中间格式 |
|---|---|
| 符号→Q-id 映射 | SYMBOL 节点的 `props.wikidata_qid` |
| 实体标签 / 别名 | `node.props.label` / `node.props.aliases` |

## 6. 标准化中间格式（Canonical Intermediate Format）

**目标**：所有源归一为同一 JSON Lines（`.jsonl`）文件，每行一条 `node` 或 `edge` 记录，供 ETL 管道统一消费。

### 6.1 记录类型

```jsonc
// 节点记录
{"record":"node","id":"<global_unique_id>","labels":["THEOREM"],
 "props":{"latex":"...","informal":"...","proof":"...","symbols":["G","π"],
          "domain":"math.AG","source":"mathxiv","source_ref":"2103.12345",
          "wikidata_qid":null,"confidence":1.0}}

// 边记录
{"record":"edge","id":"<edge_id>","source":"<node_id>","target":"<node_id>",
 "kind":"DEPENDS_ON","props":{"relation":"uses","confidence":0.92,
          "source":"mathgraph","inferred":false}}
```

### 6.2 Schema 约束

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `record` | enum(node,edge) | ✓ | 记录类别 |
| `id` | string | ✓ | 全局唯一；建议 `<source>:<local_id>` |
| `labels` | string[] | node ✓ | 见第 3 节枚举 |
| `source`/`target` | string | edge ✓ | 指向 `node.id` |
| `kind` | string | edge ✓ | 见第 3 节枚举 |
| `props` | object | ✓ | 源特有属性，宽松 schema |
| `props.wikidata_qid` | string\|null | — | 锚定后回填 |
| `props.confidence` | float[0,1] | — | 边/节点可信度 |

### 6.3 文件布局约定

```
01tuopu/02_数据层/staging/
  mathxiv_nodes.jsonl
  mathgraph_edges.jsonl
  vashy_nodes.jsonl
  elementkg_nodes.jsonl
  elementkg_edges.jsonl
  wikidata_symbol_anchor.jsonl   # 锚定表（node 的 SYMBOL 子集）
```

### 6.4 写入规则

- 每行一个 JSON 对象，UTF-8，**不缩进**。
- `id` 冲突由 dedupe 阶段处理（见 ETL 文档），写入时不保证唯一，但需打 `source` 标记。
- 所有数值/字符串经过转义，保证 `json.loads` 可逐行解析。
